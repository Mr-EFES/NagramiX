# Копирование поста, верхнее вложение и отправка

Видеозаписи владельца: `-4360413780024695663.mp4` (34,37с,обычный редактор) и `123659302364207631.mp4` (59,53с,расширенный). Просмотрены полные временные последовательности и кадры. В первом ролике в21с файл расположен после текста, затем публикуется перед ним; подпись ссылки «Радио Таврия — подписаться» становится обычным текстом. Во втором первая вставка также теряет оформление/ссылку, повторная сохраняет их; в44–48с виден красный индикатор ошибки отправки, позднее появляется карточка канала. Видео не раскрывает код ошибки Telegram RPC или точную причину сети.

## Изменение

Единый атомарный clipboard item для копирования обычного поста содержит:

- исходный полный текст;
- точные Telegram entities в прежнем `private.telegramtext`;
- структурный Document в штатном private fragment обоих новых редакторов;
- штатный RTF export редактора для межприложенной вставки.

Используются действующие TextFormat converters, Document bridge/codec и RichTextEditorClipboard. Старый legacy RTF не вычисляется повторно перед native export. Все15 существующих Copy-вызовов меню используют этот producer; ограничения копирования, перевод/сводка, restricted text и сами действия меню прежние. Уже структурные rich-посты и пустой composed content сохраняют свой прежний путь. Первый paste получает те же ссылки/стили, что повторный: отдельная подготовительная вставка не нужна. Копирование из обычного поля ввода и внешний clipboard не перестраиваются.

В обычном редакторе новые файлы сразу вставляются в начало поста, после ранее выбранных ведущих файлов. Порядок выбранного набора сохраняется, обе структурные позиции выделения сдвигаются по индексу блока, UTF16-координаты текста прежние. В расширенном редакторе скрепка также вставляет media fragment в начало документа через действующий `replaceRange` — структурную команду редактора с undo. Персистентный document setter, отдельный плеер или новая геометрия пузырьков не добавлены. Пустой выбор ничего не вставляет; регистрация медиа, partial references и preupload прежние.

Обычные текст+entities с файлами перед текстом либо после него теперь выбирают штатный file+caption transport. Прежняя проверка принимала только файлы после текста, поэтому визуально правильный ведущий файл расширенного редактора неоправданно переводил такой пост в rich transport. Настоящий inline-файл между двумя текстовыми областями, структурное оформление и текст длиннее допустимой подписи сохраняют rich-путь: содержимое не обрезается и не уплощается. Premium/серверные лимиты прежние. Все поддерживаемые типы файлов и прежние ограничения кружков/альбомов сохраняются.

У поста с собственным вложением URL остаётся кликабельной сущностью и не добавляет вторую карточку канала. Общая state-обработка обоих редакторов отменяет preview query и снимает уже показанную карточку; запоздавший callback не возвращает её. Native file enqueue и rich payload запрещают генерацию дополнительного preview. Обычные сообщения без вложений сохраняют штатное поведение предпросмотра. Reply/thread, очередь, права, оплата, silent/schedule, clear, retry и обработка реальной ошибки отправки не подменяются.

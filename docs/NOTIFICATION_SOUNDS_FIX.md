# Каталог звуков уведомлений

После физической проверки предыдущей сборки №82 пользователь обнаружил пустые системный и классический разделы выбора звука. Правка подготовлена после этого выпуска: implemented / compile_passed / device_pending. Она включена в новый проверенный IPA 0.5.1 / №83.

## Причина и решение

В закреплённом Telegram 13.0 общий экран NotificationSoundSelection строит встроенные разделы исключительно по NotificationSoundList из кеша account.getSavedRingtones. Сам экран не обновляет этот список. Заголовки и «Нет» остаются, даже если список не содержит встроенных документов. В проверенном IPA №82 из мелодий этого каталога присутствует только штатный 0.m4a; остальные звуки база рассчитывает получить из облака. Выбор не должен зависеть от полноты серверного списка. Причина конкретного неполного серверного ответа на устройстве без журнала не установлена; сетевые учётные данные и API ID не менялись.

Overlay добавляет независимый каталог с исходными cloudSoundMapping ID: 23 системные и 8 классических мелодий. Новые системные идут первыми, начиная с Rebound. Предпрослушивание использует локальные M4A через прежний AVAudioPlayer и штатную аудиосессию. Файлы включены в существующую группу AppResources, доступны без сети; их происхождение и хеши зафиксированы в [ресурсах](../ios/Resources/NotificationSounds/README.md). Новый каталог не создаёт поддельных серверных документов и не изменяет кеш пользовательских мелодий.

Исправлен getCloudLegacySound: ключи 200–210 соответствуют индексам 12–22 штатных локализованных названий. Ранее вычитание 100 давало индексы 100–110 вместо Rebound, Antic, Milestone и остальных названий.

При открытии экран запрашивает свежий список с hash=0 и загружает пользовательские файлы прежним механизмом. Запрос принадлежит экрану и отменяется при закрытии. При ошибке сети прежний кеш не стирается; встроенные разделы, «Нет», наследуемый звук и загрузка доступны также при nil/пустом кеше. resolvedNotificationSound сохраняет выбранный встроенный ID при отсутствии соответствующего серверного документа. В NotificationService встроенные ID используют локальный файл; облачные пользовательские звуки сохраняют прежнюю загрузку и app-group Library/Sounds.

Общий экран используется личными чатами, группами, каналами, историями, реакциями и исключениями. Сохранение выбора, подтверждение/отмена, MP3-пикер, лимиты и сохранение звука из сообщения остаются штатными. Новых переключателей, изменений настроек, тем и шрифтов нет.

## Проверено

- Полный overlay на чистом pin f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838: изменены ровно четыре Swift-файла и добавлена 31 мелодия; 369 остальных проверенных файлов побайтно прежние.
- Все 31 cloud ID уникальны, названия соответствуют штатным локализованным ключам; все M4A декодируются без ошибок, длительность менее пяти секунд. Хеши итоговых ресурсов совпадают после копирования.
- Четыре изменённых Swift-файла проходят синтаксический разбор. Это не нативная компиляция.
- Восемь случаев изменения/дублирования входного stock-источника и повторное применение отклоняются до небезопасного изменения дерева.
- Три теста проверки IPA: полный набор; отсутствие файла в каждой из трёх групп; повреждённый файл. Проверка явно отклоняет опубликованный №82 за отсутствие 200.m4a. Она выполняется существующим шагом перед публикацией, поэтому новый неполный пакет не будет опубликован.
- Python, метаданные текущего выпуска, 13 русских строк приветствия и git diff --check.

## Проверка следующего IPA на iPhone

В каждой категории открыть «Звук», проверить 23 системных и 8 классических мелодий, прослушать Rebound, Milestone, Note, Tritone и Chime. Выбрать, подтвердить, снова открыть и перезапустить приложение; выбор и название должны сохраниться. Отдельно проверить «Нет», отмену выбора, наследование в исключении и уведомление при заблокированном экране.

Повторить открытие без сети и после очистки обычного кеша. Загрузить короткий MP3, прослушать, выбрать и удалить его; сохранить подходящее голосовое как звук. Проверить отмену загрузки и закрытие экрана во время обновления. Нативная компиляция прошла в №83; AVAudioPlayer, серверное сохранение и доставка уведомлений на устройстве ещё не проверены. Опубликованный №82 не переиздавать; следующий IPA собирать только по новой команде пользователя.

## Актуальный результат выпуска

Изменение включено в чистую нативную сборку 0.5.1 / №83, компиляция пройдена. Новый IPA опубликован и независимо проверен; [результат](RELEASE_STATUS.md). Проверка на физическом iPhone ожидается: compile_passed/device_pending. Новую сборку запускать только по новой команде пользователя.

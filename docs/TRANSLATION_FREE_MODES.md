# Бесплатные переводчики и температура нейросетей

Статус27октября: исходники включены в опубликованный0.7.6/build139 (`c7201b506bbc8ccd25e84e9cef9dd812b905bd77`). Нативная SDK и релизный IPA проверены; физическая приёмка ожидается. [Результат](RELEASE_STATUS.md).

Уточнение пользователя 26 октября 2026 года отменяет прежний API-only режим Google и Яндекса: эти два пункта работают **только бесплатно**, без полей ключей и без перехода к платному Cloud API. Apple остаётся офлайн-переводчиком после загрузки поддерживаемой пары языков. В «Прочее» отдельная группа «Перевод», переключатель «Перевод сообщений» и условный пункт «Настройки перевода»; прежние stable IDs 5010–5012 сохранены.

Guarded stage `translation_free_modes` идёт после `message_translation`. Четыре замены helpers по точному SHA, новый Web helper и 23 guards проверяются до записи. Ранние stage/templates не переписываются. Сохраняются настройки v1, master/auto OFF, выбор языка/провайдера, per-account/peer/thread scope, оригинал и entities. Старые ключи Google/Яндекса не читаются и не удаляются автоматически.

## Google и Яндекс

Google использует анонимный `translate_a/single?client=gtx`, текст передаётся POST form, а не URL. Яндекс получает SID из публичной страницы `translate.yandex.com`, декодирует компоненты так же, как текущая публичная страница, и делает POST в `translate.yandex.net/api/v1/tr.json/translate`. SID только в памяти, срок 15 минут. HTTP cookies, вход в аккаунт, скопированные ключи, секреты разработчика и обход CAPTCHA не применяются.

Это **онлайн** режимы. Офлайн API Google ML Kit существует, но требует отдельной SDK/Bazel-интеграции и управления моделями; в этой доработке он не подключён и не изображён работающей загрузкой. Офлайн-словари приложения Яндекса не являются подтверждённым публичным SDK для NagramiX.

Короткие части переводятся последовательно внутри одной задачи; длинные делятся по границам графем и преимущественно слов до 3500 UTF-8 байт, сохраняются исходные порядок и краевые пробелы. Только полный результат возвращается в существующий план форматирования. До каждого следующего запроса проверяются подписчики и settings revision. Общая очередь ограничена: два активных задания, 32 ожидающих, общий deadline 90 секунд. Как прежде, одна задача объединяет одинаковые подписки и использует bounded memory cache с account/revision scope.

При HTTP/JSON-отказе бесплатного сервиса действует ограниченная пауза следующих запросов (минимум 30 секунд, учитывается числовой Retry-After до часа), без автоматического повтора и смены переводчика. Частичный перевод не записывается. Проверка/CAPTCHA/изменившийся ответ показываются как недоступность бесплатного перевода; оригинал остаётся. Это не обещание безлимитной доступности стороннего сайта.

Живые Python-проверки подтвердили HTTP 200 и перевод нейтрального Hello обоими сервисами. Затем production Swift URLSession/CloudClient/WebPlan успешно перевёл массив [Hello world., Thank you!] в [Привет, мир., Спасибо!] через Google и Яндекс, без ключей. Проверка 26 октября 2026, 22:41 МСК; доказательство live.json. Это подтверждает именно сетевой клиент/запросы на дату проверки, но не UIKit/iPhone или доступность из любой сети.

## Нейросети и бесплатные квоты

Три нейросети используют собственный ключ выбранного сервиса из Keychain. Наличие ключа не означает обязательную оплату: Gemini предоставляет бесплатную квоту подходящим аккаунтам/моделям, но аутентификация нужна и для неё. OpenAI и DeepSeek применяют тариф/выданные кредиты своего аккаунта; бесплатный веб-чат не является анонимным программным API. Ключ, тексты, модель и температура не переключаются на другой сервис скрыто.

В настройках нейросетей есть ключ, модель, ссылка на официальный кабинет, температура и удаление ключа. Для Google/Яндекса страницы ключей отсутствуют. Бесплатный тариф определяется сервисом: приложение не может подтвердить, что произвольный введённый ключ не имеет платного биллинга.

Настоящий бесплатный анонимный вариант найден и проверен отдельно: Pollinations Classic возвращает GPT-OSS 20B, а не Gemini/ChatGPT/DeepSeek. Не выдавать его за одну из этих моделей. Пользователь подтвердил отдельный пункт; он добавлен следующей стадией [translation_gpt_oss](TRANSLATION_GPT_OSS.md), с самостоятельной температурой и без подмены прежних моделей. Документация Classic указывает один текстовый запрос раз в 30 секунд, поэтому это не равно беспрепятственному массовому автопереводу чата.

Источники: [Gemini: ключи](https://ai.google.dev/gemini-api/docs/api-key), [Gemini: бесплатный уровень](https://ai.google.dev/gemini-api/docs/billing), [DeepSeek: тарифы и кредиты](https://api-docs.deepseek.com/quick_start/pricing/), [OpenAI: биллинг API отдельно](https://help.openai.com/en/articles/9039756-managing-your-work-in-the-api-platform-with-projects), [Pollinations Classic](https://github.com/pollinations/pollinations/blob/master/APIDOCS.md), [текущий каталог Classic](https://text.pollinations.ai/models), [офлайн Google ML Kit](https://developers.google.com/ml-kit/language/translation/ios).

## Температура

Отдельно для каждой нейросети сохраняется 0–2 с шагом 0,1. Это вариативность формулировок, а не оценка качества. Смена температуры меняет revision: старый кеш и незавершённый результат не используются. Optional-поле `temperatures` декодирует прежние настройки без сброса. Начальные значения: Gemini 1,0; ChatGPT/DeepSeek 0,2.

Параметр отправляется только известным совместимым моделям. Для Gemini — в generationConfig, ChatGPT/DeepSeek — temperature. ChatGPT по умолчанию теперь gpt-5.4-mini в поддерживаемом режиме reasoning_effort=none; сохранённое явное имя не меняется. Прежний gpt-5-mini не получает неподдерживаемую температуру; UI сообщает, что она управляется моделью. DeepSeek работает в non-thinking режиме. Неизвестная модель не получает неподтверждённый параметр. Нет автоматического второго оплачиваемого запроса после ошибки.

## Проверка

`scripts/validate_translation_free_modes.py` проверяет точные outputs/templates/guards, отсутствие платного Google/Яндекс endpoints и наличие отдельной группы в «Прочее», применение/повтор/неправильные входы без частичной записи. Для старых source validators четыре файла восстанавливаются строго из проверенных предыдущих templates в отдельной папке; неизвестный drift не обходится.

Production Settings/Cloud/Web/TextPlan и весь Runtime исполняются в Linux debug/O с явными границами HTTP, Apple ML, signals и Postbox. Проверяется полный путь free и LLM, отсутствие даже чтения старых ключей Google/Яндекса, реальная передача температуры, отмена до следующего фрагмента, rate limit, coalescing, cache, HTML/неполный ответ, Unicode/whitespace, миграция и прежние stale/store/entity guards. Негативные варианты потери температуры и чтения legacy key должны падать. UIKit, реальный Keychain, TranslationSession, SDK и физический iPhone такими тестами не проверяются.

Доказательства: `/workspace/.codex-validation-nagramix-translation-free/`. Включено в опубликованный0.7.6/build139; физическая приёмка ожидается.

Локально завершены 127 free/temperature/client + 60 прежних policy/entities + 26 прежнего actual runtime + 27 новых actual routing/cancellation проверок в каждом debug/O, всего 240 на режим. Два отрицательных варианта отвергнуты в обоих режимах. 71 fail-closed случай без частичной записи. Живой production Swift клиент Google/Яндекса пройден; платные LLM API не вызывались.

Полная чистая композиция и 20 source validators PASS: всего 314 модифицированных/новых native files, ровно 5 изменённых/новых относительно предыдущей translation-цепочки. Остальные 309 прежних модифицированных нативных файлов побайтно сохранены; включая реализацию PiP/архива/кружков вне переводческих helpers. Swift parse и совпадение SHA исполнявшихся production helpers с итоговой композицией пройдены.

# Единый системный PiP

Актуальная команда отменяет гибридный режим: [системный переход без локального уменьшения](PIP_NATIVE_TRANSACTION.md). Старое описание гибридного выбора и ручной геометрии ниже историческое; не включать hybrid_pip обратно.

Актуальное изменение после0.7.1: пользователь выбрал [гибридный режим](HYBRID_PIP.md) — внутренний mini по свайпу и системный PiP в фоне. Ниже описаны прежние решения и ограничения AVKit; прежнее требование всегда показывать системное окно заменено новой командой для жеста. Source_checked, SDK/device pending.

## Исправление по скриншотам 21 октября

Пользователь показал дефекты установленного112: рядом с системным окном остаётся уменьшенный исходный слой с PiP-заглушкой; место видео в чате бывает пустым. Причины в нашем коде: inline fade начинался лишь после didStart, когда AVKit уже закончил собственный переход; при интерактивном раскрытии фона галерея продолжала скрывать исходную ячейку. Новая правка только в исходниках main, в IPA112 отсутствует.

Изучен открытый [Swiftgram/Telegram-iOS, commit cf8b23b](https://github.com/Swiftgram/Telegram-iOS/blob/cf8b23beaaac4126a396337ac2d5be13f9f76b66/submodules/GalleryUI/Sources/Items/UniversalVideoGalleryItem.swift#L852): sample-buffer AVKit, willBegin вызывается из native willStart, inline fade запускается там. Это проверка опубликованного исходника, не аудит бинарного файла App Store. Три файла GalleryUI получены через GitHub connector и проверены по Git blob SHA1; proof swiftgram-research.json. Чужой код в приложение не копировался.

Новая схема:

- На began жеста выдаётся временное разрешение показать штатный poster исходной ячейки **до** раскрытия фона. Меняется только hide-request этой галереи; другие источники GalleryHiddenMediaManager и read-history gate не снимаются. Shared decoder остаётся у галереи/PiP, второго воспроизведения нет. Это штатный poster, а не обещание точного последнего кадра видео.
- Native willStart начинает fade галереи одновременно с системным переходом. Единственный NagramiXPiPVisualHandoff координирует только presentation: завершённый fade + успешный native didStart дают одно окончательное закрытие. Ожидание/отказ не закрывает галерею и не выдаёт ложный успех. Rollback возвращает alpha из presentation-состояния; Expand инвалидирует исходящий fade. Reduce Motion использует немедленное восстановление/нулевую длительность fade.

Очистка одного не снимает другой; после отмены восстанавливается текущий источник, после успешного dismiss старый hidden media не возрождается. Обе штатные регистрации gallery source используют один gate. Камера, screenshot protection и settings не меняются.

## Поведение

- Кнопка и свайп запускают один и тот же системный механизм. Отмена подготовки при Back, повороте и уходе в фон применяется к обоим входам; после начатого native перехода его результат обрабатывает AVKit. Явная отмена не показывает предупреждение об ошибке. Выключение «Видео PiP свайпом» отключает жест, сохраняя кнопку. Ключ и сохранённый выбор не меняются.
- Горизонтальное, вертикальное и квадратное видео используют один путь. Свайп вверх, вниз, в стороны и по диагонали двигает источник по соответствующему вектору. При удерживании источник следует пальцу в пределах видимой области. Запуск происходит после отпускания, а не посреди движения.
- Уменьшение сохраняет пропорции и плавно замедляется у минимального размера. Отпускание не меняет геометрию: AVKit получает последнюю живую поверхность прямо из положения под пальцем. Прежний отдельный перелёт к краю на0.18с и принудительный переход к минимальному масштабу удалены. После подтверждения нет второго броска или сброса по таймеру.
- Фон галереи открывает лежащий под ним интерфейс вместе с движением пальца. Возврат при отмене восстанавливает видео и фон одним animator из текущего presentation-состояния. Его можно перехватить новым жестом без возврата в промежуточную точку. Кнопка PiP блокируется до конца возврата, чтобы AVKit не захватил ещё движущийся источник. Смена ролика сбрасывает и активный жест, и незавершённый возврат.
- Двигается отдельный контейнер видеоповерхности. Галерея, подпись, кнопки и заглушка не перетаскиваются вместе с видео. При перетаскивании управление скрывается штатным способом; при отмене восстанавливается прежняя видимость. Pinch, увеличенное видео, scrubber, обычные нажатия и выключенный жест сохраняют своё взаимодействие.
- Запрос ожидает готовность текущего слоя и AVKit до восьми секунд. До подтверждённого запуска галерея остаётся открытой. Отказ или отмена восстанавливает исходную геометрию и допускает новую попытку; сообщение об отказе кнопки остаётся штатным.
- PiP сохраняет тот же плеер, позицию, паузу, скорость и звук. Expand возвращает эту же галерею. Быстрый возврат до конца скрытия не создаёт повторный контроллер и не закрывается запоздавшим завершением fade. Закрытие PiP ставит скрытый источник на паузу и освобождает владение.

## Устройство кода

`NagramiXPiPLifecycle.swift` — один владелец фаз idle/preparing/starting/active/stopping/finished. Один результат запроса, ограниченные ожидания, обработка позднего didStart после отмены, повторных callbacks, неудачной передачи галереи и восстановления. Успех требует native didStart либо фактического active. Видимость галереи меняется только в commit. При асинхронном восстановлении ресурс удерживается до его завершения; все системные completion вызываются один раз. Во время обычного активного воспроизведения таймер отсутствует.

`NagramiXSystemPiPController.swift.inc` — AVKit adapter к реальному primary AVSampleBufferDisplayLayer или AVPlayerLayer. Он может создаваться до появления слоя и перепривязываться при смене качества до запуска. Используются KVO и один таймер всего запроса, а не вложенные source/AVKit ожидания. Playback delegate задаёт желаемое play/pause, берёт позицию перемотки из текущего timebase и гарантирует completion. Размер источника не меняется по render-size callback системы.

Право декодировать вне иерархии получает отдельный UUID через существующий setNagramiXBackgroundPlayback. Очистка снимает только его, сохраняя разрешения фонового воспроизведения других владельцев. Аудио остаётся под управлением Telegram. Сначала завершается активация собственного renderer; при отсутствии playback audio и готовности AVKit через полсекунды допускается один managed lease для немого/остановленного ролика. Готовность требует действующей playback-сессии и совместимой категории: ambient не считается готовым даже при штатном isPlay=true. PlayAndRecord без собственного playback не перехватывается; запись и звонки сохраняют сессию. Нет прямой записи AVAudioSession, дополнительного проигрывателя или декодера.

Отдельный UUID системного PiP также удерживает существующее разрешение MediaManager на сохранение аудиосессии в фоне. Он не зависит от checkbox фонового видео и наличия звуковой дорожки; подготовка/перекрывающиеся запросы/активное окно освобождают только свой ID при отмене, остановке или deinit. Без PiP прежнее условие фонового воспроизведения сохраняется. Ветви foreground/dropAll и сам ManagedAudioSession, запись и звонки побайтно прежние; меняется только входной флаг удержания. Добавлен protocol requirement с безопасной default-реализацией и динамическим override основного MediaManager. Тест компилирует реальные setter/update bodies, включая вызов через протокол.

`NagramiXPiPGestureController.swift` владеет pan, временной геометрией и прозрачностью отдельного backgroundNode; GalleryControllerNode содержит только установку и вызовы lifecycle. Контейнер в UniversalVideoGalleryItem сохраняет штатные scroll/zoom layout. На начале жеста заранее привязывается текущий AVKit source, без запуска PiP и изменения воспроизведения; запрос и активация аудио остаются на отпускании. Pan имеет динамический приоритет над штатным TapLongTapOrDoubleTap, который завершает long tap через0.3с даже без действия; это сохраняет перетаскивание после удерживания. При OFF/zoom приоритет не применяется, короткий tap/double tap освобождается после отказа pan. Три native места вставки placeholder/transition snapshots используют новый прямой sibling-контейнер. Centrality/visibility во время PiP не запускают повторный autoplay, seek или detach, поэтому возврат сохраняет паузу. Закрытие обычной галереи запрещает незавершённый запуск.

`ios/pip_runtime.py` — финальная проверяемая замена runtime после исторических стадий overlay. Шесть полных SHA, 25 точных операций, preflight всех ресурсов и Swift glob до записи. Прежний NagramiXPiPPlaybackSession удаляется из итогового native дерева после проверки отсутствия ссылок. Исторические templates сохраняются только для воспроизводимой ранней стадии; второй runtime не компилируется. База Telegram и её SHA-защиты прежние.

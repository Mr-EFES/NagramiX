# Исправления, найденные при проверке 0.9.0

Владелец поручил проверить весь main перед отдельной командой на сборку. Проверка выявила ошибки сохранения сообщений; они исправлены поздней стадией `release_090_preflight_fixes`, после десяти предыдущих доработок. Запуск SDK, Actions, сборка IPA и публикация релиза не разрешены этой задачей.

## Пересылка из нескольких источников

Выбор сообщений из общего поиска может содержать несколько чатов. В прежней ветке `last.append(message)` изменял временную копию массива, поэтому, например, из `A1, A2, B1` мог пропадать `A2`. Та же ветка формировала пакеты только из `.forward` и теряла комментарий либо подготовленное медиа `.message`.

Теперь все такие наборы используют общий группировщик. Сообщения сохраняют исходный порядок, а непрерывные серии пересылок разделяются по источнику. Комментарии и группы обычных вложений остаются в наборе. Каждый следующий `enqueueMessages` запускается после результата предыдущей локальной транзакции: асинхронная подготовка медиа больше не позволяет следующему пакету обогнать первый. Доставки сервером этот порядок не подтверждает.

Одноисточниковая ветка, преобразования silent/schedule/repeat, Stars, topic/reply/correlation, поздняя проверка retained-reply lease и обработчики завершения сохранены. Изменён только сбор источников и подготовка многоисточниковой очереди в `ChatControllerLoadDisplayNode.swift`.

## Целая запись локального архива

Старая фильтрация сохраняла обычные медиа только типов Image/File/Poll. Контакт, геопозиция, игральный результат, игра или web-карточка могли оказаться в архиве без медиа. Безопасные display-атрибуты также сохранялись только для временных записей.

`makeRecord` теперь кодирует весь поддерживаемый набор медиа и проверяет обратное декодирование с тем же конкретным типом. Если вложение либо необходимый атрибут не восстанавливается, весь новый снимок отклоняется до резервирования ресурсов; частичный пост не сохраняется. Существующие шесть безопасных типов content attributes сохраняются и для обычных записей. Исключения для expired/paid/ephemeral и проверок допустимости не ослабляются; service actions явно исключены.

Контакт, venue/map и оригинальный результат dice проверены через native constructors/coders; для game/webpage проверены вложенные ресурсы, ожидание байтов и ownership. Управление отметками потребления, TTL, механизм первой/повторной стадии удаления и public API не менялись.

## Доказательства

Стадия заменяет два существующих файла, проверяет 18 зависимостей и не добавляет файлов приложения, локализационных ключей или импортов Postbox. Все preimages и templates проверяются до записи. Совместный gate на полном дереве, независимое ревью и повторное применение к заново полученной исходной цепочке прошли.

- Пересылка: 1 092 проверки в debug и `-O`; 12 отрицательных запусков, включая реальные старые потери и перестановку при задержке медиа.
- Архив: 68 сценариев и 40 проверок native constructors/resources в каждом режиме; 12 отрицательных запусков.
- Loader: 14 отказов до изменения дерева. Inverse: 666 путей совпали с опубликованной базой, 34 отрицательных сценария отвергнуты. Все 2 070 прежних snapshots сохранены.

Точные SHA и результаты — [RELEASE_090_PREFLIGHT_FIXES_CHECKS](RELEASE_090_PREFLIGHT_FIXES_CHECKS.json). Это source gate и исполнение production-методов в ограниченных адаптерах; UIKit, реальный Postbox, сеть Telegram и Apple SDK не исполнялись. Полный предсборочный source-аудит завершён: [SOURCE_PREFLIGHT_090](SOURCE_PREFLIGHT_090.md). Статус четырёх Apple-framework suites, SDK и физической приёмки 0.9.0 остаётся pending; исходники готовы к отдельно разрешённой сборке.

В workflow также освобождаются четыре временные полные копии исходников сразу после соответствующих успешных validators 8–11. Скрипт cleanup принимает только известное имя, проверяет маркеры и отсутствие пересечения с активными исходниками, не следует symlink и не выполняется при ошибке validator. Отчёты сохраняются. Семнадцать проверок безопасности и порядка вызовов прошли. Это уменьшает ненужное хранение копий перед SDK; фактическая нехватка диска на runner не заявляется.

# Переключатель оригинального видео в новой галерее

Статус: source_checked, локальные проверки пройдены; Apple SDK и iPhone ожидают проверки. Новая IPA этой задачей не запускается.

Владелец уточнил сценарий: обычное видео из «Галереи», без редактирования. «Видео без сжатия» включено — отправлять оригинал; выключено — использовать штатное сжатие Telegram. Ключ nagramix.videos.original, defaultON, сохранённые ON/OFF, stableID138 и название переключателя сохраняются.

Настройка и обработчик сохраняли значение правильно. При переходе на современную галерею отправка стала проходить через MediaPickerScreen.sendThroughChatMediaSend → ChatMediaSendMessages(context:...). Этот путь не читал originalVideos; обычное видео попадало в один и тот же VideoLibraryMediaResource.compress(adjustments/nil) при обоих значениях. Старая интеграция original export находилась в LegacyMediaPickers и не управляла этим новым путём. Это подтверждённая ошибка выбора режима; реальные байты или размер пользовательского видео на устройстве не исследовались.

Стадия70 original_video_mode после selection_scroll_continuity подключает настройку к фактическому началу современной отправки. Режим снимается один раз для текущей отправки. OFF возвращает исходные items/global без Photos original lookup/export, затем выполняется прежний native compression pipeline. Битрейт, выбранный профиль качества и алгоритм Telegram не подменяются. ON готовит подходящие неизменённые library videos уже существующим PHAssetResource-экспортом и передаёт готовый оригинал в прежнюю очередь отправки. Тело экспортера, сохранение байтов и владение временным файлом не меняются; его функция получает public-доступ для вызова из другого модуля. Добавлена прямая BUILD-зависимость на NagramiXMediaSettings. После подготовки выполнение возвращается на main queue перед прежним UIKit/render pipeline.

Сохраняются подписи/entities, выбранная обложка, спойлер, uniqueId, порядок, send options и обычные фото/видео альбомы. Редкие неподдерживаемые контейнеры остаются исходными документами; для такой смешанной отправки локально выключается группировка, чтобы документы не смешивались с photo/video альбомом. Настройка группировки пользователя не переписывается.

Обычный оригинал не заменяет crop/trim/rotation/painting/tools/audio edits, mute/GIF, Live Photo, HFR/slow-motion, timed/paid media, кружки, камера/tempVideo и явную отправку файлом. Только качество без содержательных правок не препятствует оригиналу при ON. Ошибка или отсутствие оригинала даёт прежний skipped-item outcome; скрытого перехода к сжатию при ошибке ON нет. Подготовка оригиналов ограничена одним одновременным экспортом; отмена прекращает текущий запрос и не запускает следующие.

[Проверки](ORIGINAL_VIDEO_MODE_CHECKS.json) выполняют фактические новый helper, context wrapper, item/options, visual-edit eligibility, неизменённую native library-video compress ветку и настоящий SwiftSignalKit (subscription/disposal, map/catch/switch/take/then/combine и bounded lanes). Photos/export/media/renderer — явные границы. Проверяются ON/OFF, отсутствие Photos export при OFF, caption/cover/options/order, неподдерживаемый контейнер, реальные правки и специальные типы, ошибка без lossy fallback, snapshot при смене настройки во время подготовки, следующий send и отмена. Прежний context wrapper обязан провалить проверку различия ON/OFF. Тесты подтверждают маршрутизацию, но не фактическое перекодирование, размер файла или серверный byte roundtrip.

Дополнительная проверка компилирует реальный NagramiXMediaSettings как модуль и импортирует его current.originalVideos. На Apple полные новый helper и context wrapper проверяются с настоящими UIKit/Photos и этим модулем; подпись оригинального экспортера извлекается из production declaration. Telegram/media/model I/O остаются адаптерами, полная SDK-компиляция и устройство — отдельные gates. Linux не объявляет UIKit/Photos пройденными.

На iPhone отправить одно и то же обычное видео при ON, OFF и повторном ON без перезапуска, сравнить поведение со штатным Telegram и проверить выбранный профиль качества. Для ON сравнивать скачанный основной original resource с выбранным Photos resource, а не thumbnail/автоматический поток. Проверить обложку/подпись/спойлер/альбом, iCloud/отмену/ошибку, edited/special cases и сохранение выбора после перезапуска. Опубликованная0.9.6 не изменяется; новая IPA только по прямой команде владельца.

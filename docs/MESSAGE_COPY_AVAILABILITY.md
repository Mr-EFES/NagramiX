# Переслать и Рассылка: доступность и опросы

Текущая правка исходников0.8.6: **source_checked / compile_pending / device_pending**. В IPA171 её нет. SDK, Actions, новая IPA и публикация в этой задаче не запускались; любой следующий запуск — только по отдельной личной команде владельца.

## Последнее уточнение владельца

Финальное требование заменяет раннее «независимо от флажка»: ON у «Свободного контента» разрешает копировать доступные сообщения из защищённых каналов/групп и секретных чатов. OFF возвращает штатные ограничения: команды копирования защищённого содержимого скрываются, а уже открытые операции повторно проверяют разрешение перед отправкой. Обычные незапрещённые сообщения сохраняют доступные действия. Отдельные пользовательские настройки видимости «Переслать»/«Рассылка» и readonly/account/destination права сохраняются.

Нативный «Репост» остаётся пересылкой исходного ID, доступен только при штатных правах. Free Content не разрешает его для secret/protected/недоступного источника. Для закрытого канала без участия, исключённого участника и отсутствующего source peer нативный пункт скрывается; активный публичный username позволяет обычный native path. Для копий этого ограничения нет при ON и наличии самого содержимого.

## Исправленные причины

На скриншоте обычный анонимный опрос. Прежний копировщик не принимал TelegramMediaPoll и возвращал nil; обе команды становились серыми даже при разрешённом репосте. Дополнительно Core безусловно запрещал source namespace SecretChat, а панель множественного выделения скрывала и не запускала обработчики для секретного чата даже при ON.

Новая поздняя стадия `message_copy_availability` после `pip_first_request` меняет шесть файлов с точными Before/After,17 SHA guards и проверкой всех зависимостей до первой записи. Старые canonical стадии и их hashes сохранены; исторические проверки снимают новый этап перед собственными контрактами. PiP и его исправление presentation-copy не менялись.

- Core свойство `nagramiXRequiresFreeContentCopy` объединяет secret namespace, индивидуальную/peer-защиту, Ephemeral forwardingDisabled и недоступность source channel. `nagramiXAllowsContentCopy` читает тот же живой ContentSettings→privacy flag; новых ключей/defaults/migration нет.
- Меню показывает разрешённые copy commands по фактической возможности полного переноса. При OFF запрещённые пункты отсутствуют, а не показываются серыми. Панель массового выделения использует ту же возможность и снимает unconditional secret-chat ban только при ON. При смене флажка force layout от существующего privacy observer повторно разрешает уже выбранные ID: прежние callbacks отменяются поколением, повторно выделять сообщения не нужно.
- Оба custom пути отправляют новые сообщения. Одиночный `.forwardWithoutSource` разрешается в `.copyToSingleRecipient`, а не в server forward ID; в destination composer hideNames перед Send разрешает полный набор и подготавливает локальные копии. «Репост» использует прежний callback.
- Подготовка получает полные байты всех вложений до enqueue. Новый local media ID/temp file/group ID отдельны для каждого адресата; captions/entities, порядок, альбомы, темы, комментарий, silent/schedule/fees сохранены. Три guards перед асинхронным commit/diversion повторно проверяют OFF; destination composer заново проверяет Core policy. Отключение после выбора/подготовки не приводит к отправке защищённой копии.
- Для обычных секретных вложений используется неизменённый native SecretFile fetch → multipartFetch с encryptionKey/decryptedSize. MediaBox содержит расшифрованные полные байты; stager создаёт новый local upload без secret resource/key или cloud reference оригинала. Нет нового чтения истории/уведомления о просмотре/consume.

## Копии опросов

Опрос отправляется как новый интерактивный poll с отдельным LocalPoll ID каждому адресату. Сохраняются вопрос, варианты и их порядок, entities, анонимность/публичность, множественный выбор и поведенческие flags, доступные вложения question/options/solution. Счётчики/личности голосовавших, старый выбор пользователя, серверный hash, старые option author/date и истёкшие deadlines не переносятся. Новые голоса считаются отдельно. Неполное или непредставимое native sender вложение не удаляется молча: весь пакет отклоняется до частичной отправки. Destination SecretChat для опросов исключён по штатной API-возможности; это отличается от копирования обычного содержимого ИЗ секретного чата.

Викторины копируются интерактивно только при известном правильном ответе: из correctAnswers либо доступного isCorrect в результатах, без переноса чужих голосов. Правильный ответ не угадывается; обычный опрос не выдаётся за викторину. Владелец явно выбрал сохранять викторину только при доступном правильном ответе. Текстового fallback и автоматической смены формата нет. Plain анонимный опрос со скриншота поддержан. Платные/invoice/service/expired/подтверждающие коды, входящие view-once и отдельные lifetime-правила не расширялись этим запросом. Недоступные серверу байты/неизвестный ответ не восстанавливаются флажком; write bans/fees/сеть по-прежнему могут остановить реальную отправку.

## Проверки и границы подтверждения

`python3 scripts/validate_message_copy_availability.py --source <pre-port> --swiftc <swiftc> --report <json>`

153 исполняемых проверок actual copier/fetch/stager и извлечённых menu/draft/selection/commit expressions проходят в debug и `-O`. Проверены ON/OFF/повторный OFF, source secret/protected/private-left/kicked/public alias, нативный Repost, открытая операция и отмена после staging, опросы/правильные ответы/вложения, два адресата и порядок. Конструкторы poll model извлекаются из фактического pinned источника; native API conversion, Postbox/network/UIKit — явные тестовые границы. Реальная криптография/сервер и iPhone этим не подтверждены.

# PiP: отпускание пальца и текущий источник

Пользователь проверил опубликованную0.6.0/build100 и сообщил о продолжающемся отказе. На скриншотах системное окно уже открыто, а в галерее смещается заглушка «Это видео воспроизводится в окне…». Различие кадров само по себе не доказывает запуск другого ролика: в источнике мог остаться предыдущий кадр. Это физический отказ прежней версии, а не успешная приёмка PiP.

Сохраняется прежний выбор пользователя: **системный PiP**. Исходное видео следует за пальцем; направление сворачивания задаётся жестом. Конечную позицию отдельного системного окна выбирает iOS. После нового требования точного размещения при удерживании задан дополнительный вопрос; пока действует прежний выбор. Собственное окно внутри приложения не добавлено.

## Подтверждённые недостатки исходников0.6.0

- Запрос PiP создавался на `.changed` после48точек, ещё до отпускания пальца. Поэтому удерживание могло перейти в PiP посреди движения.
- Допускался pan узла без владения decoder; двигался весь `GalleryItemNode`, включая sibling-заглушку.
- Прежний вертикальный scroll-путь также мог запросить PiP независимо от отдельного pan.
- Неактивный AVKit-адаптер мог сохранять прежний videoNode/display layer после замены источника. Проверялось наличие `nativePictureInPictureContent`, но не его привязка к текущему плееру.
- Void-callback передачи галереи мог выйти по guard, а запрос всё равно завершался успехом. Теперь требуется подтверждение, что штатная передача действительно началась.

Это проверенные механизмы кода; единственная причина каждого скриншота без runtime-трассы не установлена.

## Новая обработка

`NagramiXReleasePiPGesture.swift.inc` захватывает timestamp первоначального касания, включая время удерживания. В `.began`/`.changed` AVKit не создаётся и не запускается. Пока палец на экране, viewport с видео получает точные x/y без прежнего ограничения0.45экрана. Заглушка находится вне этой поверхности. Отпускание — единственная точка решения; отмена возвращает геометрию.

Чистая Swift-политика `NagramiXPiPReleaseDecision.swift` различает короткий свайп и drag. Для свайпа: до0.35с, минимум12точек и согласованная скорость600точек/с; также учитывается быстрое перемещение минимум48точек со средней скоростью500точек/с, если конечная скорость обнулилась. Разворот в конце не запускает бросок в противоположную сторону. Для удерживания дольше0.35с достаточно12точек; обычное медленное перемещение — от48точек. Дрожание и нечисловые значения отменяются.

После подтверждения native PiP быстрый свайп продолжает движение **от точки отпускания наружу**; горизонтальный не добавляет y, вертикальный не добавляет x, диагональ сохраняет отношение координат. Drag остаётся в смещении отпускания без броска к краю, пока источник исчезает при штатной передаче. Расположение отдельного системного окна этим не задаётся. Исходная геометрия возвращается после fade для Expand.

Уже переданная/не принадлежащая текущему плееру заглушка не становится новым видео-жестом. Pan поглощает её перемещение, сохраняя кнопки/тапы; три native scroll pans по-прежнему ждут его отказа. OFF, фото, controls и zoom сохраняют прежний путь. Прежняя автоматическая передача из scroll callbacks удалена: остался один ended-путь.

`NagramiXCurrentPiPSource.swift.inc` привязывает запрос к UUID, videoNode и актуальному display layer. Неактивный устаревший адаптер пересоздаётся, активный не освобождается при обычной отмене. При явном запуске другого ролика после отпускания предыдущий известный PiP получает stop один раз; новый start ждёт didStop/освобождения владельца. Поздний запрос не закрывает окно, появившееся позже исходного previousOwner. Общий срок stop/readiness/start —3с. Проверяются настройка, foreground, centrality, window/navigation и identity; отмена/поворот/смена останавливают ожидание.

Callback передачи галереи возвращает Bool. Без подтверждения регистрации источника/начала штатного fade запрос не считается успешным, а несостоявшееся native окно останавливается. Запоздалые callbacks старого адаптера не очищают нового владельца и не меняют новый videoNode. Кнопка PiP обновляет неактивную привязку и различает media identity в альбоме. В локальный системный журнал пишутся только этап запроса, эфемерный UUID и domain/code ошибки AVKit, без текста, ID сообщений или пользователей.

Decoder, аудио, read-state, media storage, настройки/defaults, camera и предыдущие исправления не меняются.

## Физическая приёмка

- Три пропорции видео×8направлений, одиночное вложение/альбом,10повторов; cold first touch и потоковая загрузка.
- Быстрый свайп, удерживание до движения, медленный drag, остановка/разворот перед отпусканием: до подъёма пальца PiP не стартует; движется видео, не заглушка.
- После release быстрый бросок идёт в ту же сторону, drag не бросается к краю; Expand возвращает геометрию. Позицию системного окна оценивают с учётом управления iOS.
- Уже открытый PiP того же/другого видео, повторное открытие галереи, смена элемента/качества, отказ/таймаут, Cancel/OFF/фон/поворот; только текущий запрос управляет своим источником.
- Кнопки, pinch/zoom, фото, ссылки/контент с прежними native ограничениями и фоновый звук. При повторном отказе сопоставить этапы `NagramiX PiP` в локальном системном журнале.

Эта проверка на iPhone ещё не выполнена; source-проверки не являются её заменой.

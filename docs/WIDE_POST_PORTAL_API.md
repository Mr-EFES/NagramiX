# Нативный фон широких постов

Сборка212 прошла ранние Apple-проверки, применение overlay и проверку чистой основы, затем остановилась в `ChatMessageItemView`: у протокола `WallpaperBubbleBackgroundNode` нет `update(rect:within:transition:)`. Старый тестовый класс ошибочно предоставлял этот метод.

В Telegram13.2 фон сообщений использует портал, который следует за источником обоев автоматически. Абсолютные координаты нужны только внутренним конкретным источникам портала. Потребитель использует штатный `ChatMessageBubbleBackdrop.updateFrame`, который задаёт локальные размеры содержимого и маски.

Этап74 `wide_portal_api` удаляет устаревший кеш абсолютных координат, передающий их метод и два вызова из обычных и анимированных стикеров. Меняются три файла приложения. Геометрия широкой области, изображения, тема, реакции, выделение и обработчики остаются прежними. Объявления протокола и штатный backdrop защищены хешами; Git blob протокола `53ff04ca5f609345446c47977505c08599601eb4` сверен с официальным pin24638bc69bd083981b178dd1e7f921eebbf7fc46.

Новая проверка использует дословное объявление протокола и тело штатного метода обновления рамки. Исходный212 обязан отклоняться компилятором с `has no member 'update'`; исправление проходит проверку типов и478 проверок геометрии/состояния в debug и optimized. Проверяются локальные размеры портала и маски, перемещение без повторного создания привязок, границы при выделении, тема и выключение. Три смысловые регрессии проверяются в обоих режимах. ASDisplayNode, тема и аппаратный вывод явно представлены тестовыми границами; проверка не подтверждает пиксели на iPhone.

Проверка API поставлена перед длинным набором Apple-тестов, а полный сценарий добавлен в ранний набор. Планы и4603 снимка прежних этапов сохранены;31 обратимый checkpoint43–73 проверен. Новые изменения приложения добавляются следующим этапом75+, без переписывания74.

# Выбор чата для исключения уведомлений

Повторный физический тест показал: «Добавить исключение» в группах, каналах и историях открывает пустую панель без поиска; личные чаты работают частично. Предыдущая правка, вошедшая в0.5.9/build97, оказалась недостаточной. Новая доработка подготовлена в исходниках: **source_checked / compile_pending / device_pending**. В опубликованном IPA97 её нет; новая сборка и публикация по этой задаче не запускались.

## Подтверждённые пути сбоя в коде

1. `apply_notification_exception_peer_picker` добавил предикат категории перед Postbox pagination, но создал временный `ChatListFilter` с `id: 0`. `ChatListNode.init` вызывает `resetFilter()`, который для любого ID кроме `Int32.max` подписывается на сохранённые папки аккаунта. ID0 совпадает с `.allChats`: временный фильтр заменяется им либо `nil`, если такой папки нет. Предикат теряется, и поиск групп/каналов снова ограничивается постфильтрацией последних200 обычных чатов. Если нужные чаты старее, остаётся HeaderEntry, дальнейшая загрузка этой страницы не запускается.
2. В `PeerSelectionControllerNode.isEmptyUpdated` при `.empty(false, _)` вызывается `navigationBar.setContentNode(nil)`. Это полностью снимает поиск; принудительно раскрывать оставшийся `searchContentNode` в controller недостаточно. Последующее появление строк не возвращает снятый header.
3. В `ChatListNodePeersFilter` `.includeSelf` и `.excludeSavedMessages` используют одинаковый bit7. Штатное условие поиска трактует запрет «Избранного» как разрешение включить себя. Оно отличается от списка исключений, который свой чат правильно исключает.

Это проверка реальных веток закреплённой Telegram13.0 `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`, а не воспроизведение UIKit на iPhone. Определение `.allChats.id == 0` сверено с Git blob `44a0d386d95bb14de9d4bf11605ec10830f18d11`, SHA1 содержимого проверен.

## Текущая интеграция

Существующий `apply_notification_exception_peer_picker` сохранён:4fullSHA/7точных замен. Его transient bit18 `nagramiXNotificationExceptions` выставляется только из NotificationsPeerCategoryController. Предикат разрешает прочитанные, muted и архивные чаты и применяется до tail/around pagination. Права отправки и глобальный выключатель уведомлений не ограничивают выбор.

Новый `apply_notification_exception_picker_lifecycle` вызывается после предыдущих helpers, включая PiP. Он проверяет полные SHA256 обоих входов и3точных якоря до любой записи:

- `PeerSelectionControllerNode`: временный фильтр получает штатный sentinel `Int32.max`. `resetFilter` не заменяет его сохранённой папкой; первоначальная загрузка и дальнейшая прокрутка сохраняют предикат категории. Никакой папки в аккаунте не создаётся.
- Там же empty callback возвращается для помеченного picker, сохраняя штатный поиск при начальной загрузке, действительно пустой категории и обновлении списка. Прежнее раскрытие поиска и отказ от его scroll snapping остаются. Остальные selectors сохраняют штатный empty state.
- `ChatListSearchListPaneNode`: только помеченный поиск исключает собственный ID, «Ответы» и verification codes до общих веток, поэтому они не обходят ограничение через общий bit7. Локальные, контактные и серверные результаты продолжают использовать существующие category/secret flags.

| Раздел | Список до pagination | Дополнительные ограничения и поиск |
| --- | --- | --- |
| Личные чаты | contacts / nonContacts / bots | только CloudUser, без «Избранного» и secret chats |
| Группы | groups | legacy group / supergroup, включая форум без выбора темы |
| Каналы | channels | broadcast, в том числе канал без права отправки |
| Истории | contacts / nonContacts / bots | тот же выбор CloudUser, редактор с native `isStories` |

Поиск использует существующий ChatListSearchContainerNode и его фильтрацию local/remote; сохранение найденного peer выполняет `_internal_storedMessageFromSearchPeer` перед переходом в прежний редактор. Выбор одного чата, Confirm/Cancel/Remove, mute/previews/story settings, обновление списка исключений и сохранение после перезапуска не переписывались. Каталог31звука, пользовательские preferences, форматы БД, сохранённые папки и остальные подготовленные правки, включая PiP, не менялись. Доставка APNs этой правкой не диагностируется.

## Выполненные проверки

Полный запуск overlay:595выходов, только2изменённых Swift-файла относительно состояния с новой PiP-правкой,593побайтно прежних. `scripts/validate_notification_exception_lifecycle.py` выполняет настоящий helper: clean integration,3точные обратные замены и5отказов без частичной записи — повторное применение, дрейф каждого входа, отсутствие каждого входа. Проверены порядок/единственность вызова в pipeline, грамматика2Swift-файлов, Python syntax, release metadata и diff.

Это проверка интеграции исходников. В Linux-окружении нет Swift/Xcode/Apple SDK; нативная компиляция, Postbox runtime, UIKit и физический iPhone здесь не выполнялись. Прежняя Python-модель sparse pagination не проверяла resetFilter/снятие header и не доказывала исправность на устройстве. Новых моделей пользовательского поведения вместо реального теста не добавлено.

## Приёмка на iPhone после новой сборки

Для каждого из четырёх разделов при глобальных ON и OFF:

1. Открыть «Добавить исключение» и сразу проверить поиск и список. Проверить старые чаты глубже первой страницы, архив, muted/read и длинную прокрутку; для групп — legacy/supergroup/forum, для каналов — readonly.
2. Найти по имени, названию и username, включая контакт без переписки и серверный результат. Проверить отсутствие результатов, очистить запрос, отменить поиск, закрыть и открыть picker повторно. «Избранное», «Ответы» и secret chats не должны проходить в личные/истории.
3. Выбрать peer, открыть правильный редактор, отменить изменение; затем подтвердить звук, mute и preview (либо настройки историй). Проверить появление/редактирование/удаление исключения и сохранение после холодного запуска.
4. При действительно пустой категории поиск и закрытие должны оставаться доступны; входящий новый чат/обновление папок не должны убирать поиск или менять категорию.

Регрессии: обычный поиск, пересылка/рассылка и выбор тем форума, существующие исключения, персональный и общий каталог31мелодии. Итог физической проверки пока не подтверждён.

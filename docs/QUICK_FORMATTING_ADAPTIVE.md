# Адаптивная панель быстрого форматирования

## Текущая рабочая правка после 0.7.3

Пользователь утвердил финальный макет без надписи и с равными **внешними** зазорами: низ поля ввода → верх первого ряда плиток равен низ последнего ряда плиток → нижний край экрана. Это заменяет прежнее требование равных внутренних полос. Размеры зазоров компактные, не увеличенные как на поясняющей схеме A/B.

Новый поздний `quick_format_equal_spacing` после `quick_format_no_heading` меняет3Swift-файла с точными SHA. Высота полос больше не зависит от пустого UILabel. Сохраняется ориентир штатной headline-строки и прежних внутренних отступов; из верхней полосы вычитается реальный промежуток между полем ввода и панелью. Формула: `D=max(ceil(referenceLineHeight)+(landscape ? 12 : 16), safeBottom+8, composerGap+8)`, `top=D-composerGap`, `bottom=D`. Тогда верхний внешний зазор `composerGap+top=D=bottom`. Безопасная область снизу учитывается один раз.

Поле ввода передаётся слабой ссылкой на штатный textInputBackgroundNode.view. Координаты переводятся через UIView.convert только в общем окне. При изменении рамки поля ввода и присоединении панели запрашивается layout; обхода дерева окон и отдельной анимации нет. Порядок/обработчики12действий,4×3/6×2, шрифты,6ptмежду плитками и обычная высота input host не меняются. Для accessibility остаётся штатная прокрутка при физической нехватке места.

Проверка `validate_quick_format_spacing.py --source <final> --swiftc <swiftc>`: точные SHA, скрытый заголовок,240случаев реальной Foundation-геометрии в debug и optimized, внешнее равенство и все12плиток внутри доступной области, разные ширины/высоты/ориентации/safe area/gap. Вариант со старой симметрией внутренних полос отвергается. Swift parse и полный clean overlay с source guards остальных правок пройдены. Это не Apple SDK и не физическая проверка iPhone. Новая IPA-сборка не запускалась.

## Предыдущая реализация

Последнее утверждённое изменение: текст заголовка панели больше не отображается ни вертикально, ни горизонтально. Финальный guarded stage quick_format_no_heading очищает heading.text при создании и обновлении, скрывает UILabel и исключает его из accessibility. Сетки4×3/6×2 и действия сохранены. Предыдущие указания о видимом заголовке ниже описывают исходную адаптацию.

**Состояние выпуска:** правка входит в 0.7.2, сборку 130; нативная компиляция, IPA и символы проверены. Физическая проверка ожидается. [Результат и точный исходник](RELEASE_STATUS.md). Упоминания pending и отсутствия SDK ниже описывают проверки до этого выпуска.

Оба макета утверждены пользователем. Правка подготовлена после опубликованной 0.7.1/build127: source_checked / native_compile_pending / device_pending. В опубликованный IPA не включена.

Вертикально — 4×3, горизонтально — 6×2. Верхняя и нижняя полосы равны: максимум измеренной высоты заголовка с внутренними отступами и нижней безопасной области с 8pt. Safe area учитывается один раз внутри панели; фон заполняет прежние полные bounds без дополнительной цветной полосы. Заголовок «Быстрое форматирование» оптически смещён на 2pt вниз относительно центра верхней полосы.

В вертикальном порядке действия прежние. Горизонтальный порядок: Цитата, Скрыть, Жирный, Курсив, Дата, Зачеркнуть; затем Моно, Ссылка, Подчеркнуть, Код, Выносная цитата, Выделить всё. Меняются только позиции frames, индексы и обработчики действий сохранены. Выносная цитата/Выделить всё находятся под Датой/Зачеркнуть в обеих ориентациях.

Кнопки равномерно занимают доступную область, промежутки 6pt. Для низких клавиш и горизонтального режима группа иконка/подпись компактнее: иконка20pt и промежуток4pt вместо26/8pt. Минимальная высота44pt; на обычных проверенных размерах все12кнопок видны без прокрутки. Для увеличенных accessibility-шрифтов остаются уменьшение числа столбцов и вертикальная прокрутка, чтобы не скрывать действия. Подпись «Выносная цитата» сохраняет обычный пробел и получает базовый шрифт11pt вместо12pt, без сжатого кернинга; полное VoiceOver-имя не изменено.

Ориентация берётся из окна; до присоединения используется консервативная проверка ширины/соотношения сторон. После присоединения работает прежний layout native host. Измерение и кэш высоты штатной клавиатуры, собственно размеры input host, переходы эмодзи/клавиатура/форматирование, настройки, selection и rich document не изменены. Новых анимаций, зависимостей и BUILD-изменений нет.

## Интеграция и проверка

Поздний `quick_format_adaptive` после `video_display_resume` изменяет2nativeSwift-файла по полным входным/выходным SHA и точным якорям; все проверки выполнены до записи. Ранние этапы и canonical-шаблоны сохранены.

`python scripts/validate_quick_format_adaptive.py --source <published127-full-overlay> --swiftc <swiftc>` проверяет реальный Foundation-код сетки и извлечённую арифметику UIKit frames:673проверки сетки и24варианта полос в debug/optimized, порядок действий, отсутствие пересечений/обрезания, доступность крупного текста, неизменный кэш высоты, обратимость,5атомарных отказов и Swift parse. Последовательное применение четырёх текущих WIP-этапов сверено по8выходнымSHA; прежние исправления видео/бота не изменены.

Эти проверки не исполняют UIKit и не подтверждают измерение шрифтов/плавность на устройстве. README, версия, опубликованный IPA и тег не изменены; SDK/IPA/публикация не запускались.

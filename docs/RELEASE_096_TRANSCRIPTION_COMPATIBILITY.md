# Тип описания ошибки Premium-расшифровки

Попытка205 прошла ранние Apple-проверки и все проверки патчей, затем остановилась на основной компиляции TelegramCore. В `Transcription.swift` локальная переменная, полученная из `MTRpcError.errorDescription`, имеет тип `String?`; вызвать у неё `hasPrefix` без обработки `nil` нельзя. Сам исходный Objective-C заголовок не содержит аннотаций nullability. Прямое обращение к импортированному IUO-свойству в прежнем коде и копирование этого свойства в переменную имеют разные правила Swift.

Stage62 `release_096_transcription_compatibility` после61 меняет ровно одну строку: `let description = error.errorDescription ?? ""`. Пустое или отсутствующее описание попадает в прежнюю общую ошибку сети. Распознавание Premium/quota/tooLarge/unavailable, выбранный провайдер, RPC по отдельному файлу, защита исходного ID, сохранение одноразового голоса/кружка и управление временем жизни остаются прежними. Принудительного раскрытия optional нет.

Сохранены все4344 прежних `.inc` и планы. Добавлены шесть snapshots: один replacement/preimage и четыре guards, в том числе настоящий `MTRpcError.h`, Network.swift, Runtime и Settings расшифровки. Полное дерево62 отличается от61 только этой строкой;19исторических манифестов43–61 восстанавливаются через lossless checkpoints.

Предыдущая историческая fixture51 использует явный сетевой адаптер с обязательной строкой и потому не доказывала nullability настоящего Objective-C API. Её исторический контракт сохраняется. Новая окончательная fixture62 исполняет полный Premium Runtime/Engine/Coordinator с IUO-свойством, повторяет прежние сценарии и дополнительно передаёт `nil`, пустую строку и дополнительные ответы сервера. Проверяются обычная ошибка сети без неявного переключения на Apple и неизменность исходного одноразового сообщения.

Перед большим ранним набором теперь отдельно проверяется точный production-блок классификации. На Apple он импортирует неизменённый настоящий `MTRpcError.h` через iPhoneOS SDK при target iOS15; на Linux используется явно обозначенный IUO-адаптер. Исходный вариант205 обязан не скомпилироваться с диагностикой optional/hasPrefix, исправленный обязан пройти. Тип результата настоящего Network.request и SHA заголовка проверяются. Signal в узком typecheck — явная граница результата, не замена настоящей сетевой реализации. Полный runtime отдельно проверяет весь путь. Набор увеличен до27fixtures/54debug-Oexecutions; обязательные проверки и исторические snapshots не отключаются.

Локальная проверка IUO не подтверждает Objective-C importer Apple, полную сборку приложения или работу на телефоне. Эти результаты отмечаются отдельно после настоящего SDK/IPA и физической приёмки. Все прежние опубликованные релизы сохраняются; повторы текущей0.9.6 разрешены владельцем до успешной публикации.

# Ширина нижней панели

Владелец подтвердил широкую нижнюю панель с двумя вкладками «Чаты» и «Настройки». При добавлении «Контакты», «Звонки» или поиска используется штатная адаптация. Стадия `wide_bottom_bar` восстанавливает это поведение после опубликованной 0.8.9; стадия `wide_tab_bar_setting` добавляет согласованный переключатель.

Изменены два файла: native `TabBarComponent` и `TabBarContollerNode` (опечатка имени файла сохранена из upstream). У компонента новый аргумент `fillsAvailableWidth` с default false. Только root-панель из двух вкладок без поиска, бокового размещения, compact-режима и landscape wide-режима передаёт true. Все остальные callers получают прежнее поведение. Новый аргумент входит в сравнение компонента.

Полная ширина достигается прежним `tabBarSystemItemsLayout`: flex-раскладка использует всю доступную длину. Сохранены native высота 62 pt, внутренние отступы, hit testing, линза выбора, темы, значки, подписи и анимации. Дополнительная кнопка поиска не создаётся. Штатные боковая, compact, landscape и многоэлементная раскладки не меняются.

Стадия проверяет два точных входа и восемь зависимостей до первой записи. Native вход `TabBarComponent.swift` закреплён Git blob из официального pin Telegram 13.2; исторические canonical snapshots не изменены. Из-за отсутствия прежних локальных файлов реализация восстановлена по согласованному поведению, её байтовая идентичность потерянной стадии не заявляется.

`validate_wide_bottom_bar.py` исполняет фактические native функции раскладки, добавленный gate и `Params` в debug/-O. На режим: 277 проверок направления/режимов, семи размеров, native геометрии и стабильности параметров. Шесть отрицательных запусков выявляют потерю полной ширины, ошибку поискового gate и изменение поведения при дополнительных вкладках. Четырнадцать fail-closed вариантов проверяют отказ без записи при повреждении входов, зависимостей, templates, pin, стадии-предшественника, повторном применении и небезопасном пути. Полный parse обоих изменённых Swift-файлов проходит.

Эти проверки не выполняют Apple SDK-сборку и не подтверждают пиксельный результат на iPhone. Сборка остаётся запрещённой до новой личной команды владельца.

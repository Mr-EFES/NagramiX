# Выбор автора и удаление текущей переписки

Физический тест0.5.4 выявил: выбор автора объединяет обычные сообщения с архивными ID, но такой набор блокирует корзину; после удаления часть видимой переписки остаётся, повторный выбор автора сообщает пустой результат, хотя ручной выбор работает. Пользователь требует все доступные сообщения данного автора в текущем чате, включая локальные копии, с обычным подтверждением и сохранением остальной переписки.

## Подтверждённые дефекты

1. `NagramiXAuthorSelection` собирал только серверную историю/поиск и архив. Доступная локальная история Postbox не была самостоятельным источником выбора; успешная пустая серверная выдача давала пустой результат при видимых локальных сообщениях.
2. Смешанный набор передавался целиком в native пересечение прав. Архивный ID отсутствует в Postbox, поэтому мог убрать удаление для всех обычных сообщений. Особая ветка обрабатывала лишь набор, состоящий целиком из архива, причём сразу удаляла его без подтверждения.
3. Native backend создавал cloud operation и для отсутствующего архивного ID. Архивные копии не разделялись с реальными серверными сообщениями.
4. При локальном undo игнорируемые ID исключались из исходной истории, но архив добавлялся позднее. Сохранённая копия могла оставаться видимой во время окна отмены.

Нет серверного журнала пользователя: точная причина расхождения конкретной серверной выдачи и видимой истории не установлена. Исправление устраняет зависимость выбора исключительно от этой выдачи.

## Что изменено

- До прежней сетевой пагинации helper проходит всю существующую локальную историю страницами200, по реальному `message.author.id`, peer и thread. Cloud, Local, SecretIncoming и обычные EphemeralLocal; scheduled/quick-reply/template namespaces не добавляются в обычную переписку. Все страницы идут последовательно через Postbox, без общего лимита и с проверкой прогресса. Пустая страница автора не завершает обход чужих сообщений. Сохраняются server100/page, старый migration peer и final-проверка существования каждого выбранного ID. Секретные чаты обходятся локально, без попытки cloud RPC.
- На корзине права запрашиваются только для ID, имеющих сообщение в Postbox, и обычных неархивных ID. Отсутствующие локальные снимки не участвуют в пересечении. **Временное сообщение с настоящим expired placeholder в Postbox сохраняет native права/удаление**, а не ошибочно считается отсутствующим серверным сообщением.
- Архивный набор и выбор автора используют обычный native ActionSheet с предупреждением о числе выбранных сообщений и локальных копий. В смешанном наборе предлагаются штатные варианты удаления обычных сообщений; при полностью локальном наборе — только локальное удаление. При реальном отсутствии прав администратора объяснение остаётся, но очистка кэша больше не предлагается вместо удаления такого набора.
- Разделение actual live/local IDs в TelegramCore происходит **после** штатного расширения альбома и **до** cloud/secret операций. Снимки, которых нет в Postbox, удаляются из архива/локальной базы без RPC. Настоящие live/expired placeholders проходят прежнее native удаление с выбранным типом. История правок выбранных живых сообщений очищается прежним `removeLocal` в native backend.
- Подтверждение и native undo сохраняются: до commit архив не очищается. `pendingRemovedMessages.union(update.4)` исключает архивные вставки для ID, временно скрытых undo; отмена восстанавливает отображение.
- Новый thread-safe `isLocallyDeletedMessage` читает ownership независимо от видимости архива. Выключение настройки во время открытого подтверждения/undo не меняет смысл уже выбранной копии.

Выбор не вызывает clear-all-history/delete-all-from-author, не меняет временные метки/границы очищенной истории и не восстанавливает старую переписку из чужого аккаунта. Серверная пагинация по-прежнему запрашивает только доступную текущему аккаунту историю; локальный проход видит только существующие индексы Postbox. Чужие сообщения в супергруппе без разрешённых прав не удаляются принудительно. «У всех» не означает удаление локального архива на чужом устройстве.

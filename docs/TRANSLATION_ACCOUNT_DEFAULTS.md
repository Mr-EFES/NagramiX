# Начальные настройки переводчика по аккаунту

Владелец утвердил эскиз с тремя состояниями: «Прочее» для Premium, настройки переводчика для Premium и настройки без подписки. Внешний пункт «Настройки перевода» показывает **Telegram**; внутренний способ сохраняет полное название **Telegram Premium**. Другие названия способов не меняются.

## Поведение

Для новой конфигурации «Перевод сообщений» включён. «Показать панель „Перевода“» и «Переводить чаты целиком» выключены. Подтверждённый Premium аккаунта выбирает Telegram; без Premium используется Apple в «СЛОВАРИ», Google и Яндекс доступны для ручного выбора. Неизвестный peer не записывается как аккаунт без Premium.

Это начальные значения, а не сброс при каждом холодном запуске. Сохранённые ON/OFF, язык, исключения, модель, температура, ключи и индивидуальные настройки чатов остаются. Прежний сохранённый provider считается явным выбором. Новый optional `usesAccountDefaultProvider` отличает отсутствие выбора от ручного Apple; даже нажатие Apple, совпадающего с базовым значением, фиксирует ручной выбор. Явные способы остаются общими, как до изменения; только начальный способ зависит от аккаунта.

Ключ конфигурации `nagramix.translation.configuration.v1` и ключ чатов прежние. Подтверждённые статусы хранятся отдельно по account ID в `nagramix.translation.account-default.v1.<id>`. Пока используется начальный способ, его изменение обновляет общую revision и уведомляет существующие наблюдатели. Таким образом отложенный запрос прежней revision не публикует результат после смены способа. Повторный одинаковый статус и изменения статуса при ручном выборе не меняют revision.

## Связи исходников

Guarded стадия85 `translation_account_defaults` после84 `unified_glass_menus` заменяет8Swift-файлов и проверяет9зависимостей до записи. Новых файлов приложения, ресурсов, UI-ключей, зависимостей и изменений подписи нет. Прежние `.inc` и планы неизменны.

Модель предоставляет отдельный короткий `settingsTitle` и публичный `configuration(accountId:)`. Подписка реального AccountContext и открытая страница переводчика регистрируют известный peer. Внешний список, включая поиск, передаёт разрешённую конфигурацию. Внутренние галочки и запуск индивидуального, общего и inline-перевода читают тот же аккаунт. Общий dispatch также разрешает начальный способ по аккаунту. Глобальные master/язык/revision остаются общими; существующие отмена, entities, исключения и сетевые реализации не меняются. Панель выводит фактическое название выбранного способа.

## Проверки и пределы

`validate_translation_account_defaults.py` выполняет реальную модель на Foundation/Codable/locks в debug и optimized с warnings-as-errors. Единственная замена модели — изолированный экземпляр UserDefaults вместо стандартного хранилища. Изменённые строки выбора/регистрации/построения строк/запуска выполняются с явными account/peer/row-адаптерами. Проверяются два аккаунта, изменение Premium, отсутствие peer, повторные события, старые записи, ручной Apple и другие способы, оба состояния переключателей, revision и неизменность настроек чатов. Отдельные процессы проверяют сохранение после перезапуска. Семантические отрицательные варианты обязаны обнаруживаться. Настоящий Swift module export/import проверяет новые public API и отклоняет закрытый `settingsTitle`.

Проверка входит в обязательный ранний preflight и запускается ещё раз после применения стадии, до длительной SDK-компиляции. Прежние проверки не отключены. Полная Apple SDK-сборка приложения, пиксельная сверка UIKit и реальные сервисы на iPhone в этой задаче не выполняются. Actions/IPA запускаются только отдельной прямой командой. Сводка фактически выполненных проверок — [TRANSLATION_ACCOUNT_DEFAULTS_CHECKS.json](TRANSLATION_ACCOUNT_DEFAULTS_CHECKS.json).

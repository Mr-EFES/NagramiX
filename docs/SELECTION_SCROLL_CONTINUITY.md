# Выделение во время непрерывной прокрутки

Статус: source_checked, локальные проверки пройдены; Apple SDK и iPhone ожидают проверки. Новая IPA этой задачей не запускается.

Владелец прислал25,03-секундный пример: контекстное меню → «Выбрать» → прокрутка по левой полосе галочек. На видео счётчик остаётся на одном сообщении. Требуемое поведение: один непрерывный контакт расширяет диапазон вниз, у края продолжается прокрутка и выбираются подгружаемые строки, обратное движение снимает только новые отметки. Ранее выбранные сообщения сохраняются. Это уточнение прежнего контракта; проверка на видео новых исходников стадии68 не заявляется. Личные кадры и содержимое переписки в репозиторий не добавляются.

Дополнительный тест удержания у края выявил пропуск промежуточного сообщения в кеше диапазона. Кеш сохранял ObjectIdentifier исходного MessageHistoryView и location.id. ObjectIdentifier не удерживает объект. Пока обновление выделения пропускает очередной кадр display link, предыдущий объект может освободиться; новый snapshot может получить тот же адрес. При прежнем location.id сравнение ошибочно считает окно уже закешированным. В тесте после последовательных подгрузок4/5/6 выбранными оказались1/2/3/4/6, без5. Это воспроизведение исходного кода с адаптерами; причина конкретного поведения на телефоне не прослежена.

Стадия69 selection_scroll_continuity после selection_column_coordinates меняет только три выражения в ChatHistoryListNode.swift: кеш удерживает последний MessageHistoryView вместо его ObjectIdentifier, token содержит сам объект, сравнение выполняется через ===. Пока snapshot закеширован, его адрес не может повторно использоваться другим объектом. Удерживается только один последний snapshot; прежние очистка и начало жеста освобождают его. Определение строк, левый край стадии68, распознаватель, число касаний, диапазон, возврат, таймер0,45с, скорость и направление прокрутки прежние. Настройки, отправка, запись и PiP не меняются.

[Проверки](SELECTION_SCROLL_CONTINUITY_CHECKS.json) выполняют фактические методы истории и прежние5975 проверок выделения. Новый сценарий для обоих backend и отмеченного/неотмеченного начала держит один палец на визуальном нижнем краю повёрнутой истории, запускает штатный таймер и display link, подгружает несколько окон между обновлениями, затем ведёт палец обратно и завершает жест. Проверяются направление backend, скорость, новые и промежуточные строки, сохранение прежних отметок, остановка прокрутки и освобождение кеша. Weak reference отдельно детерминированно проверяет срок жизни кешированного snapshot; это не зависит от случайного повторения адреса аллокатором. Прежний код обязан провалить эту проверку. Отрицательные варианты отключают обновление под неподвижным пальцем и очистку кеша после отпускания.

Модель UIKit, загрузка строк, таймер и display link представлены явными адаптерами. Реальный жест UIKit, его плавность и конкуренция с прокруткой требуют iPhone. Apple preflight по-прежнему компилирует полные реальные history hooks с UIKit; native MessageHistoryView подтверждён закреплённым Postbox-классом. На телефоне проверить показанный жест, длительное удержание у обоих краёв, появление новых сообщений и возврат, отпускание и отмену, Legacy/CoreList, короткие/длинные посты, альбомы и обычную прокрутку вне полосы галочек. Опубликованная0.9.6 не изменяется; следующий IPA — по прямой команде владельца.

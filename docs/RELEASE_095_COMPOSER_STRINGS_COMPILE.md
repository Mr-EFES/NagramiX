# Нативные строки ошибок вложений 0.9.5

В попытке200 исправленный SettingsUI прошёл компиляцию. На следующем зависимом модуле TelegramUI обнаружились два обращения к отсутствующему `PresentationStrings.Common_UnknownError` в ChatControllerOpenAttachmentMenu.swift, строки168/1535. Прежний custom-member audit проверял расширения NagramiX и не доказывал наличие нативных generated getters Telegram. Composer runtime fixture явно заменяет UI alert на счётчик ошибки; такой тест не проверяет имя native строки.

Stage45 `release_095_composer_strings_compile` после `release_095_fonts_compile` меняет только эти два обращения на существующее `Login_UnknownError`. Эту же стандартную строку уже использует обычная обработка вложений Telegram. Весь остальной файл побайтно прежний: черновик, текст/файлы, отмена, подтверждение Send, получатель, entities и отправка не изменяются. Один replacement,6guards,8новых snapshots;3545старых `.inc` сохраняются. Native generator проверяется и по SHA256, и по Git blob e10ff2b8a797200c6027b3310f66f5cf61000d4c, подтверждённому official24638bc69bd083981b178dd1e7f921eebbf7fc46. Catalog и настоящий build rule также pinned.

Новая проверка запускает фактический GenerateStrings.py на итоговом английском каталоге, создаёт оригинальный Objective-C header и сверяет `__swift_name__` всех12190native getters/методов. Затем проверяет обращения через strings/namedStrings во всех Swift-файлах. Комментарии исключаются, типы вроде PresentationStrings.FormattedString не смешиваются с экземплярами. Другой владелец допускается лишь по фактической аннотации параметра и объявлению его полей в исходнике; исключений по выдуманным native именам нет. Регрессия Common_UnknownError отдельно возвращается в настоящий вызывающий файл и должна быть отклонена.

На macOS тот же настоящий сгенерированный header импортируется в Swift через Clang module map. Все найденные native member expressions typecheck против него с warnings-as-errors/iPhoneOS15+/ARM64; отсутствующий getter из SDK200 должен быть отвергнут. Canonical audit выполняется сразу в metadata gate, настоящий Apple-header check — до длинного overlay, полный audit/header check — в обязательном stage45 validator перед SDK. Это name/import contract, не замена полного Swift argument/body typecheck или device testing. Генератор выполняется без importlib bytecode cache, поэтому не пишет __pycache__ в проверяемое дерево.

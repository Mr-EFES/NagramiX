## Пользовательское поведение

Настройки NagramiX → Интерфейс → Контекстное меню. Прежние «Переслать без автора» и «Возможность рассылки» управляют видимостью действий «Переслать» и «Рассылка». Ключи, начальные значения, перенос старого выбора и ID не менялись. Отдельного «Обход защиты от копирования» нет.

В обычном защищённом чате «Переслать» подготавливает новую копию для одного адресата. Штатный picker ограничен одним получателем; выбор сам ничего не отправляет. После выбора доступны комментарий, явный Send, отправка без звука/по расписанию. «Рассылка» использует прежнюю панель с одним или несколькими адресатами. Оба действия доступны также в нижней панели выделения; проверяются весь актуальный набор ID и возможности каждого сообщения. Неподдерживаемое сообщение не превращает пакет в незаметную частичную отправку.

Защищённый оригинал не отправляется через server forward: только новые сообщения без источника. Перед picker явно выбранные основные вложения загружаются целиком через штатный MediaBox с отменой. При ошибке picker не открывается, сообщение не ставится в очередь. При Send содержимое проверяется снова: подготовленные полные файлы получают LocalImage/LocalFile identity и временную независимую ссылку, cloud reference оригинала не используется. Если к этому моменту данные недоступны или staging не удался, отправка останавливается с локализованной ошибкой до enqueue. Фоновой очереди повторной рассылки нет.

Текст, Unicode, entities, custom emoji, спойлеры, обычные media attributes и альбомная группировка сохраняются. Скрытие подписи применяется. Source reply/thread/send-as/payment не копируются; тема и оплата адресата, беззвучный режим, расписание и correlation IDs остаются на прежнем native commit. Обычная незапрещённая пересылка и архивный одиночный черновик сохраняют прежние пути. «Репост» остаётся настоящей серверной пересылкой со штатными ограничениями.

Когда включён хотя бы один из этих двух существующих пунктов, защищённое обычное содержимое можно копировать штатным «Копировать» и сохранять из контекстного меню. Фото/видео используют штатный SaveToCameraRoll и запрос доступа к Фото только по действию. Как и в штатном меню, пункт Фото появляется при доступном основном ресурсе. «Сохранить в Файлы» доступен для обычных защищённых файлов, включая документы и видео; загрузка/отмена используют native fetch, папка выбирается штатным Files picker. При обоих OFF новые возможности защищённого экспорта скрыты. Незащищённые сообщения сохраняют прежнее поведение.

Секретные чаты, полученные одноразовые/исчезающие секретные, платные/истёкшие медиа, служебные сообщения, коды подтверждения и незавершённые/ошибочные отправки не получают новое разрешение копирования. Уточнение21октября: для собственных отправленных одноразовых голосовых/кружков добавлен отдельный account-scoped путь новой одноразовой загрузки через «Переслать»/«Рассылка»; сохранение не расширяется. [Контракт дополнения](OWN_VIEW_ONCE_COPY.md). Неподдерживаемые типы не преобразуются в фиктивное вложение. Доступ к содержимому и права отправки адресату не обходятся. Новый сценарий не снимает флаги защиты с исходного сообщения и не меняет настройки владельца чата.

Checkbox «Свободный скриншот» независим: его ON/OFF по-прежнему управляет только capture protection и новым secret screenshot action. Дополнительные права копирования задаются существующими действиями контекстного меню.

## Нативная интеграция

content_copy.py применяется после screenshot_bypass.py. Проверяются6полных SHA и21точная операция, оба template/collision/parent назначения до первой записи. Изменяются только ChatControllerForwardMessages, ChatController, ChatInterfaceStateContextMenus и компонент ChatMessageSelectionInputPanelNode; добавляются два helper через существующие source globs.

TelegramCore/NagramiXContentCopy содержит eligibility и конечный Signal загрузки основных ресурсов. Дублирующиеся resource ID загружаются один раз; выбирается самое большое фото, не thumbnail. Не вызываются consume/read-history/просмотр истории/отправка сообщения. Failure/cancel освобождают fetch/keep leases, late callbacks не завершают отменённую подготовку. Уже полученный архив не пытается загрузиться по удалённому server ID. Прежний NagramiXArchivedMediaCopy повторно используется для независимой локальной отправки; его код не менялся.

TelegramUI/NagramiXProtectedCopyPreparation привязывает отменяемую загрузку к собственному MetaDisposable ChatController, с dispose в deinit. Progress появляется с задержкой150мс; кеш/текст не дают вспышки экрана загрузки. Основной picker не содержит source forwarded IDs для защищённых копий. У protected single recipient limit1 действует и на чат-лист, и на Контакты/поиск через уже существующий native bridge.

При аудите pinned SaveMediaToFiles обнаружено, что он рассчитан на музыку и использует mp3 fallback. Музыка делегируется прежнему exporter. Для остальных защищённых файлов новый helper получает полные байты native fetchMediaData, закрепляет их через TempBox/hard link с copy fallback на фоновой очереди и сохраняет безопасный basename; известный MIME даёт корректный fallback, PDF/видео не превращаются в mp3. Lease переживает завершение fetch, удаление исходного cache path и dispose операции после открытия picker; освобождается после completion/dismissal или если picker не был представлен. Ошибки staging показывают сообщение об ошибке сохранения, без ложного сообщения об отправке.

Native Repost/external Share и их copy-protection tips сохранены. Разрешение снимается только с двух custom copy buttons; источником возможности остаётся полный свежий набор сообщений. Права удаления/жалобы/меток, readonly preview/read gates, архив и его очистка, network/crypto, presence/privacy, PiP/player/onboarding не меняются.

# Автовоспроизведение голосовых

Проверка текущего выпуска: **compile_passed / device_pending**, нативная сборка№86 и независимая проверка опубликованного IPA успешны. [Результат и исходный SHA](RELEASE_STATUS.md). Физические сценарии остаются непроверенными.

## Состояние

Физическая проверка предыдущей сборки №84, выявила ошибку: следующее сообщение не запускалось, но текущий плеер оставался на паузе в верхней панели; одноразовый экран не закрывался. Аналогичное поведение у кружков. Исправление подготовлено в исходниках: implemented / compile_passed / device_pending. Опубликованный IPA №84 остаётся прежним и этой правки не содержит. Правка включена в проверенный№86; физическая приёмка ожидается.

## Поведение

Настройки NagramiX → Функции → СООБЩЕНИЯ → «Автовоспроизведение голосовых». По уточнению пользователя checkbox положительный: default OFF без сохранённых предпочтений, ON возвращает штатный auto-next. Public voiceAutoplay/voiceAutoplayEnabled, UI updater, поиск и RU/EN подписи имеют положительный смысл; stable IDs130/131 прежние.

Хранение совместимо с опубликованным пакетом: единственный legacy ключ `nagramix.messages.disableVoiceAutoplay` сохраняется, положительное значение читается и записывается инверсией. Missing/legacy true → checkbox OFF, legacy false → ON. Выбор пользователя сохраняет прежнее поведение после обновления, холодного запуска и изменения других настроек; отдельного конкурирующего ключа нет.

При выключенном автовоспроизведении окончание голосового или кружка завершает текущий плеер через штатный callback playedToEnd. MediaManager проверяет идентичность текущего voice player, останавливает и освобождает его, публикует пустое состояние; верхняя панель и видео-overlay закрываются. Следующее сообщение не открывается и не получает отметку прослушивания от автоматического запуска. Позиция к началу не перематывается; повтор обычного или сохранённого сообщения возможен новым ручным выбором.

Перед завершением проверяются поколение playbackItem и currentPlayedToEnd: поздний callback старого элемента не закрывает новый, повторное окончание не вызывает повторный cleanup. Очищаются scheduledPlaybackAction и scheduledStartTime; текущий item приостанавливается, затем вызывается native owner callback. В ветке выключенного автовоспроизведения нет .next, .play или seek0. Включённое автовоспроизведение, музыкальная очередь, ручные next/previous/seek, prefetch и native read/consumed обработчики сохраняются.

Одноразовый экран прежде ждал исчезновения globalMediaPlayerState. Теперь он использует filteredPlaylistState по accountId, playlistId, полному messageId/index и type .voice: сначала ждёт появления своего элемента, затем его исчезновения. Начальный nil не закрывает экран раньше запуска; другой аккаунт, сообщение или оставшийся музыкальный плеер не удерживают закончившийся экран. Штатные возврат/анимация/освобождение idle timer остаются. Обработчики архивирования временных медиа, consumption и сохранение файлов не меняются.

## Проверки исходников

Полный overlay на проверенной базе Telegram 13.0: 427 outputs, изменены только два native файла плеера/одноразового экрана, settings/model/string bindings и две RU/EN строки; остальные 420 побайтно совпадают с опубликованным source. Шесть substitutions полностью обратимы до audited integrated источников. Полные SHA256 обоих inputs проверяются до записи; четыре drift-сценария и повторное применение отклонены без изменения файлов. Все пять изменённых Swift grammar деревьев без ошибок. Положительные bindings/default, обратные read/write legacy значения и стабильные IDs проверены; прочие RU/EN строки прежние. Native manager identity guard, ON/music/manual ветки, архивные/consumed paths сохранены. Python, release metadata и diff check проходят.

Proof: `/tmp/nagramix-051-autoplay-positive-proof`; проверка `/tmp/nagramix-validate-autoplay-positive.py` с PYTHONPATH=/tmp/nagramix-syntax. Это проверка исходников на Linux, без Apple SDK; после этой проверки нативная компиляция пройдена в№86; фактическое закрытие UIKit на iPhone ещё не проверено.

## Физическая приёмка после новой сборки

1. Чистая установка: checkbox OFF. Голосовое→голосовое, кружок→кружок, смешанная очередь. В конце текущего верхняя панель/увеличенный кружок закрываются, следующее не запускается. Ручной повтор обычной или сохранённой копии работает.
2. Одноразовые голосовое и кружок: экран закрывается по окончании без выхода из приложения. При включённом сохранении доступна прослушанная архивная копия; проверить также выключенное сохранение, входящее/исходящее и ручное закрытие.
3. Повторить с ранее запущенной музыкальной очередью на паузе, разными аккаунтами и быстрым выбором другого сообщения рядом с концом: старый callback не закрывает новый плеер, музыка не удерживает одноразовый экран.
4. ON возвращает штатный auto-next; OFF закрывает текущий плеер без запуска следующего. Проверить ручные next/previous, seek, скорости, повтор/shuffle музыкальной очереди и изменение ON/OFF во время воспроизведения. Сохранённый выбор остаётся после перезапуска. При обновлении прежний «Отключить…» ON отображается как новый OFF, прежний OFF — как новый ON; проверить оба случая, включая изменение соседней настройки.
5. Фон, блокировка, наушники/Bluetooth, proximity и системные прерывания. Проверить геометрию, маску и прозрачность сохранённых кружков. При краше сохранить iOS stack trace.

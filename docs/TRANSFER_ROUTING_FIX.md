# Пересылка одноразовых записей и адресаты рассылки

**Уточнение22октября:** пользователь воспроизвёл потерю адресатов/неверную тему в IPA114. Проверки ниже не охватывали смену folder list node и server reply target новых копий. Дополнительное [исправление](BROADCAST_TOPICS_FIX.md) находится только в исходниках; физическая приёмка прежней рассылки не пройдена.

Текущий результат: включено в Release0.6.8/build114; Apple SDK compile и опубликованный IPA проверены. Физическая приёмка **device_pending**. Source-only описания ниже — история подготовки; [актуальный статус](RELEASE_STATUS.md).


21 октября после Release 0.6.7/build113 пользователь сообщил две регрессии: «Переслать» свою одноразовую запись открывает интерфейс рассылки; выбор вложенного рабочего канала в рассылке теряет ранее отмеченных получателей. Исправление находится в main, **source_checked / native_compile_pending / device_pending**. Опубликованный IPA113 его не содержит. Новая сборка не запускалась.

## Причины и изменения

1. Защищённые оригиналы, включая свои одноразовые voice/round, безусловно попадали в `nagramiXSelectCopyRecipient`. Этот bridge включает массовое выделение даже при лимите одного получателя. Теперь собственная одноразовая запись в одиночном режиме проходит обычный выбор → чат назначения → штатный Send. Нет кнопки массового выбора или счётчика адресатов. До Send ничего не отправляется. Смена получателя уже подготовленного одноразового черновика сохраняет одиночный режим.
2. Bridge повторно вызывал `beginSelection` после выбора вложенного канала/темы. Нативная инициализация очищала `ContactListNodeGroupSelectionState`; в итоге оставался только последний выбранный канал. Для copy picker инициализация теперь однократная. Переходы Контакты ↔ Чаты переносят весь текущий выбор, включая снятие отметок. В других штатных picker этот режим не включён.
3. Поиск в массовом выделении игнорировал контейнеры сообществ/форумов и мог обойти фиксацию threadId для результата-темы. Теперь контейнер открывает штатный вложенный выбор, а выбранная тема проходит общий callback. Перед запросом оплаты/асинхронной отправкой фиксируется словарь **peerId → threadId** только для выбранных адресатов. Старое значение темы удаляется и при новом nil. Контейнер сообщества и форум без явно выбранной темы не отправляются; не подставляются General, первая тема или первый канал. Обычная группа/канал не требуют искусственного threadId.

Сценарий пользователя с рабочей группой разбирается как нативный community/container и как forum/topic: поддержаны обе ветви закреплённой базы. Доставка конкретного рабочего пространства требует повторения на устройстве; лабораторная проверка не подтверждает её автоматически.

## Сохранение одноразового режима

При Send нативного forward draft оригиналы и актуальный получатель/платность читаются через Engine Data. Это также работает для восстановленного черновика, без временного глобального payload. Пока идёт чтение, повторный Send блокируется. Если изменились чат, тема, черновик или ввод, старый callback не отправляет сообщение.

Собственные одноразовые записи вместо `.forward` получают прежний local copier с account identity и `forceLocalMedia=true`. Он повторно проверяет полные локальные байты и создаёт новый one-shot timer. Обычные forward draft и архивный fallback сохраняют свои пути. Отсутствующий локальный файл не превращает запись в обычную копию или серверную пересылку. Сохраняются ограничения получателей: обычные частные пользователи, без self/ботов/платности/групп/секретных чатов; schedule/whenOnline/repeat/postpone запрещены. Последняя native diversion в scheduled также не может принять одноразовую копию.

«Рассылка» остаётся выбором нескольких адресатов с собственной панелью Send. Обычное видео не становится одноразовым. Copier, проверка владельца, TTL/upload, входящие одноразовые записи, сохранение, архив, Repost, чтения, контакты/permissions, PiP, прокси и настройки/defaults не переписаны.

## Интеграция и проверка

Финальный `ios/transfer_routing.py` / `transfer_routing_patches.json` применяется **после quick_format**: 6 полных SHA256 и 20 точных операций, все проверки до записи. Исторические own_once/content_copy/quick_format стадии не меняются. Новых зависимостей, настроек или формата persisted state нет.

- Полный feature overlay закреплённого Telegram-iOS13.0 применён заново: 421 файл, изменились только 6 заявленных native файлов, **415 побайтно прежние**.
- `scripts/validate_transfer_routing.py`: **65 проверок** в debug и optimized с warnings-as-errors. Выполняются извлечённые native selection state, guard повторной инициализации, перенос выбора, выбор одиночного пути, snapshot/routing тем, асинхронный preflight Send и dispatch собственных записей. Обе прежние ошибки воспроизведены. UIKit/Engine/сеть — управляемые границы, не реальная доставка.
- **147 прежних own-once + 75 protected-copy проверок** в каждом режиме повторно прошли на прежней стадии. Проверенные policy/copier/staging/preparation и native media-timer conversion побайтно совпадают с текущим кодом: новые тесты отдельно проверяют изменённый dispatch/picker.
- **14 отказов без частичной записи**: повторное применение, missing/drift каждого входа и последняя несовпавшая точка. Swift grammar всех шести файлов, Python AST, release metadata и diff проверены.

Proof: `/workspace/.codex-validation-nagramix-transfer-fix/verification.json`, `own-once-regression.json`, `before.json`, `overlay-reviewed.log`. Полный новый fixture: `/workspace/.codex-validation-nagramix-prefer-ipv6/native-transfer-routing-reviewed`. Apple SDK/IPA в этой задаче не запускались.

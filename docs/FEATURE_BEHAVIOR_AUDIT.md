## Подтверждённые расхождения

### A1. «Фото максимального качества» не управляет всей современной отправкой

Сценарий: выключить максимальное качество, выбрать20%, снова включить максимальное качество и отправить обычное фото из Галереи, оставив штатную кнопку HD выключенной. Ожидается100% и увеличенный размер. Текущий modern-путь создаёт ресурс с `forceHd=false`, без зафиксированного качества; загрузчик берёт прежние20%. При чистых настройках JPEG остаётся100%, но наш переключатель сам не включает HD.

Точки в развёрнутом исходнике:

- `SettingsUI/Sources/NagramiXSettingsController.swift:1263` скрывает ручной ползунок при ON; callbacks1447/1448 сохраняют правильные значения.
- `TelegramUI/Components/ChatMediaSend/Sources/MediaPickerChatMediaSendMapping.swift:139` задаёт HD только из штатного редактора (`editing.isHighQualityPhoto`).
- `TelegramUI/Components/ChatMediaSend/Sources/ChatMediaSendMessages.swift:144` создаёт PhotoLibraryMediaResource без качества и без нашего флага.
- `LocalMediaResources/Sources/FetchPhotoLibraryImageResource.swift:114` при отсутствии quality читает `mediaSettings.jpegQuality`, который не учитывает `highQualityPhotos`.
- В старом `LegacyMediaPickers.swift:387` флаг, напротив, явно выбирает100% и HD. Поэтому настройка действует по-разному в двух отправщиках.

Выполнены реальные функции построения photo resource и реальное выражение выбора JPEG quality с адаптерами графики/ресурсов. Оба режима компиляции подтвердили20% при максимальном качестве ON. Photos, кодирование настоящего изображения и сервер в этом probe не эмулируются как проверенные.

### A2. Ползунок качества игнорируется у отредактированного фото

Сценарий: максимальное качество OFF, выбрать20% либо90%, обрезать/обработать фотографию в Галерее и отправить как фото. В обоих случаях `ChatMediaSendMessages.swift:115` вызывает JPEG-encoder с постоянным `quality:0.6`. Выбранного значения у функции нет во входах. Обычный неотредактированный library-путь при OFF продолжает читать ползунок; неисправность не относится ко всем фотографиям подряд.

Два запуска actual rendered-photo builder подтвердили передачу60% в encoder при обоих запрошенных значениях. Это отдельное проявление пропущенного подключения настроек к modern ChatMediaSend.

### A3. «Широкие посты каналов» охватывают не каждый тип

Флаг читается общей раскладкой `ChatMessageBubbleItemNode.swift:1951`; она расширяет бюджет пузыря, обычные медиа и мозаику. Но `ChatMessageItemImpl.swift:318–384` выбирает отдельные ChatMessageStickerItemNode/ChatMessageAnimatedStickerItemNode для стикеров, кубиков и самостоятельных крупных/анимированных эмодзи. Эти узлы `wideChannelPosts` не читают. Например, обычный sticker-node сохраняет собственную область184×184 при масштабе100% (`ChatMessageStickerItemNode.swift:447`).

Это неполный охват относительно требования «для любых типов», а не утверждение о поломке ширины каждого обычного поста. Нужна единая широкая область поста с сохранением пропорций содержимого. Отдельно текущая eligibility общей раскладки исключает preview, рекламу и reply-thread; эти области не следует молча выдавать за обычную историю канала.

Проверка — статическая трассировка реального выбора узла и его расчёта размеров. Повторённый runtime широких постов проходит для общей bubble/media/mosaic раскладки, но отдельные sticker-renderers он не проверяет. Скриншоты iPhone для этого исключения не получены; дата появления этого ограничения не установлена.

## Отдельные замечания к смыслу переключателей

**S1. «Расшифровка сообщений» OFF не выключает штатную расшифровку Telegram.** Наш runtime проверяет `config.enabled` (`NagramiXTranscription/Sources/Runtime.swift:141`), а обычные Premium/trial/boost ветки file/instant-video узлов независимо показывают кнопку и могут вызвать native transcribeAudio. Это фактическая граница действия переключателя. Название выглядит общим, поэтому пользователь может ожидать полного выключения. Сохранение штатного пути само по себе не объявляется регрессией; менять его без согласованного смысла настройки не следует.

**S2. Ручной перевод при OFF — согласованное поведение.** Ручное действие вызывает перевод с `manual:true`, тогда как автоматический режим соблюдает master. Это учтено как намеренное исключение, не включено в число ошибок.

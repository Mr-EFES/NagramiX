## Согласованное поведение

Для обычных сообщений Репост — настоящий native forward Telegram с автором, только где это разрешено сервером. Запрещённый пункт скрывается. Сохраняется ранее отдельно согласованное исключение для временных вложений: их «Репост» отправляет самостоятельную копию с текстовой подписью автора, без поддельной серверной метки пересылки. «Переслать» создаёт собственную копию одному получателю, «Рассылка» — нескольким; эти два действия не зависят от флажка «Свободный контент». Это последнее уточнение заменяет предыдущие OFF-gates. Отдельные настройки временного хранения, доступность исходных данных, права отправки адресату и подтверждение стоимости не подменяются флажком.

Приоритет — полноценная копия. Обычные доступные медиа отправляются как новые сообщения через native cloud media reference; скачивать целое видео перед каждой отправкой не требуется. При отказе ссылки выполняется ограниченный переход к загрузке и новому upload. Защищённые/сохранённые вложения, требующие локальных байтов, подготавливаются с реальным прогрессом, отменой, ошибкой и повтором. Кэш используется повторно. Повтор не создаёт новое сообщение при потерянном подтверждении: pending ID/random_id сохраняются.

Копия сохраняет все вложения, подпись, entities, ссылки, исходный выбор preview, порядок и допустимую группировку. Локальные файлы закреплены до передачи в native outbox. Отложенная/тихая/обычная отправка используют штатные обработчики. Простой тап/Enter отправляет, удержание открывает native send options. Результат enqueue не считается подтверждением сервера; состояния и ошибки отслеживаются по адресатам.

Обычные выбранные строки не перемещаются. «Переслать» использует одиночное выделение с заменой выбранного адресата, «Рассылка» — несколько галочек. Поиск отделён от обычного выбора. Новый найденный контакт добавляется после адресатов, уже выбранных к моменту поиска; если их не было, он остаётся сверху, а последующие обычные выделения не передвигают список. Одинаковые адресаты и темы не дублируются.

## Временные сообщения

После уточнения владельца отдельно перепроверены четыре поддерживаемых типа в личной облачной переписке: фото, видео, голосовое, кружок. При включённых «Временных сообщениях» общая копирующая отправка применена к полученным и собственным вложениям. «Переслать» и «Рассылка» создают полные самостоятельные копии без подписи автора и без переноса одноразового таймера. Для временного «Репоста» восстановлена ранее согласованная подпись автора; для кружка это соседнее текстовое сообщение. Заголовок выбора остаётся «Репост», а payload проходит тот же batch sender, без обращения к уже удалённому server ID.

Ответ на существующий оригинал сохраняет native reply. Если оригинал уже удалён и доступна локальная временная копия, Ответ вставляет цитату с автором и текстом/описанием вложения. Сохранение файлов, воспроизведение, локальная расшифровка и анимация этого уточнения не менялись. Доступность полных сохранённых байтов и права отправки адресату остаются необходимыми.

Ограниченное повторное отправление своей одноразовой голосовой/кружка при OFF остаётся прежним отдельным исключением. При ON оно больше не перехватывает обычную сохранённую копию: не добавляет новый одноразовый таймер и не сужает её получателей/режимы отправки. Изменение политики во время выбора адресата, оплаты или даты перепроверяется до staging, commit и enqueue, чтобы не сменить механику молча. Сам callback временного репоста также перепроверяет включённую функцию.

## Типы содержимого

Текст/entities/emoji, фото, видео, кружки, голосовые, полученные временные записи, аудио, GIF, документы/файлы/стикеры, контакты, точки/места и превью используют обычные native payloads. Rich blocks и альбомы сохраняются целиком. Опросы и викторины сохраняются интерактивными, когда доступны необходимые данные; неизвестный правильный ответ не выдумывается, чужие голоса не переносятся. Вложения вариантов/условия/решения опроса должны загружаться, а не исчезать.

Игровые 🎲/🎰 и другие dice сохраняют исходный результат изображением; новый бросок и денежная ставка не выполняются. Native конечный кадр используется при доступных assets, резервный renderer отображает тот же результат. Истории с доступным самостоятельным медиа превращаются в собственное сообщение с текстом/entities. Для связанного с сервером содержимого, которое нельзя полноценно воспроизвести, используется согласованная карточка с доступными сведениями/ссылкой.

Игры сначала пробуются как native game payload в обычной очереди. При известном отказе сервера используется подготовленная карточка исходного объекта с тем же pending/random_id. Чек-лист создаётся интерактивно, когда текущие права и его состояние позволяют точную самостоятельную отправку; иначе карточка сохраняет пункты и отметки. Полностью полученный paid-media bundle копируется обычными медиа без создания нового счёта. Для недоступной платной части, счетов, розыгрышей и других специальных объектов действует карточка/ссылка; платёж, розыгрыш или серверные права не создаются автоматически.

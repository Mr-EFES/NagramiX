# Отступ файла в начале расширенного поста

Статус: `source_checked / native_compile_pending / device_pending` после завершения доступных проверок, зафиксированных в [отчёте](RICH_FILE_PADDING_CHECKS.json).

Владелец подтвердил красную разметку второго скриншота: кнопка воспроизведения и имя аудиофайла почти касались верхней границы пузырька. Эталон — обычный файл на первом скриншоте с видимым внутренним отступом. Исправление касается верхнего отступа вложения; файл и текст остаются одним сообщением.

Обычный `ChatMessageFileBubbleContentNode` берёт верхний отступ из `layoutConstants.file.bubbleInsets.top` (15 pt). Расширенный пост использует V2: `.audio` и `.document` имеют `flushAbove`, первый блок располагается при y=0, а host добавляет только рамку страницы 2 pt. Это объясняет расхождение двух способов отображения поста.

Стадия80 `rich_file_padding` после `named_link_preview` меняет три существующих файла. V2 принимает необязательный `leadingFileInset`, по умолчанию 0. Только первый отрисованный audio/document в последовательности верхнего уровня получает этот минимум до вычитания рамки host. Пустые якоря и отсутствующие медиа не занимают ведущий край; вложенные последовательности сохраняют прежнюю геометрию. Host пузырька передаёт обычный file inset; стиль без пузырька оставляет 0. Предпросмотр отправки использует тот же штатный отступ. Заголовок автора/ответа не добавляет прежний зазор flush-медиа поверх нового собственного отступа файла.

Весь блок, подпись и следующий текст перемещаются одним проходом layout; высота пузырька включает добавленный зазор. Области нажатия, выделения и цитирования получают новые координаты из того же результата. Строки плеера/документа, правила переноса/обрезки имени, проигрывание, загрузка, отправка и данные поста не меняются. Фотографии/видео, ширина постов, рамка и маска страницы, внутренняя геометрия документов/аудио, нижний статус, кеш/reveal, код/таблицы/цитаты и другие поверхности V2 сохраняются. Для прочих V2-вызовов новый аргумент остаётся 0; отправочный предпросмотр включается явно.

Все три новых native preimage сверены байт в байт с официальным Telegram-iOS pin `24638bc69bd083981b178dd1e7f921eebbf7fc46`; Git blob закреплён в loader/плане. Старые `.inc` и планы не переписываются. Новых файлов приложения, строк, ресурсов, зависимостей, SDK/подписи нет; импорт `ChatMessageItemCommon` в отправочном предпросмотре обеспечен существующей прямой BUILD-зависимостью TelegramUI.

```sh
python3 scripts/validate_rich_file_padding.py \
  --source <native> --swiftc <swiftc> --report <json>
```

Регрессия исполняет настоящий `layoutBlockSequence`, native spacing/metrics, audio/document ветки создания строк и header helper в debug и -O. Проверяет обычные/широкие/планшетные размеры, разные масштабы текста, якоря, отсутствующее медиа, подпись и следующий текст, высоту/ширину, media index, вложенные блоки, прежние default=0 кадры и заголовки. Исходный driver и смысловые мутации обязаны воспроизвести отсутствие отступа или связанные ошибки. UIKit, модель данных/сеть, отрисовка текста и посторонние блоки представлены явными границами. Проверяются решения и координаты; реальные пиксели, взаимодействие на iPhone и Apple SDK-компиляция этим не подтверждаются.

Приёмка в новой IPA: тот же MP3 с текстом через оба редактора; файл без подписи; документ с/без миниатюры; входящие/исходящие, ответ/пересылка с заголовком, широкие посты ON/OFF, выделение и контекстное меню, разные шрифты/размеры, загрузка→воспроизведение и повторное открытие. Ожидание: верхний отступ как у обычного файла, единый пузырёк, нет обрезки/лишнего зазора/скачка размеров; текст и медиа нажимаются и выделяются по видимым координатам. Ранее опубликованные IPA не заменяются; новая сборка — по прямой команде.

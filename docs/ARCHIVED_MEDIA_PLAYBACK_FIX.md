# Правка воспроизведения локального архива для 0.4.8

Состояние: код подготовлен, compile_pending/device_pending. Сборка, публикация и смена версии не запускались. Опубликованный IPA №77 этих изменений не содержит. Предыдущая подготовленная правка жестов списка чатов сохранена.

## Подтверждённая причина

Архивное сообщение отсутствует в Postbox, поэтому OpenChatMessage получает его snapshot с standalone=true и запускает штатный PeerMessagesMediaPlaylist через .recentActions(message). Однако peerMessagesMediaPlaylistAndItemId в AccountContext возвращал .peer(peerId) для строки обычного чата. filteredPlaylistState и filteredPlayerAudioLevelEvents искали другой playlist ID. Звук мог воспроизводиться, а Play/Pause, waveform и статус встроенного кружка оставались несогласованными с плеером.

Для NagramiXArchivedMessageAttribute общий helper теперь возвращает .recentActions(peerId) и штатный item ID с прежними message ID/index. FileMediaResourceStatus использует этот helper для статуса и аудиоуровней голосовых и кружков. Остальные ветки helper не изменены. Новый плеер или дополнительная видеосессия не создаются; встроенный UniversalVideoNode и SharedMediaPlayer остаются штатными. Причину всех визуальных симптомов со скриншотов нельзя подтвердить без запуска на устройстве.

## Изменения

- ios/apply_features.py: apply_archived_media_playback содержит восемь точных патчей для AccountContext/MediaManager.swift, ChatMessageInteractiveFileNode.swift и ChatMessageBubbleItemNode.swift. Только у архивного голосового UITapGestureRecognizer через штатный wrappedGestureRecognizerDelegate принимает тап внутри существующего Play/Pause/download control. Вне него тап проходит родительскому bubble и открывает стандартное контекстное меню. Сохраняются штатные hit tests даты, транскрипции, links, выбор сообщений и длинное нажатие; scrubbing/pause/seek используют прежние компоненты. Поведение обычных голосовых и остальных файлов не меняется.
- В существующем footer минимальная высота уменьшена с 22 до 16 пунктов, запас над измеренным текстом — с 8 до 2. Шрифт, вторичный цвет темы, иконка, пользовательский текст и многострочное измерение прежние.
- Прозрачность архивного содержимого остаётся 0.5. clippingNode получает allowsGroupOpacity=true: thumbnail/video/control stack компонуется до применения прозрачности, вместо отдельного просвечивания каждого слоя. При reuse обычной строки исходное значение возвращается. Нужна физическая проверка исчезновения двойного изображения и переходов встроенного видео.
- ios/Sources/TelegramCore/NagramiXMessageArchive.swift: локальный snapshot классифицирует сохранённые медиа через реальный tagsForStoreMessage Telegram, включая voiceOrInstantVideo. TTL оригинала не переносится в локальную копию. Схема JSON, файлы архива, ключи, defaults и условия сохранения не менялись.

## Временные сообщения

Пользователь подтвердил: при ON «Удалённых сообщений» и «Временных сообщений» полученное одноразовое вложение должно оставаться после просмотра или удаления, повторно открываться штатным плеером и храниться до очистки архива. Существующие capture-before-consume/expiry, отдельные полные файлы и замена expired placeholder сохранены. Архивная копия без TTL использует исправленный snapshot playlist, который не требует удалённого оригинала и не запускает повторное consumption. Это относится только к успевшим сохраниться полным байтам; недоступный файл восстановить нельзя. Явное локальное удаление копии также удаляет её данные.

## Пересылка с автором — ожидает уточнения

Штатная EnqueueMessage.forward приводит к messages.forwardMessages с исходным серверным message ID. После удаления оригинала сервер не может переслать его по этому ID. EnqueueMessage.message отправляет локальный текст/файл заново и не создаёт серверную плашку «Переслано от». Подделывать forwardInfo в локальном UI нельзя: получатель его не получит.

Задан вопрос, подходит ли отправка сохранённой копии с явной текстовой подписью исходного автора. Ответ пока не получен, этот вариант не реализован. Существующая «Переслать без» сохранена; неработающая кнопка серверной пересылки не добавлялась. Не считать всю задачу завершённой до согласования и реализации этого пункта.

## План физической проверки

1. Получить обычные голосовое и кружок, сохранить полные файлы, удалить оригиналы с другого клиента. У архивного голосового Play → Pause, waveform/progress, пауза/продолжение и seek должны совпадать с верхним плеером. Тап вне Play открывает меню; транскрипция, дата, выбор и long press доступны.
2. Кружок запускается с первого действия, расширяется/возвращается штатно, не зависает и не показывает два видео. Переключить обычный → архивный → другой архивный кружок, прокрутить за экран и назад, открыть/закрыть меню. Только одна активная сессия, прозрачность 50%, метка сохранена.
3. Повторить сценарии со скриншотов: 8/17-секундные голосовые, 7/22-секундные кружки, затем 5/6-секундные кружки. Уменьшенный footer не перекрывает длительность/время, включая длинную пользовательскую метку и увеличенный текст.
4. Оба checkbox ON: получить одноразовые фото, видео, голосовое, кружок; просмотреть оригинал/дождаться удаления, затем повторно открыть сохранённую копию. Очистить штатный кэш, перезапустить, включить авиарежим и повторить. Явная очистка архива удаляет копии; поздние загрузки не возвращают их.
5. Проверить четыре сочетания checkbox, OFF после сохранения, нормальные сообщения при reuse, все стандартные/custom темы, папки и предыдущую правку аватарки без автоматической отметки прочтения. Не запускать сборку до отдельной команды.

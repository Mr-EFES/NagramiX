# Подготовка восьми исправлений к 0.9.0

Владелец разрешил восстановить семь предыдущих доработок, объединить их с восьмой правкой PiP, проверить и сохранить в main. SDK, Actions, IPA и публикация релиза прямо запрещены до отдельной команды. Далее планируется девятая правка. Метаданные исходников подготовлены под 0.9.0; опубликованный 0.8.9/build185, его тег и файлы не меняются.

Прежние неопубликованные файлы не обнаружены в доступной среде или main. Причина их отсутствия не установлена. Семь исправлений восстановлены по согласованным требованиям; побайтный возврат исчезнувших снимков не заявляется. Точный Core wide model восстановлен по прежнему SHA, PiP REV7 сохранён целиком.

## Состав и порядок

| № | Стадия | Поведение |
|---|---|---|
| 1 | `wide_bottom_bar` | Широкая нижняя панель двух вкладок; штатные раскладки дополнительных вкладок и поиска сохраняются. |
| 2 | `author_selection_no_restore` | «По автору» читает существующие локальные сообщения и выделяет их, без сетевого восстановления удалённых. |
| 3 | `preview_reply_intent` | Ответ из предосмотра открывает обычный чат с целевым сообщением для ответа; поздняя загрузка черновика не стирает выбор. |
| 4 | `cloud_credential_entry` | После свежей установки ключ не подхватывается из старого Keychain. Введённый ключ запускает актуальное получение моделей; устаревшие ответы не меняют новый ввод. |
| 5 | `extended_poll_integrity` | Вложения и новые поля опросов сохраняются при копировании, предпросмотре и архивировании; локальные ресурсы подготавливаются атомарно, ссылка не попадает в очередь загрузки двоичных файлов. |
| 6 | `bot_delete_without_block` | Для бота доступны удаление с блокировкой, простое удаление и очистка истории. |
| 7 | `wide_tab_bar_setting` | Чекбокс широкой панели включён на свежем запуске, сохранённый OFF учитывается; обновление применяется сразу. Перевод добавлен во все 71 языка. |
| 8 | `pip_swipe_handoff` | Короткий намеренный свайп запускает тот же системный PiP, что кнопка; источник фиксируется и остаётся видимым до подтверждения запуска. Штатные углы сохраняются. |

Порядок закреплён в `scripts/late_source_stages.py` и manual-only workflow. Каждая стадия проверяется непосредственно после применения, до следующей стадии. Старые canonical snapshots, точные SHA, границы Postbox и исторические source checks сохранены. Перед выполнением прежних runtime проверок обратный проход проверяет все восемь стадий и возвращает их точные предыдущие байты во временной проекции; настоящее итоговое дерево не меняется.

## Проверка исходников

Полная опубликованная база построена настоящим `apply_overlay.py` из закреплённой Telegram 13.2 `24638bc69bd083981b178dd1e7f921eebbf7fc46` и исторического входа 13.0, затем применены оба post и шесть прежних исправлений SDK-совместимости. После этого восемь новых loaders применяются к полным checkpoint, а не к нескольким файлам-пробам. Перед каждой записью в checkpoint общий файл отсоединён от hard link; предыдущие деревья не изменяются.

Локальные проверки каждой функции исполняют production-код в debug и с оптимизацией, проверяют отрицательные варианты и отказ на неверных входах до записи. Общие gates сверяют реальные объявления custom members на полном исходнике, происхождение native входов, полную цепочку SHA, Swift parse и PostboxImportCheck. Итоговая локализация содержит 71 каталог по 630 ключей; прежние 629 значений сохраняются. Для будущего IPA отдельно проверяются старый контракт 0.8.9 и новый контракт 0.9.0.

Фактические checkpoint и отчёты находятся в `/workspace/scratch/recovery-090`; актуальную карту путей содержит `checkpoints.json`. Финальные стадии 5–8 имеют суффикс `v3`; старые V1/V2 checkpoint не заменяют текущий набор. Сводный receipt `task-state.json` записан после завершения проверок и до push. Краткое доказательство и точные SHA изменённых исходников: [PREPARATION_090_CHECKS](PREPARATION_090_CHECKS.json).

## Результат source gate

- Все восемь loaders применены к полным checkpoint. В итоговом дереве 37 641 обычный файл: 94 ожидаемых изменения, 37 547 остальных сохранены; опубликованный baseline не изменён.
- Проверки каждой из восьми функций в debug/-O, семантические отрицательные варианты, fail-closed и parse — пройдены. Для PiP финальная интеграция и 17 guard cases повторены после последнего исправления опросов; результаты 68 проверок на режим и 14 отрицательных исполнений сохранены по доказанно идентичным четырём production-файлам и девяти зависимостям.
- Общая цепочка: 436 Swift parse, 47 migration fail-closed, 14 исторических runtime исполнений и native PostboxImportCheck — пройдены. Обратный проход совпал с настоящим опубликованным baseline по 648 действующим контрактным путям; 11 повреждённых входов отвергнуты без изменения дерева.
- Проверка реальных custom members на 7 320 Swift-файлах, native blob origins и две проверки прежних ошибок происхождения — пройдены.
- Строгая локализация: 113 файлов, 611 обращений, 71 язык по 630 ключей, 44 899 runtime проверок в каждом debug/-O. Новых непереведённых UI-литералов нет.
- 16 проверок старого и нового IPA-контракта, 28 owner-publication tests, release metadata/build-mode, YAML/manual-only trigger, Bash syntax и diff checks — пройдены.

Статус: `source_checked / native_compile_pending / device_pending`. Apple SDK и реальные UIKit/AVKit, Keychain, сеть и анимации на iPhone этим не подтверждаются. Все compile статусы новой версии — pending. После следующей задачи запуск IPA потребует отдельной личной команды владельца.

# Личный ключ интернет-провайдера и актуальные модели

Восстановление четвёртой согласованной правки после 0.8.9. Новая поздняя стадия `cloud_credential_entry` применяется после `preview_reply_intent` к четырём файлам: двум экранам настроек и двум хранилищам ключей расшифровки и перевода. Двенадцать точных зависимостей проверяются до первой записи. Исторические snapshots не меняются.

## Причины неправильного первого открытия

Оба экрана автоматически читали собственный сервис Keychain. Эти записи могут пережить удаление приложения, тогда как настройки приложения отсутствуют. Наличие оставшегося Keychain-item само по себе не доказывает, что пользователь ввёл этот ключ в новой установке. Поля были защищены `isSecureTextEntry`, но не задавали явные API-key input traits. Каталог обновлялся при открытии страницы и нажатии на модель; обработчиков изменения и завершения ввода не было.

## Поведение

- Новая установка начинает с пустого поля и прежней локализованной подсказки ввода ключа. Оставшийся от предыдущей установки Keychain-item не подставляется и не используется для расшифровки или перевода.
- Успешное явное сохранение ключа фиксирует только Boolean-признак пользовательского ввода отдельно для провайдера и способа. Сам ключ остаётся в прежнем отдельном Keychain-сервисе, без iCloud-синхронизации и с прежним `ThisDeviceOnly` accessibility.
- Сохранённый пользовательский ключ при обновлении приложения сохраняется. Для миграции старой записи необходима прежняя конфигурация с сохранённой моделью именно этого провайдера; для расшифровки дополнительно требуется сохранённая credential revision. Обычный выбор нового провайдера такого доказательства не создаёт. После первого решения ложный признак не превращается в разрешение из-за последующих изменений других настроек.
- Успешная очистка снимает признак владения. Ошибка записи или удаления Keychain не сообщает об успехе и не изменяет признак. Сохраняются прежние уведомления revision, отмена незавершённых операций и разделение ключей перевода и расшифровки.
- Поле использует прежний скрытый ввод, отключённые autocorrection/capitalization и явные ASCII/text-content traits. Ключ не становится паролем сторонней учётной записи.
- Изменение ключа или Cloudflare Account ID сразу отменяет применение прежнего результата каталога: сбрасываются generation, identity, models, loading и отложенный показ picker.
- Завершение ввода загружает список моделей для текущего ключа. Запрос на каждый введённый символ не выполняется. Нажатие на модель во время запроса использует тот же запрос; результат показывается после его завершения. Пустой ключ не отправляет запрос; при выборе модели появляется существующая локализованная просьба ввести ключ.
- Провайдеры, сетевые адреса, фильтры совместимых моделей, сохранённые model IDs, выбор температуры, языки и согласие на передачу аудио не подменяются. Ключ перевода автоматически не переносится в расшифровку.

Boolean-признак находится в UserDefaults; значение ключа туда не записывается. Он отделён для `translation` и `transcription`, а также каждого provider ID. Миграция не удаляет невостребованные старые Keychain-items. После новой установки пользователь вводит нужный ключ явно.

## Проверки

```bash
python3 scripts/validate_cloud_credential_entry.py \
  --source <точный-полный-checkpoint-после-стадии> \
  --swiftc <swiftc> \
  --report <отчёт.json>
```

Пройдены 250 production checks в каждом debug/-O, восемь компилируемых отрицательных семантических вариантов и 37 fail-closed проверок. Проверены все четыре текущих облачных провайдера расшифровки и три провайдера перевода с API-ключом, первый запуск, сохранение, неуспешная запись, удаление, upgrade, повторное открытие, simulated reinstall, отдельные сервисы и отсутствие секретов в UserDefaults. Каталог проверен на пустом вводе, текущем ключе, объединении запросов, изменении ключа, устаревшем callback и новом выборе модели. Parse четырёх полных Swift-файлов пройден.

Исполняются реальные тела Settings, Credentials и обработчиков каталога. Defaults, Security.framework, HTTP и UIKit/picker/layout — явные ограниченные границы теста. Реальные ключи не читаются, сеть и платные сервисы не вызываются. Эти проверки не заменяют Apple SDK, настоящую Keychain-проверку и физическую приёмку на iPhone.

Новых видимых строк нет; используются существующие общие локализованные подсказки и ошибки. Обязательную проверку всех 71 языков выполняет общий gate итоговой композиции. Сборка IPA, Actions, commit/push и публикация не выполнялись этой отдельной задачей.

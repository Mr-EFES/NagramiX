Актуальный результат: эта правка вошла в0.7.5/build134/sourcefe620c5f7c2463882455d1609622779db8b3239c. SDK и публичный IPA проверены; физическая приёмка ожидается. Ниже описан также предшествующий этап source-проверок. Подробности — [RELEASE_STATUS](RELEASE_STATUS.md).

Пользователь прислал запись ожидаемого перехода и скриншоты сборки132: уменьшенное видео остаётся на чёрном fullscreen вместе с большими кнопками; бывает отказ запуска PiP. Запись просмотрена через последовательность кадров, источник сохранён только во временной проверочной папке. Скриншоты не содержат системного кода отказа, поэтому причина каждого отказа AVKit по ним не устанавливается.

## Поведение

Вертикальный свайп и кнопка запускают один существующий системный путь. Жест больше не уменьшает/перемещает слой, не скрывает фон и не создаёт локальную миниатюру перед AVKit. До подтверждения запуска изображение сохраняет полноразмерную геометрию, прежние controls и воспроизведение. Короткий/отменённый жест оставляет просмотр без изменений. Горизонтальное перелистывание принадлежит галерее; окно PiP размещает iOS.

На willStart остаётся прежнее согласованное затухание галереи и скрытие controls. После didStart галерея закрывается однократно, без ожидания завершения отдельной локальной fade-анимации. Этот callback мог быть прерван, поэтому он больше не является условием закрытия после подтверждённого системного старта. Успех не объявляется по одному swipe/button request.

При неуспехе completion восстанавливает UI сразу, даже если lifecycle ещё ждёт didStop/истечение срока освобождения AVKit. Общий rollback для кнопки и свайпа очищает transform отдельной PiP-поверхности, сбрасывает состояние жеста и возвращает прежнюю видимость controls. Перед новым запросом source pose также нормализуется. Zoom обычного видео и состояние Play/паузы/позиция не подменяются. Restore инвалидирует старые fade callbacks и сохраняет возврат к тому же существующему видео.

Регистрация AVKit по-прежнему только в явной preparing. Не меняются eligibility/secret/ad/unsupported gates, readiness слоя/окна/владельца, запрет записи аудио, managed audio/decoder leases, Now Playing, восстановление failed/requiresFlush слоя и полноэкранный layout поворотов. Отдельного AVPlayer/декодера/плавающего окна нет. Фоновый режим и блокировка сохраняют прежний native lifecycle. Реальные ограничения iOS не скрываются удалением ошибки: если PiP не запустился, остаётся полноценный обычный просмотр.

В журнал отказа добавлен последний этап readiness: offscreen/content_owner/source_layer/recording/avkit_unavailable/audio_session/ready. Лог не содержит peer ID, имён или содержимого видео; штатный NSError domain/code уже записывается. Это нужно для диагностики реального отказа, который невозможно отличить по одному alert на скриншоте.

## Интеграция и проверки

Последний guarded stage pip_native_transaction после story_icon_consistency: три Swift-файла,14 точных замен, один template guard и четыре guards (GalleryUI BUILD, GalleryControllerNode, lifecycle и MediaPlayer). Ранние stages, API и hashes не переписываются. validate_system_pip_restore учитывает новый финальный SHA; validate_pip_presentation распознаёт только точные итоговые SHA и направляет проверку жеста на актуальный код. Прежние тесты геометрии остаются историческими и не выдаются за путь нового жеста.

`scripts/validate_pip_native_transaction.py --source <native> --swiftc <compiler>` исполняет production gesture с UIKit boundaries, реальные start wrapper/lifecycle/visual. В debug и optimized проходят587проверок жеста и588прежних проверок lifecycle, плюс startup/timeout/ошибка/duplicate/Expand сценарии. Проверяется полноразмерный source в обеих ориентациях и при разных пропорциях/направлениях, отсутствие prepare/controls/fade до подтверждения, отмены, немедленный отказ, синхронный ответ, устаревший callback и горизонтальное перелистывание.

Отрицательные проверки запускают прежние реальные тела: старый fade gate не закрывает галерею без animation completion; прежний start wrapper не выполняет rollback перед сообщением об ошибке по timeout. Оба отклоняются теми же сценариями. Это воспроизведение двух дефектов управления, а не запись физического AVKit или диагноз всех ошибок со скриншотов.

Полная чистая overlay-цепочка с прежними source validators и Swift parse проходит. Proof `/workspace/.codex-validation-nagramix-pip-native-transaction/` содержит reference frames, native tree, behavior.log и full.log. UIKit/AVKit представлены границами; новая композиция native_compile_pending/device_pending. Новую SDK/IPA, Actions, commit/push этой задачей не запускали. Изменений нет в исходнике90d1cd0 уже собранного132.

## Физическая приёмка

Проверить кнопку и вертикальный свайп на Native/HLS-видео в обеих ориентациях: полноэкранный исходник остаётся до системного перехода, после него виден чат с одним системным окном; нет миниатюры на чёрном fullscreen. Короткий/отменённый жест, недоступный PiP и быстрый повтор возвращают полноценное видео. Повторить многократные portrait↔landscape, PiP→блокировка→пауза/Play→разблокировка→Expand, Close и другой ролик. Сохраняются пауза, позиция, скорость, звук и обычное фоновое воспроизведение. При отказе нужны NSError/readiness logs и версия/build.

# Чтение по действию: границы тем и комментариев

20 октября исправлен пункт3 [проверки стабильности](STABILITY_REVIEW_2026-10-20.md). В `main` изменены исходники без SDK, Actions и IPA. Статус: **source_checked / native_compile_pending / device_pending**.

Раньше действие в теме отправляло общий `channels.readHistory`, затем `messages.readDiscussion`. Оно также вызывало peer-wide локальное прочтение, а ответ брал верхнее сообщение всего чата. Так можно было затронуть другие темы. Теперь контекст разделяется до локальной записи и RPC:

- Обычный диалог/канал сохраняет прежние `messages.readHistory`/`channels.readHistory`, включая обработку pts.
- Тема/комментарии получают только `messages.readDiscussion` с точными root/maxId; monoforum использует штатный `messages.readSavedHistory`. Недоступный sub-peer и root вне Int32 не разрешают общий запрос или подмену root через clamping.
- Реакция читает текущую тему до выбранного сообщения. Ответ сохраняет верхнюю границу своей темы до enqueue; новые входящие после этого не расширяют разрешение. Для «Общее» без явного threadId применяется native topic1, для forum reply учитывается тема сообщения, на которое отвечают. Неизвестная тема не подменяется верхним сообщением всего чата.
- Каждая позиция enqueue получает отдельную границу. Отложенная или не поставленная на отправку позиция не разрешает прочтение; одинаковые границы не дублируются. Native отправка, платежи и планирование остаются прежними.
- Локальное изменение счётчиков темы использует извлечённое без изменения тело штатного topic accounting. Частные действия не вызывают peer-wide read и не очищают другие темы. Автоматический peer read support-аккаунта также подавляется при локальном чтении/чтении по действию; обычный support-путь сохранён.

В Postbox добавлен отдельный ключ `peer+thread` для private watermark. Прежний16-байтный peer-key, magic и формат `{maxId}` сохранены; новые темы используют24-байтный ключ с другим magic. Старый общий маркер нельзя достоверно разделить по темам, поэтому он сохраняется и не удаляется подтверждением одной темы. Account isolation остаётся свойством Postbox. Успешный action или обычный visible-thread RPC удаляет только покрытый маркер своей темы; false/error и более поздний private watermark остаются защищёнными. Все настройки, defaults, UI и ограничения аватарного просмотра прежние.

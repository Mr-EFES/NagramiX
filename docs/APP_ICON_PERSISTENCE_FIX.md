# Подтверждение и сохранение иконки приложения

Актуальный результат: включено в опубликованный Release0.7.1/build127, source32f6b5a; чистая Apple SDK-сборка и проверка IPA пройдены, физическая приёмка ожидается. [Итог выпуска](RELEASE_STATUS.md). Описанные ниже pending/запреты запуска относятся к этапу подготовки.

24 октября пользователь сообщил, что на его iPhone смена иконки работает, а у друзей выбор возвращается к основной. Исправлены подтверждённые проблемы обработки результата и отсутствия восстановления сохранённого выбора. Статус: **source_checked / native_compile_pending / device_pending**. В опубликованном 0.7.0/build123 этой правки нет. Сборка и публикация не запускались.

## Что установлено

В исходной ThemeSettingsController выбранный вариант отмечался **до** ответа UIApplication, а результат `(Bool)` полностью игнорировался. При отказе система оставляла прежнюю иконку, хотя меню показывало новую; повторное открытие меню читало реальное значение iOS и возвращало отметку. Отдельного последнего подтверждённого выбора и восстановления после сброса системой не было.

Проверен именно опубликованный IPA123: семь дополнительных системных объявлений, home-screen PNG120/180 и разные изображения присутствуют; имя основной иконки корректно. В приложении нет другого вызова, который принудительно сбрасывал бы выбранную иконку. Пользователь уточнил iPhone15ProMax/iOS18.2, установка «через джейлбрейк»; меняется лишь отметка в настройках, системного подтверждения и изменения рабочего стола нет. Инструмент установки ещё неизвестен. Отсутствие файлов не подтверждено, конкретный отказ на этом устройстве не воспроизведён; не приписывать проблему SideStore, определённой версии iOS или SpringBoard-кешу без доказательств.

## Новое поведение

- Все восемь прежних вариантов и имена NagramiX1…8 сохранены. Основной соответствует native `nil`, дополнительные — NagramiX2…8. Графика, размеры иконок и способ упаковки не менялись.
- Один NagramiXAppIconController в основном AppDelegate сериализует UIKit-вызовы и завершение на главной очереди. Проверяются активность приложения, `supportsAlternateIcons` и наличие выбранного имени в реальных CFBundleAlternateIcons. Неподдерживаемое/неизвестное/удалённое подписывающим инструментом имя не становится успешным выбором.
- Новая локальная preference `nagramix.appearance.appIcon` хранит только **подтверждённый** выбор. Запись происходит при `error == nil` и совпадении `UIApplication.alternateIconName` с запросом. При ошибке старый сохранённый выбор остаётся. Это настройка приложения, а не аккаунта: иконка одна на установку.
- Меню ждёт завершения, затем отмечает фактическую системную иконку. Повторные нажатия до результата не запускают конкурирующие операции. Отказ показывает локализованную RU/EN ошибку вместо ложного успеха. Исходный Premium gate сохранён; восемь NagramiX-иконок, как прежде, бесплатные.
- При первом активном состоянии процесса сохранённый вариант восстанавливается, только если фактическая иконка отличается. Не более одной автоматической попытки на процесс; системное подтверждение/foreground-события не образуют цикл. Ручной выбор отменяет автоматическую попытку старого выбора в этом процессе. Неудачное восстановление оставляет preference для следующего запуска.
- На обновлении без нового ключа существующая допустимая системная иконка принимается как исходный выбор, без сброса. Чистая установка не навязывает смену основной иконки и не вызывает системный диалог. Неизвестная preference не сбрасывает текущий значок.

Используются только публичные UIKit API. Нельзя гарантировать изменение изображения на рабочем столе, если переподписанный пакет потерял metadata или iOS отклоняет вызов/не обновляет свой кеш. Контроллер проверяет состояние UIApplication, не читает изображение из SpringBoard и не подменяет реальные системные ошибки.

## Интеграция

Финальный `app_icons` после `protected_stories`: 5 входных/выходных SHA256, 9 точных операций, 2 неизменённых BUILD guards, 1 проверенный helper-copy в TelegramUI. Все проверки завершаются до записи. Изменены AppDelegate, ThemeSettingsController, расширение PresentationStrings и две локализации NagramiXCore. TelegramUI уже собирает Sources/**/*.swift; SettingsUI уже зависит от NagramiXCore. Новых модулей, зависимостей, entitlement, схем или private API нет. Ранние canonical .inc/JSON и строгий порт13.1.1 не изменены.

`scripts/validate_unsigned_ipa.py` теперь проверяет реальные системные объявления, ссылки на имена, оба home-screen масштаба каждого варианта, PNG-размеры, различия изображений и согласованность iPad-раздела при наличии. Проверка запускается для будущих IPA до публикации, дополнительных действий с выпущенными файлами не выполняет.

## Проверки

Proof: `/workspace/.codex-validation-nagramix-app-icons/verification.json`; full native tree `full-overlay`, clean replay log `overlay.log` в той же папке.

- 74 проверки actual Foundation controller и извлечённого native picker action в debug и optimized: все варианты, отсутствие оптимистической записи, отказ/несовпадение состояния, retry, дубли callback, main-queue boundary, конкурентный запрос, upgrade, восстановление, ограничение попыток и меню/ошибка.
- По17 отдельных cold процессов на режим, всего34: fresh и запись/чтение каждого из8 вариантов. Linux corelibs UserDefaults flush вызывается только на границе завершения тестового процесса; в production synchronize не добавлялся.
- 32 повреждённых inputs/anchors/outputs/paths/helper cases отклонены без частичных записей.
- Опубликованный IPA123 проходит новые проверки ресурсов;26 намеренно повреждённых комплектов отклоняются. Это проверка прежнего пакета, не доказательство наличия новой runtime-правки в нём.
- Полный clean Telegram13.1.1→строгий порт→все поздние stages→branding прошёл с фиктивными API credentials. Ровно5 файлов изменены,1 добавлен,34478 остальных файлов побайтно прежние. Все предыдущие WIP сохранены. Swift parse4 полных выходных файлов и Python AST прошли.

UIKit, настоящий SpringBoard, подпись и главный экран физических iPhone здесь не исполнялись. Apple SDK-компиляция также ожидает отдельной команды на сборку. Перед утверждением физического результата нужны два устройства: все8 вариантов, возврат основной, повторное открытие настроек/закрытие/перезапуск, обновление поверх установки, повторная подпись, быстрые нажатия, светлый/тёмный/тонированный главный экран; отдельно воспроизвести окружение друзей и сохранить реальную ошибку AppIcon из журнала при отказе.

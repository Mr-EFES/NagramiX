## Накопленные изменения следующей сборки

- RU default и полный официальный ресурс с покрытиями pin доступны без сети. Ручная localizationSettings сохраняется, автоматические предложения другого языка подавлены. Системная клавиатура управляется iOS.
- Системный default тем: штатные dayClassic/night, trigger.system, force.false. Начальное представление учитывает UIScreen trait; затем штатный WindowUserInterfaceStyle. Tinted принудительно не задаётся, сохранённые темы/расписание/ручные режимы не перезаписываются. На обновлении нельзя надёжно отличить старую сохранённую Tinted от ручного выбора.
- Поиск: убран повторный horizontal inset 16 pt, края совпадают с list insets. Поле 48 pt/radius 24, item 71 pt (12 сверху/11 снизу плюс native header 7). Search получает sectionId первого результата/раздела, убирая межсекционный gap 28 pt; категории/handlers сохранены.
- Архивное сообщение: fallback «Это сообщение было удалено», отдельная theme-tinted корзинка ASImageNode; custom label/ключ сохранены. ContextExtractedContentSource наблюдает локальный архив, вместо отсутствующего оригинала Postbox. Добавлены копирование текста, ответ цитатой с сохранением черновика, редактор локальной копии, copy-as-new, выбор, автор, локальное удаление. Редактор обновляет stableVersion, хранит предыдущий текст и медиа, удаляет несовместимые offsets entities после текстового изменения.
- Архивный copy handler принимает snapshot напрямую; выбранные ID получают fallback из архива. Если в наборе есть архивная копия, весь набор отправляется без автора. Медиа используют standalone reference и требуют доступного ресурса; повторная загрузка после серверного удаления не гарантируется. Выбор автора объединяет серверную пагинацию с архивными ID в том же чате/теме. См. [deleted-messages.md](../product/features/deleted-messages.md).
- Архив не восстанавливает серверное закрепление, редактирование, реакции/жалобы и пересылку с исходной атрибуцией; локальное закрепление/внешний share и отдельное локальное удаление смешанного выбора не реализованы. Не обещать полный набор серверных действий с удалённым оригиналом.
- Сохранены иконки шестерёнки/лампочки, UI настройки видимости «Переслать без»/«Выделить от автора» с default true.

## Текущая правка прокси

Пользователь на устройстве сообщил: ручной выбор рабочего резерва соединяет аккаунт, автоматика не отрабатывает. Найдено, что updating отображался в UI как «Соединение», но отменял таймер. Также тап строки сохранял выключенную автоматику, когда прокси уже были включены.

Исправлен `ios/Sources/TelegramCore/NagramiXProxyFailoverController.swift`: единое окно 15/30/60 для connecting/updating без перезапуска; online старого proxyAddress не отменяет срок нового выбора. MTProto сообщает proxySettings.ip; одинаковый host на разных портах статусом не различается. На дедлайне активный пинг сбрасывается; выбирается следующий по циклическому порядку свежий успешный резерв (maxAge 180). Если резерва нет, ожидание общего checker, без подключения к непроверенным адресам. Удалены дополнительные последовательные probes и восстановление непроверенного исходного прокси. Новый резерв получает собственный срок до online. Generation/transaction guards защищают ручные действия; waitingForNetwork отменяет автоматику, не меняя выбор. Логи дедлайна/смены не содержат адресов/credentials.

`ProxyServersStatuses.swift.inc`: максимум два native probe по 12 секунд на checker аккаунта, 120 секунд между проходами при online, 30 при восстановлении. refreshIfNeeded не отменяет текущий проход и ограничивает начало 30 секундами. Выключение прокси/нет сети/уведомление UIKit о фоне прекращают periodic checks; ручная кнопка работает и при выключенном использовании. Возврат из фона обновляет список. RTT проверяется на finite/неотрицательность/верхнюю границу перед отображением. Несколько аккаунтов имеют собственные checker; суммарную нагрузку отдельно измерить на iPhone. iOS suspend не позволяет обещать секундные таймеры в фоне.

`ios/apply_features.py`: публичный refreshIfNeeded/maxAge 180, тап любой строки включает использование и автоматику; её можно затем выключить вручную. «Проверить все» использует общий список с UI/контроллером. DNS-код не менялся.

## DNS и известные проверки

DoH GET A/AAAA с резервным POST; timeouts 8/12 и штатный fallback. Callback/отмена сериализованы, nil-блок не вызывается, границы DNS-парсера проверяются. Из Cloud Google/AdGuard ответили GET/POST, Mullvad/Cloudflare — GET, Quad9 — HTTP 503 шлюза с connection timeout. Это не проверка DNS из сети iPhone; прежний crash/ANR stack trace отсутствует.

Текущая правка прошла полное применение overlay к pin и синтаксический разбор Swift. Сравнение с предыдущим overlay показывает изменения только трёх proxy-файлов: контроллер, общий checker и ProxyListSettingsController. Остальные generated файлы совпадают побайтно, включая предыдущие правки меню/поиска/темы и защищённые пути. Проверяются Python syntax, локализации, согласованность метаданных и whitespace. Это не typecheck/нативная компиляция и не измерение батареи. Для текущей версии все compile-статусы — compile_pending, device — device_pending.

## Следующий шаг

Продолжить задачи пользователя без запуска сборки. По отдельной команде собрать новый IPA/релиз с актуального SHA, затем пройти [IPHONE_TEST_0.4.1.md](IPHONE_TEST_0.4.1.md) на **iPhone 17 Pro Max через SideStore**; версия iOS ещё неизвестна. Проверить 4 прокси (3 недоступных/1 рабочий), все таймеры и переходы статуса, stale online, ручной выбор/выключение у дедлайна, отсутствие резерва и его восстановление, фон/возврат, RTT, несколько аккаунтов, фактическую задержку и батарею. До этих результатов не утверждать, что автоматическое переключение точно работает на устройстве.

Успех выбранного прокси — online с его host и успешный результат checker. Если актуальная проверка даёт notAvailable, прежний online не удерживает автоматику. Выбранный сервер проверяется первым (максимум 12 секунд на probe, меньше минимального таймера 15), в том числе после ручной смены; повторные статусы без смены сервера этот проход не перезапускают.

Уход в фон отменяет также таймер failover, на возврате начинается новое окно. Ручной тап строки публикует отдельный сигнал отмены, включая выбор уже активного сервера. Захваченный Atomic-флаг отмены проверяется внутри транзакции переключения, чтобы callback прежнего поколения не отменял ручной выбор или действие после паузы.

## Повторная правка первого кружка после разрешений

Пользователь сообщил, что первая запись после разрешений всё ещё не отменяется. В native legacy-кнопке найден cancelTrackingWithEvent → отложенный _commitLocked вместо callback отмены. В `ios/apply_features.py` добавлен opt-in cancelOnTrackingInterruption (default false), включаемый только режимом video: прерванное незаблокированное касание отменяет запись без отложенной блокировки. Намеренный свайп вверх сохранён. Pending видео инвалидируется также при обычном отпускании до появления mediaRecordingState. После системного prompt требуется новое удержание, чтобы не запускать запись без живого жеста.

Полное применение к pin прошло. С предыдущим overlay отличаются только четыре файла записи (.h/.m legacy-кнопки и два Swift input-компонента), их синтаксис проверен tree-sitter; остальные файлы совпадают побайтно. Python/метаданные/локализация/diff проверены. Нативная компиляция и iPhone-проверка отсутствуют, сборка не запускалась. Следующий шаг — задачи пользователя, затем отдельно сборка и проверка permission/cold-start сценариев по [round-video-camera.md](../product/features/round-video-camera.md). Не считать найденный путь единственной runtime-причиной без результатов устройства.

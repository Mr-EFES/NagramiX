# Передача контекста NagramiX

## Текущая база

- Дата: 2026-09-25 (UTC).
- Актуальная версия продукта: **0.3.8**.
- Статус: **кандидат в стабильную базовую версию для device-регресса**.
- Платформа: только iPhone/iOS.

## Состояние репозитория и GitHub

Исторической базой 0.3.8 остаётся очищенная линия 0.3.7 из `https://github.com/Mr-EFES/NagramiX`. В активном дереве файл релиза 0.3.7 заменён на 0.3.8; workflow сборки и публикации переведены на новый номер.

В GitHub Actions сохранены только три необходимые workflow: аудит upstream pin, сборка неподписанного IPA и публикация релиза. Ветка `work` отправлена в GitHub, открыт PR #15. Первый build run `36140188656` подтвердил наличие `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` и дошёл до нативной Swift-компиляции, но обнаружил несовместимый тип placeholder в новом SearchBar. `NagramiXSettingsSearchHeader` исправлен: `SearchBarNode.placeholderString` теперь получает штатный theme-aware `NSAttributedString`, а не `String`. Повторный workflow должен создать артефакт `NagramiX-0.3.8-unsigned-arm64`.

Для текущего checkout восстановлен remote `origin` на `https://github.com/Mr-EFES/NagramiX.git`. GitHub CLI авторизован как `Mr-EFES` с правами `repo` и `workflow`; push, создание PR и запуск Actions фактически проверены. В `docs/BOOTSTRAP.md` также описан безопасный неинтерактивный вариант через защищённую переменную `GH_TOKEN`. Секреты и токены в репозиторий не записывались.

Исправлена первопричина дефекта «Широких постов в каналах»: подготовительный проход `ChatMessageBubbleItemNode` сужал общий `maximumNodeWidth` до intrinsic-width самого узкого content node (в частности фото), после чего caption, headers и footer финализировались с этим узким ограничением, хотя внешний пузырь отдельно растягивался. Для broadcast-поста при включённой существующей настройке теперь сохраняется единая адаптивная `maximumContentWidth` до общего финального layout. Дополнительно каждый финализированный линейный content node получает frame этой ширины: отдельный node больше не может вернуть узкий intrinsic frame и оставить пустую правую полосу внутри широкого background. Штатный media layout по-прежнему отвечает за aspect fit/fill и высоту изображения. Видимые сообщения перепривязываются по уведомлению об изменении настроек, поэтому ON/OFF не требует перезапуска; observer удаляется в `deinit`, а состояние wide каждый bind вычисляется заново.

В основной экран настроек добавлен постоянный theme-aware SearchBar сразу под сегментами «Интерфейс / Функции / Прочее». Непустой запрос фильтрует `nagramiXAllSettingsEntries`, то есть единую модель всех трёх категорий, и не использует активную вкладку. Индекс строится из локализованных title, description, section и category; результаты используют исходные entry cases и handlers, группируются как `Категория · Секция`. DNS и proxy-действия представлены поисковыми ссылками на существующий Proxy screen без новых preference keys. Очистка запроса возвращает текущую выбранную вкладку.

Документация репозитория ведётся на русском языке. Английский допускается только в коде, стабильных идентификаторах, названиях внешних API и локализационных таблицах, где он необходим по назначению.

## Проверка и следующий шаг

Статические проверки Python, JSON, YAML, shell и пробельных ошибок для подготовки 0.3.8 прошли. Upstream pin Telegram-iOS 12.9.2 актуален. Первый нативный ARM64 build run `36140188656` завершился на двух Swift type errors в строках присваивания placeholder; причина исправлена и локально повторно проверена Swift parser. Упаковка IPA и runtime-проверка на физическом iPhone ещё не выполнялись.

Исправление wide posts статически проверено повторным успешным применением полного `ios/apply_overlay.py` к чистому pinned checkout Telegram-iOS `6ad963e5b62d354da79040f388ae2b9132fb17b8`, а также структурными проверками общей width pipeline. Linux-среда не может выполнить нативную iOS-сборку, визуальное сравнение с референсами, rotation/split-screen и runtime-регресс на физическом устройстве. Риск остаётся в фактическом отображении редких content nodes; требуется macOS build и mixed-channel regression на iPhone/iPad до признания исправления полностью проверенным.

Глобальный поиск статически проверен Swift parser, применением feature overlay к чистому pinned checkout и проверками, что search pipeline использует all-settings model без параметра активной категории. Нативная компиляция, клавиатура/Back, внешний вид тем и нажатия на результаты на устройстве не проверены. Вложенные proxy-результаты открывают существующий Proxy screen; отдельного deep-link к конкретной строке Telegram сейчас нет.

Следующий инфраструктурный шаг: дождаться повторного macOS workflow после исправления SearchBar placeholder и убедиться, что создан артефакт `NagramiX-0.3.8-unsigned-arm64`. Затем подписать IPA внешним способом и на устройстве проверить глобальность запросов `Proxy`/`Истории` во всех вкладках, поиск title/description/section, очистку, Back, empty state и темы; выполнить wide-post и полный регресс 0.3.8 по checklist из `product/releases/0.3.8.md`. Только после успешной приёмки публиковать релиз 0.3.8 и присваивать ему status stable.

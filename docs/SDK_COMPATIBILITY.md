# Совместимость SDK и границы модулей


Последняя guarded стадия `release_076_sdk` после `voice_transcription` переносит транзакции в TelegramCore через TelegramEngine.Messages. UI получает только snapshot сообщения и API замены локальных attributes; Postbox/transaction handle наружу не передаются. Native EngineRawMessage/EngineMessage.Id/EngineCodableEntry вместо прямого импорта. Списки AllowedImporters/AllowedPostboxAccess не расширяются, проверка не отключается. В workflow эта upstream-проверка выполняется и перед дорогой SDK-компиляцией.

Чтение snapshot остаётся отдельно от вычисления; transform вызывается заново над текущим сообщением внутри атомарной транзакции. Guards ON/revision/cancellation/source/язык/target/cache/удаление сохраняются. Текст, media, entities, thread, timestamp, flags, grouping, другие attributes не переписываются. TelegramEngine только сохраняет локальный результат, без серверной отправки/прочтения/Premium-обхода.

Проверка `scripts/validate_release_076_sdk.py` восстанавливает вход предыдущей стадии для строгих исходных проверок. Новый engine helper и оба фактических runtime исполняются в debug/optimized на прежних регрессиях с Postbox/Apple/API границами. Это проверка логики маршрута, не замена Apple SDK. Все input/guard/template/BUILD/destination SHA проверяются до первой записи.

Попытка136/run40450622301 прошла PostboxImportCheck, затем остановилась на Bazel analysis: URL codeload без расширения требует явного `type = "tar.gz"`; у TranslateUI осталась BUILD-зависимость Postbox, запрещённая upstream visibility. Последняя стадия `release_076_dependencies` задаёт формат существующего pinned архива (URL/SHA прежние) и удаляет больше не нужную зависимость, не расширяя visibility Postbox. Swift-код и guards обработчиков этим этапом не меняются.

Попытка137/run40451405507 прошла анализ зависимостей и дошла до Swift-компиляции. В сохранённом полном журнале подтверждены три ошибки: новый Swift запрещает неявный strong захват self с вложенным weak; у AVAssetWriterInput нет stopRequestingMediaData; у PresentationStrings нет Common_Copy. Последняя стадия release_076_compile после release_076_dependencies задаёт явный outer [self], сохраняет weak cancellation handler; завершает AVAssetWriter штатными markAsFinished/finishWriting либо cancelWriting, а callback готовности имеет weak self; кнопка диагностики использует существующий Conversation_ContextMenuCopy. Поведение PiP, отмены, серверных сообщений и настройки не перепроектируется.

Входы/выходы трёх файлов и предыдущие байты зафиксированы SHA. Проверка восстанавливает исходный предыдущий этап в изолированной копии, затем выполняет прежние dependency/engine/PiP guards; тесты coordinator/runtime запускаются также на новом фактическом коде. Локальный Swift и source checks не заменяют новую SDK-сборку или физическую приёмку.

Попытка138/run40467709965 успешно скомпилировала предыдущие проблемные модули NagramiXTranscription и GalleryUI. В финальном TelegramUI обнаружены два неизвестных символа одного обработчика ошибок перевода в ChatControllerNode: отсутствовал import TranslateUI. Последняя guarded стадия release_076_import добавляет только этот импорт; существующая BUILD-зависимость и публичный API TranslateUI уже присутствуют. Проверка фиксирует это как единственное различие Swift-файла, проверяет SHA BUILD/runtime, отсутствие частичных записей и точно восстанавливает предыдущие этапы.

# Кружок после холодного запуска: завершение и отправка

Позднее17октября пользователь прислал crash report94: подтверждён отдельный [watchdog capture/preview lock inversion](CAMERA_PREVIEW_WATCHDOG_FIX.md), примерно73минуты после process launch. Для него подготовлена дополнительная правка ownership/queue. Предыдущая правка ниже не устраняет этот механизм; принадлежность отчёта к исходному cold-recording эпизоду не установлена.

17 октября пользователь сообщил о единичном зависании и вылете в0.5.8/build94: первый кружок после запуска, задняя камера → селфи → завершение таймера → запись → отправка. Сообщение не появилось в Избранном; повторные записи работали. То же возможно в обычном чате. Разрешена проверка и исправление исходников, новая сборка не запрошена.

## Что установлено

Стек вылета/watchdog report и воспроизведение на устройстве недоступны. Причина именно этого события **не подтверждена**. Нельзя объявлять виноватыми кодек, сеть, Metal или холодную инициализацию без дополнительных данных.

В исходниках найдены два отдельных дефекта в подходящем пути:

1. `currentResults` ожидал следующий event горячего `resultsPipe`. `stopVideoRecording`/`sendVideoRecording` вызывают остановку раньше установки подписки; `takenRecordedData` дополнительно откладывает подписку до placeholder. Если результат уже опубликован, событие не повторяется, а waiter продолжает ждать. Снимок массива составлялся при создании сигнала; поздняя подписка могла также ждать уже завершившуюся остановку. Это установленная ошибка порядка событий; она не доказывает источник вылета.
2. Три вызывающих участка синхронно строили `AVMutableComposition`: добавление результата для preview, данные кадров для панели ввода, thumbnail обрезанного видео. Чтение `AVAsset.duration` и обнаружение/вставка дорожек выполнялись на вызывающем потоке, включая main. Эти AVFoundation операции могут блокировать, особенно при первом обращении к файлам. Длительность блокировки на устройстве не измерена.

Переключение на front с таймером уже использует завершённые фрагменты одного кружка и штатный adjusted-video export. Это поведение сохраняется. Default modern/legacy selector, server kill switch, rear-camera default, таймер, разрешения и настройки музыки не менялись.

## Исправление

Последний helper `apply_round_video_finalization` в `ios/apply_features.py`: один полный SHA256 входа экрана `83121d3f…`,15точных замен с полным preflight до единственной записи. Более ранние helpers и `NagramiXSelfieRecording.swift.inc` сохранены.

`Node` хранит `Promise<(revision, results)>` последней финальной остановки. Revision увеличивается только в `addCaptureResult`, после добавления финального фрагмента. `nagramiXAppendSwitchResult` сохраняет промежуточный фрагмент без публикации финального результата. При запросе остановки запоминается ожидаемая revision; `currentResults` фильтрует snapshot по ней. Promise штатного SwiftSignalKit воспроизводит значение поздним подписчикам. Поэтому подписка до результата, после результата и после создания сигнала получает целый актуальный массив, а предыдущая остановка record-more не удовлетворяет новый запрос.

`nagramiXFinishStop` сначала переводит камеру в `.none`, затем публикует результат. Синхронная доставка snapshot может сразу вызвать enqueue/dismiss; после такого callback состояние завершённой записи больше не обновляется повторно.

Все три построения composition идут через один signal на отдельной serial `Queue`, с доставкой результата на main. Сам алгоритм вставки AVFoundation дорожек и порядок/длительность фрагментов прежние. UI preview владеет отдельным MetaDisposable: продолжение записи/отправка отменяет ожидание, dismiss/deinit освобождает его. Callback дополнительно проверяет revision, `.none`, `didSend`, `isSendingImmediately`, `isDismissed`. Поздний preview не перекрывает новую запись и не возвращает экран после отправки. Уже начатую синхронную AVFoundation операцию отмена физически не прерывает; UI её не ждёт.

Логи содержат только фазы stop/finalized/preview/send/media-prepared, признак cameraSwitch и число фрагментов. Пути, содержимое, peer/message IDs, номер телефона и кадры не логируются. `media prepared for enqueue` означает передачу штатному sender, не подтверждение отправки на сервер.

Не изменены: recorder/AVAssetWriter/Metal, capture selection, кодеки/геометрия, live-upload, составление outgoing resource и export, view-once, quiet/scheduled/effects, сеть/серверные callbacks, локальный архив и значения настроек. Автоматическое восстановление несохранённого кружка после аварии не реализовано.

## Проверка исходников

Proof: `/workspace/.codex-validation-nagramix-cold-round` — before snapshot, reference pinned sources, checked-overlay, runtime.patch, verification/preservation. Полный fixture591outputs: один изменённый native экран,590побайтно прежних; нет новых runtime файлов/ресурсов/зависимостей. `scripts/validate_round_video_finalization.py` проверяет15точных обратных преобразований, clean/drift/rerun без partial writes, границы финального результата, callback order, cancellation, все три фоновых composition callers и прежние defaults/лимиты. Публичные Promise/runOn/Queue API сверены с точным upstream pin.

Swift grammar экрана проходит; это **не typecheck/SDK compile**. Python compile, release metadata и diff check проходят. Linux не выполняет Xcode/AVFoundation/Metal/XCTest или физический тест. Статус новой правки: **source_checked / compile_pending / device_pending**. В опубликованном IPA0.5.8/build94 её нет; metadata0.5.8 остаётся до новой команды на сборку, следующий рабочий выпуск0.5.9.

## Приёмка на физическом iPhone

- Полностью завершить процесс, открыть, записать первый кружок в Избранное: rear → front, дождаться3–2–1, продолжить5–10секунд и отправить. Проверить доставку, все фрагменты, A/V и воспроизведение. Повторить после нового cold launch в чате с собеседником и несколько раз в том же процессе.
- Отдельно проверить отправку непосредственно из записи и остановку → preview → отправку; front/rear без переключения; timer OFF/ON с сохранением выбора после перезапуска.
- Stop/send во время переключения, подготовки и на3/2/1: ранее записанная часть сохраняется, первый пустой старт отменяется по прежним правилам. Несколько flips, record-more, lock, trim/send: предыдущий snapshot не выдаётся за финальную новую запись.
- Быстрая отправка после stop, повторные нажатия, отмена/выход/фон во время подготовки preview: нет вечного ожидания, дублирования или возвращения старого preview. Проверить minimum duration и лимит60секунд.
- Music ON/OFF, динамик/AirPods, front flash, view-once и quiet/scheduled, доступные modern/legacy пути. Штатные ограничения прав сохраняются.

Если повторится вылет, нужны crash/watchdog report соответствующего процесса и время события; по фазовым логам можно отделить stop, preview и передачу sender. Без этого нельзя утверждать, что все возможные причины единичного вылета устранены.

# Общие переходы системного PiP

Первая часть утверждённой задачи по видео 5655902839050916057: переход в PiP и возврат, обычное превью поста, пропорции и полный откат отказа. Исправление фонового YouTube отложено по прямому указанию владельца. После публикации этой части сообщить о готовности к нему и дождаться следующей команды. Сборка IPA этой задачей не запускается.

Стадия 90 `pip_transition_coordinator` после 89 меняет три файла GalleryUI: UniversalVideoGalleryItem, GalleryController и GalleryControllerNode. Существующие sample-buffer/AVPlayer/WebKit плееры сохраняются. Новый плеер, декодер или перенос URL потока не добавляются. 19 guards фиксируют движки, WebKit-мост, YouTube JavaScript/implementation, фоновые настройки, аудио/Now Playing, декорацию, изображения, API UniversalVideoNode и BUILD.

Кнопка и свайп используют одну заявку с состояниями ожидания, запуска, активного PiP и возврата. Отсутствие sample-buffer слоя перестало служить постоянным запретом жеста. Имеется ограниченное ожидание до 5 секунд; перед фактическим запуском проверяются текущий источник, окно, владелец, готовность AVKit и показанного кадра. Ручная пауза не заменяется play/seek. Повторное нажатие не создаёт второй запрос. Таймаут, смена ролика/владельца и отказ возвращают исходные масштаб и положение, включая отказ до установки блокировки жеста. Отменённый native запрос не может возродиться поздним DidStart; повторный DidStart не прерывает уже работающий PiP.

Полноэкранные снимки чата и галереи убраны из подложки перехода. Существующая галерея закрывается после фактического подтверждения старта. Под системным окном остаётся настоящий интерфейс канала с обычным превью поста. Временное покрытие источника содержит только кэшированное изображение исходного медиа, а не служебный экран AVKit/WebKit. Превью не накрывает работающий источник до подтверждения старта. Оно сохраняет политику защиты содержимого.

Нативные размеры берутся из состояния действующего декодера с учётом его ориентации. Пока источник готовится, новая геометрия применяется сразу; во время передачи изменения откладываются до возврата. Размер actualSize передаётся вместе с размером отображения; для WebEmbed сохраняется масштаб 1, для остальных — 2. Веб-окно PiP продолжает получать пропорции от своего HTML/AVPlayer источника через системный API. При отсутствии размеров потока превью использует прежние метаданные поста. Превью вписывается целиком с сохранением пропорций, включая 16:9, 9:16, 1:1, 4:3 и широкие кадры. Новых преобразований исходных пикселей, кодеков или layer rotation нет; форму плавающего окна определяет iOS.

Native и встроенные источники используют общее подтверждение возврата. Существующий экран сначала присоединяется к окну, затем AVKit/WebKit получает подтверждение и завершает PiP. Превью остаётся над областью видео до сообщения об остановке PiP и готовности вернувшегося источника. Для sample-buffer дополнительно проверяется renderer и показанный кадр; для WebKit используются его подтверждённый выход, владение/присоединение и следующий ход отображения. Повторные Web-запросы возврата получают один показ экрана. Неудавшийся показ сохраняет активный PiP. Воспроизведение и положение не перезапускаются.

[Отчёт проверок](PIP_TRANSITION_COORDINATOR_CHECKS.json) разделяет исполнение настоящих обработчиков с явными системными границами, будущие UIKit/AVKit probes и полную SDK-сборку. В начало macOS preflight добавлены проверки общих обработчиков/отката/готовности, новых native cancellation API и полного превью с настоящими UIKit/AVKit/CoreGraphics. На Linux API-probes проходят только синтаксический разбор. Реальные пиксели, анимация и воспроизведение на iOS 27 требуют проверки IPA на iPhone.

Фон YouTube, его JavaScript-политика, звук, запись голосовых/кружков, кодеки и отправка этой частью не изменены. Паузы сайта, ограничения фонового WebKit и потеря аудиовладения остаются отдельной следующей задачей с образцом https://youtu.be/cgvHSmqSvdw.

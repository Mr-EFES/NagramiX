# Начальный способ расшифровки по Premium аккаунта

Актуальное уточнение владельца: [Premium по отдельному аудиофайлу](PREMIUM_TEMPORARY_TRANSCRIPTION.md), стадия51. Принудительная подмена Telegram на Apple отменена; original-ID RPC остаётся закрытым. Ниже описан исторический контракт предыдущей стадии.

Stage40 `transcription_account_defaults` применяется после `archived_round_native_controls`. Это изменение исходников после опубликованной0.9.4/build195; новую IPA, тег и релиз без команды не создавать. Следующий выпуск —0.9.5.

## Поведение

При отсутствии сохранённой конфигурации основной переключатель «Расшифровка сообщений» включён. Первоначальный способ — Telegram Premium для реального Premium-аккаунта и Apple на устройстве для обычного аккаунта. Авторасшифровка остаётся отдельной настройкой, исходно выключенной. При запуске приложение не начинает распознавание, не запрашивает доступ Speech, не скачивает модели и не включает облачные сервисы.

Регистрация статуса подключена к существующей подписке реального `AccountContextImpl` на собственный `EnginePeer`, а также к подписке экрана расшифровки. `nil` не трактуется как отсутствие Premium. До загрузки собственного peer безопасный временный способ — Apple. Известное состояние хранится по публичному `AccountRecordId.int64`; разные аккаунты не перезаписывают первоначальный способ друг друга. Пока пользователь не выбирал способ вручную, последующее изменение Premium обновляет этот начальный способ.

Ранее сохранённые Vosk/Whisper/Apple/Telegram/облачные варианты и явное выключение сохраняются. Новое опциональное поле `usesAccountDefaultProvider` отсутствует в старом JSON и декодируется как `nil`: такой способ считается явным выбором. Для новой конфигурации поле равно `true`. Нажатие на любой способ фиксирует ручной выбор, в том числе Apple, когда исходное поле уже равно Apple. Ручные настройки остаются общими для аккаунтов, как раньше; это не перенос всех настроек в отдельные аккаунты. По умолчанию отдельно выбирается только способ по Premium.

Существующий ключ `nagramix.transcription.configuration.v1`, enabled/automatic, языки, модели, ключи и согласия не сбрасываются. Регистрация аккаунта пишет только `nagramix.transcription.account-default.v1.<accountId>`. Runtime scope `sourceAccountId` очищается перед сохранением обычного изменения. Производный revision содержит разрешённый по аккаунту способ, чтобы очередь и результат не приняли устаревшую конфигурацию.

## Обработка и отображение

Основной экран настроек, поиск и подробные настройки используют один разрешённый по текущему аккаунту снимок. Проверки голосовых/кружков, контекстное меню, чтение кэша, выполнение, сохранение результата и автоматическая очередь получают контекст запрашивающего аккаунта. Прежние публичные вызовы без контекста остаются совместимыми.

Coordinator проверяет revision каждого задания в его аккаунте, включая отмену активных и ожидающих задач. Изменение начального способа другого аккаунта не отменяет неизменившееся задание. Порядок очереди, coalescing, ожидание подтверждения отмены работником и единственный слот декодера прежние.

Для сохраняемых временных сообщений действует прежнее безопасное локальное исключение: даже при выбранном Telegram Premium исходный одноразовый ID не отправляется в Telegram ASR/RPC. Сохраняются локальный Apple fallback, запрет скрытой авторасшифровки при выключенном основном переключателе, lifetime/consumed/TTL guards и отсутствие отметки открытия. `canUseTelegram`, IO, модели, credentials/consents, архив, штатный плеер и геометрия закреплены guards либо точным сравнением. Новых пользовательских строк нет; все71 ресурсный каталог с635ключами прежние.

## Проверки

Новый validator исполняет настоящие Settings/Codable/UserDefaults, Coordinator и полный ASR Runtime с прежней границей Telegram IO/Postbox. Из native caller извлекаются реальная регистрация аккаунта и реальное изменение ручного выбора; очередь синхронизируется барьером в тестовом same-file extension без изменения production.

Проверяются первый запуск, отсутствие самопроизвольного запуска распознавания, Premium/обычный аккаунт в обоих состояниях, неизвестный peer, разные аккаунты и смена Premium, старый JSON с ON/OFF и Vosk, неизменность сохранённых байтов/моделей/consents, ручной Apple с тем же исходным значением, scoped revision, отмена ожидающего задания и сохранение чужого активного задания. Повторяется полный suite private ASR голоса/кружков. Смысловые отрицательные варианты обязаны падать в debug и `-O`.

Обязательны guarded loader, синтаксическая проверка девяти native файлов, общие migration/inverse/Postbox проверки, canonical/full member audit и strict локализация. Независимый apply должен изменить ровно9из37655файлов; baseline39 и3285 прежних snapshots остаются побайтно прежними. Точные результаты — [TRANSCRIPTION_ACCOUNT_DEFAULTS_CHECKS](TRANSCRIPTION_ACCOUNT_DEFAULTS_CHECKS.json).

Source-проверки не заменяют компиляцию Apple SDK и проверку iPhone. При следующей отдельно разрешённой сборке проверить свежую установку с Premium и без него, вход вторым аккаунтом, основной переключатель/подробный экран/поиск, ручную смену способа и перезапуск. Speech permission и фактическое распознавание на устройстве pending.

## Управление

- Кнопка PiP и свайп вверх используют один `NativePictureInPictureContentImpl` и текущий видеослой плеера. Свайп вниз закрывает галерею. Горизонтальное перелистывание сохраняется.
- Сохранённый `nagramix.video.pipSwipe` управляет свайпом: ON соответствует направлению `up`, OFF отключает этот жест. Ключ, default true, позиция и подпись настройки прежние. Кнопка и системный автоматический переход не выключаются этим флагом — это соответствует эталону.
- Для текущего центрального видео контроллер готовится заранее, когда узел владеет содержимым и предоставляет sample-buffer слой. Повторная настройка не заменяет существующий контроллер. Создание синхронизирует центральность сразу, даже если её callback уже произошёл.
- Контроллер запоминает текущую центральность. KVO готовности `isPictureInPicturePossible` повторно назначает `canStartPictureInPictureAutomaticallyFromInline`, чтобы готовность AVKit не сбросила автоматический переход для текущего видео и не включила его для соседнего.
- PiP использует `AVPictureInPictureController.ContentSource` с существующим `AVSampleBufferDisplayLayer`. Отдельный AVPlayer, загрузчик полного MP4 и второй движок воспроизведения не создаются. Размером и расположением окна управляет iOS.
- При начале/завершении/возврате сохраняются эталонные callbacks, владение MediaManager и восстановление исходной галереи. При освобождении сначала отключаются KVO, автоматический запуск, delegate/contentSource и связь playback delegate, затем подписки/таймер и возможность воспроизведения вне иерархии.

Сохраняются серверные killswitches, `video_swipe_up_to_close`, ограничения рекламных и анимированных файлов. Если текущий узел ещё не владеет слоем либо AVKit не готов, начало PiP не гарантируется. В базовой0.8.5 очередь ожидания не добавлялась. Стадия0.8.6 сохраняет первый запрос до готовности, не обходит AVKit admission и не добавляет отдельный playback fallback. Самостоятельные настройки фонового воспроизведения, архива и экспорта прежние; специальная маска уже сохранённого архивного кружка в NativeVideoContent не удалена.

## Точность реализации

Поздняя стадия `system_video_pip` после `avatar_preview_navigation` изменяет один `UniversalVideoGalleryItem.swift`: пять точных замен и семь SHA guards. Полностью заменены native controller/playback delegate, setup и centrality; обработчик свайпа и controls visibility согласованы с эталоном. Новых dependencies и параллельных контроллеров нет. Ранние canonical стадии остаются входами воспроизводимой цепочки, их прежние реализации не подключаются дополнительным runtime-путём.

Десять целых блоков проверяются побайтно: controller, setup, centrality, свайп вверх, controls visibility, placeholder node, visibility, свайп вниз, кнопка и expand. При сравнении эталона удалены только отдельные маркерные комментарии и условие его настройки связано с существующим булевым ключом приложения. Метод получения видеослоя, его владение и галерейные жесты также сопоставлены; GalleryPagerNode/GalleryItemNode совпадают с эталоном. Все изменения вне пяти замен обратимо восстанавливаются побайтно.

## Проверка

```sh
python3 scripts/validate_system_video_pip.py --source <native> --swiftc <swiftc> --report <json>
```

В debug и `-O` проходят по 49 проверок с полным фактическим controller/playback delegate, setup, центральным блоком, кнопкой, свайпами и восстановлением. AVKit/KVO, UIKit, аккаунт/сигналы и доставка main queue — явные тестовые границы. Проверены повторные сигналы готовности для текущего/соседнего видео, один слой, отсутствие повторного setup, отсутствие владельца/слоя, OFF и killswitches, подготовленный первый свайп, кнопка, начало/stop/restore, возврат исходной галереи, владение MediaManager и очистка наблюдателя/делегата/источника/подписки. Старые lifecycle и admission воспроизводят отсутствие готовности/проверки владельца и отвергаются в обоих режимах.

27 некорректных входов отвергаются без частичной записи; Swift parse полного файла проходит. Новая стадия применена к независимому полному post-port дереву, выход совпадает с pre-post деревом побайтно. Финальный post-port не меняет этот файл; upstream PostboxImportCheck проходит. Legacy validators снимают новую стадию; прежняя проверка PiP compile fix и gallery export gate проходят.

Доказательства вне Git — `/tmp/nagramix-system-pip/verification.json`, `verification.log`, `composition.log`, `previous-pip.log`, `gallery-regression.log`, полученные файлы эталона. Временные файлы не считать долговременным архивом. SDK и IPA подтверждены поздней сборкой 0.8.5/build165; физическая приёмка остаётся pending. Опубликованный 0.8.4 содержит прежнее поведение; состояние новой публикации — в RELEASE_STATUS.

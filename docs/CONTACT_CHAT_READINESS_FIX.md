# Чаты открываются без решения о доступе к контактам

**После113 эта реализация заменена по прямому запросу пользователя.** Отдельный display seed удалён в конечном overlay; менеджер телефонной книги теперь сам завершает штатную ветку отсутствия доступа при notDetermined, startup notice подтверждён отказом без окна. [Актуальная реализация и проверки](CONTACTS_DEFAULT_DENIAL.md). Новый source/native compile pending; дальнейшие160checks и SDK113 ниже относятся только к историческому display-seed исправлению.

Текущий статус на 21 октября: включено в Release 0.6.7 / build 113; Apple SDK compile и независимая проверка опубликованного пакета пройдены. Физическая приёмка новой версии ожидается. Предшествующие source-only proofs ниже описывают этап до этой сборки; актуальный итог — [RELEASE_STATUS](RELEASE_STATUS.md).

21 октября пользователь подтвердил регрессию в установленной 0.6.6/build112: переписки, группы и каналы не открывались до обращения к контактам и отмены синхронизации. Это ошибка нашей правки отложенного запроса контактов. Исправление подготовлено в исходниках `main`; опубликованный IPA112 его не содержит.

## Причина

В закреплённом Telegram-iOS `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838` менеджер адресной книги не выдаёт `importable()` до разрешения состояния `.notDetermined`. Штатный `ContactsSettings.defaultSettings` включает синхронизацию, поэтому `optionalImportableContacts` ждёт этот источник.

`ApplicationContext` привязывает к нему как импорт аккаунта, так и отображаемые номера `sharedContext.deviceContactPhoneNumbers`. Хотя Promise номеров создаётся с пустым набором, настоящий `Promise.set` сбрасывает сохранённое значение перед подпиской. После привязки пустой набор исчезает. Номера — один из 26 входов `combineLatest` первой транзакции истории в `ChatHistoryListNode`; без первого события история не становится готовой. Отмена синхронизации выдаёт пустой словарь и снимает ожидание — именно это пользователь наблюдал на iPhone.

## Исправление

Третья точная замена в `apply_deferred_contact_permission` выдаёт пустой `Set<String>` перед подпиской **только потока номеров для отображения**. Затем поступают настоящие обновления адресной книги. Импорт `account.importableContacts`, системные статусы доступа, сохранённый выбор синхронизации и настройки по умолчанию не меняются. Никакой искусственный пустой импорт не отправляется. При смене источника не сохраняются номера прежнего аккаунта.

Автоматический запрос контактов остаётся исключённым; доступ запрашивается штатными действиями пользователя. Готовность настоящей истории не обходится. Не меняются `DeviceAccess`, `DeviceContactDataManager`, навигация, база, read receipts, сетевые функции и прочие разрешения. Полный SHA256 входного ApplicationContext и все три уникальные точки проверяются до записи.

## Проверка

`scripts/validate_contact_chat_readiness.py` и `scripts/tests/NagramiXContactChatReadinessTests.swift` используют 11 настоящих файлов закреплённого SwiftSignalKit с проверкой Git blob SHA. Старое/новое связывание потока и выбор sync-предпочтения извлекаются из native source. Выполняются реальные Promise, then, mapToSignal, dispose и 26-входовый combineLatest. Границы ОС/предпочтений/истории управляются тестом; UIKit, контакты iOS и сетевой импорт на устройстве не запускаются. Для Linux добавлен импорт CoreFoundation во временную копию; обращение к подменённому планировщику завершило бы тест ошибкой.

- По **160 проверок** в debug и optimized, warnings-as-errors: прежняя блокировка и восстановление отменой sync; отсутствие сохранённых настроек; pending/allowed/denied/пустой источник; сохранённый sync OFF; позднее разрешение и live updates; смена аккаунта; повторные подписки. Пустой контактный snapshot не заменяет настоящую готовность истории и не запускает импорт.
- Полный overlay: 418 native файлов, единственное отличие от build112 — ApplicationContext, остальные 417 побайтно прежние.
- Точное воспроизведение patcher и три отказа без частичной записи: повторное наложение, drift, отсутствующий файл. Swift frontend parse и Python AST пройдены.

Локальные доказательства: `/workspace/.codex-validation-nagramix-contact-chat-ready-fix/verification.json`, `native-scope.json`, `validation.log`. Статус: **source_checked / native_compile_passed / device_pending**. Исправление включено в Release 0.6.7 / build 113, SDK и IPA проверены. Следующая сборка только по новой отдельной команде пользователя.

## Приёмка следующего IPA

1. На состоянии iOS «доступ к контактам ещё не запрашивался» открыть переписку, группу, канал, Избранное и тему без предварительного открытия контактов. Не сбрасывать рабочие данные ради проверки; использовать отдельное тестовое состояние.
2. Холодный запуск/возврат из фона/смена аккаунта: чаты доступны, автоматического запроса нет.
3. Явно открыть функцию контактов, отменить/отказать: чаты остаются доступны, синхронизация не включается сама.
4. Явно разрешить доступ и синхронизацию: номера и контакты обновляются. Сохранённый OFF остаётся OFF после перезапуска; после отзыва разрешения приложение продолжает работать.

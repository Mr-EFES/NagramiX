## Исправление ожидания контактов при открытии чатов — 21 октября

На физическом iPhone в build112 пользователь подтвердил: после исключения стартового запроса контактов чаты не открывались до обращения к контактам и отмены синхронизации. Предыдущая проверка политики запросов не охватывала зависимость готовности истории от первого события адресной книги. Настоящий Promise сбрасывает начальное значение при set, а менеджер контактов молчит при `.notDetermined`.

Теперь поток номеров для отображения получает начальный пустой набор, затем настоящие обновления. Native импорт и выбор синхронизации не меняются, разрешения не выдаются и не запрашиваются автоматически. В apply_deferred_contact_permission теперь три уникальные замены под прежним полным SHA256. Полный overlay меняет только ApplicationContext; 417 других файлов прежние. По160 проверок настоящего SwiftSignalKit debug/optimized воспроизводят прежний отказ и способ восстановления пользователя, проверяют новую готовность чатов и отсутствие искусственного импорта. [Причина, проверки и приёмка](CONTACT_CHAT_READINESS_FIX.md).

Исправление пока только в исходниках main: source_checked/native_compile_pending/device_pending. Опубликованная112 его не содержит; новая сборка не запускалась. Следующий раздел описывает первоначальную правку20октября и её тогдашние проверки.

## Поведение

Первое обращение к камере, микрофону, фотографиям, геолокации, контактам, уведомлениям и Siri уже использует соответствующие системные API Telegram. Проверки статусов и эти запросы сохраняются. Приложение не может повторно показать системный privacy prompt после постоянного отказа: доступ меняется в настройках iOS.

Окно на скриншотах — штатный внутренний AccessDenied alert Telegram, а не первый запрос iOS. Теперь такие окна используют `UIAlertController(.alert)` с прежними текстами, кнопками «Не сейчас»/«Настройки» и прежними callbacks. Размер текста, расположение кнопок, доступная область и прокрутка определяются UIKit. Ручных размеров, собственных шрифтов и ограничивающей маски нет; светлый/тёмный стиль и акцент соответствуют текущей теме приложения.

Охват: восемь окон DeviceAccess для камеры/видеозвонка/QR/проверки возраста, микрофона/голосовых/видео/звонков, фотографий, обычной/фоновой/точной геолокации и мобильных данных; ещё пять окон контактов при добавлении, создании сообщения, приглашении и в списке контактов. Всего 13 точек вызова в пяти файлах. Мобильные данные не имеют отдельного privacy prompt iOS: там сохраняется прежний переход в настройки. Обучающие экраны Telegram для уведомлений/Siri остаются прежними; автоматический запрос контактов исключён по уточнению20октября выше, явные действия в контактах сохранены.

## Интеграция

Общий `ios/Sources/DeviceAccess/NagramiXPermissionAlertController.swift` использует существующий `Display.LegacyPresentedController` — тот же мост, которым Telegram показывает нативные UIViewController. При действии UIKit закрывает alert, а callback также удаляет прозрачный host Telegram. Отмена сохраняет прежний пустой callback; «Настройки» выполняет прежний openSettings. Нет нового запроса разрешения, автоматического перехода в настройки или подмены результата авторизации.

Поздний `apply_native_permission_alerts` в `ios/apply_features.py` проверяет шесть полных SHA256, существующий source glob и отсутствие коллизии helper. Затем заменяет только фабрику окна в 13 вызовах и копирует helper. BUILD не меняется, новых зависимостей приложения нет. Все callbacks/completion/promise, `onlyCheck`, authorized/denied/restricted/limited ветки, usage descriptions и остальные окна Display сохраняются. Окно нехватки места не относится к разрешениям и не менялось. Предыдущая правка повторных кружков сохранена.

## Проверка

Два чистых полных feature overlay на закреплённых Git blobs: 334→335 outputs, пять изменённых файлов и один новый helper, 329 прежних outputs идентичны. `scripts/validate_native_permission_alerts.py` проверяет точный обратимый scope 13 вызовов, неизменность авторизации и 11 сценариев clean/rerun/collision/partial/missing/6drift; отказы не записывают частичный результат. Swift grammar шести изменённых/новых файлов, Python syntax, release metadata и diff PASS. Proof: `/workspace/.codex-validation-nagramix-permissions`.

Apple SDK typecheck, native сборка и физический iPhone ещё не запускались. При следующей разрешённой сборке проверить:

1. На чистом состоянии разрешений: первый системный запрос камеры/микрофона, фото, геолокации, контактов и уведомлений. Разрешить и отказаться по отдельности; убедиться, что функция не запускается без доступа.
2. После отказа: обе кнопки нового окна; полный текст/кнопки, увеличение системного шрифта, VoiceOver, обе темы, портрет/поворот и показ поверх открытого экрана/клавиатуры. После отмены нет невидимого блокирующего слоя; повторное открытие не наслаивает host.
3. «Настройки» открывает прежний раздел приложения; изменить разрешение и вернуться. Повторить голосовые, кружки, камеру, видеозвонок, QR, Photos limited/save, контакты и обычную/точную/фоновую геолокацию. Системные ограничения не должны считаться выданным доступом.
4. Проверить отсутствие регрессий записи с таймером, музыки, rear camera default и ранее подготовленных кружков. При отказе во время звонка прежнее фоновое уведомление сохраняется.

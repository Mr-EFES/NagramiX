# Просмотр временного медиа и настоящее удаление

Stage43 `temporary_expiration_semantics` после `web_video_picture_in_picture`. Команда владельца: после просмотра одноразового медиа собеседником сохранять его с обычным оформлением, без эффекта удаления, подписи и прозрачности50%; галочки должны отражать реальное чтение. Новых переключателей, аннотаций и локализационных строк нет. Опубликованная0.9.4/build195 остаётся прежней; IPA/Actions без новой команды не запускать.

## Причина и исправление

`StateReplay+ReadStates` доставляет подтверждение открытия содержимого в `markMessageContentAsConsumedRemotely`. Метод сохранял настоящий `ConsumableContentMessageAttribute(consumed: true)`, но также начинал Autoremove/Autoclear countdown и сразу заменял view-once медиа на `TelegramMediaExpiredContent`. Затем `markTemporaryExpired`, `snapshotForExpiredMessage` и readonly interaction resolver присваивали `deletedAt` — тот же признак, который использует настоящее удаление. Отсюда появлялись подпись и прозрачность50%.

При разрешённом сохранении временных сообщений новый путь оставляет полученное `consumed: true`, теги и штатную обработку упоминаний. Он захватывает исходник прежним архивом, сбрасывает только активные локальные countdown values и пропускает запуск TTL/замену медиа. Исходные timeout, принадлежность одноразовому медиа, native MessageId, сами файлы и плеер сохраняются. Входящее подтверждение не создаёт нового исходящего content-read RPC.

Отдельная проверка внутри уже поставленной timer transaction покрывает переключатель, включённый после постановки таймера. Она повторно проверяет текущую eligibility, сохраняет исходник и обнуляет timestamp-based countdown attributes. Поэтому сообщение остаётся в Postbox, а штатная очередь таймеров может перейти к следующей записи. При OFF, неподдерживаемом/обычном/платном/неотправленном источнике сохраняется прежний timer path.

Для пришедшего с сервера expired placeholder архив теперь хранит отдельное необязательное JSON-поле `mediaExpiredAt`. Оно не является MessageAttribute и не меняет Postbox codec/schema. `deletedAt` присваивается прежними путями настоящего удаления. Expiry snapshot и interaction resolver не подделывают удаление; обычное оформление использует прежний predicate `nagramiXShowsArchiveNotice` с нулевым deletedAt. Реальное удаление после истечения получает прежнюю подпись/50%, а позднее истечение не отменяет подтверждённое удаление.

Истёкшая сохранённая строка остаётся доступной при ON, в исходном peer/thread и пределах истории, в том числе при отсутствии native row. При OFF показывается штатный expired placeholder, если он существует; feature «Удалённые сообщения» продолжает показывать настоящие удаления. Expiry provenance сохраняется при refresh/capture и перезапуске. Полная очистка tombstone-ит также expiry-only записи, чтобы повторная загрузка истории их не воскресила. Отдельная ownership-проверка позволяет явно удалить expiry-only копию: при отсутствии native row она очищается локально, её synthetic ID не становится серверной командой. Реальная локальная принадлежность не приравнивается к визуальному признаку удаления. Истёкший original не может получить новое разрешение «Отметить открытым».

## Галочки

Для живой строки и замены native expired placeholder сохраняется `MessageHistoryEntry.isRead`. Для добавленной expiry-only строки больше нет безусловного `isRead: true`: используется тот же реальный CombinedPeerReadState по peer/namespace и native MessageIndex, что в Postbox. Отсутствующее подтверждение даёт false; incoming не получает исходящих галочек. Имеющийся отдельный thread read override работает дальше прежним способом. Старое оформление настоящих удалённых строк сохранено.

Одна галочка Telegram означает принятие сообщения Telegram, две — прочтение переписки. Они сами по себе не доказывают просмотр вложения или прослушивание голоса. Если другой клиент скрывает открытие медиа, новое подтверждение не выдумывается. Suppression исходящих локальных content receipts, явный consent, private ASR и native history reads остались прежними.

## Границы совместимости

Старый JSON без `mediaExpiredAt` декодируется без миграции. Старое ненулевое `deletedAt` не стирается по предположению: прежняя версия не записывала, было ли это истечение или реальное удаление. Новые события разделяются однозначно в известных expiry paths.

Telegram delete updates не содержат причины удаления и не доказывают намерение собеседника. Такие обновления по-прежнему считаются удалением; маскировать все удаления временных сообщений означало бы сломать согласованную функцию настоящих удалённых сообщений. Для исчезнувшего на сервере оригинала сохраняется только реально захваченное содержимое, недоступные байты не восстанавливаются из воздуха.

Плеер, архивные resource IDs, геометрия кружков, одноразовая маркировка, Free Content, PiP, пересылка/рассылка, шрифты, ASR и права/consent не перерабатывались. Существующие предпочтения обоих alias keys сохранены.

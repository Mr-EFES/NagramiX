# Исправление SDK186 перед повтором 0.9.0

Первая чистая сборка 0.9.0, [186](https://github.com/Mr-EFES/NagramiX/actions/runs/42472042232), прошла полный macOS source gate и холодную основу, но завершилась ошибкой компиляции TelegramUI. Нового IPA и публикации нет. SDK сообщил в `ChatControllerLoadDisplayNode.swift` два обращения к невидимому `NagramiXTabSettings`, одну недоступную аннотацию `MessageId` и превышение времени typecheck большого выражения создания интерфейса.

Предыдущие изолированные тесты определяли имена типов в одном модуле и не обнаружили отсутствие импорта. Это ограничение прежней проверки, а не подтверждённая успешная компиляция приложения.

Новая стадия `release_090_author_compile` после одиннадцати предыдущих меняет ровно один файл:

- Добавляет явный `import NagramiXCore`, где действительно объявлен `NagramiXTabSettings`; dependency TelegramUI уже существует и защищена SHA.
- Использует публичный `EngineMessage.Id` вместо трёх локальных аннотаций Postbox `MessageId`. Прямой импорт Postbox не добавляется.
- Выносит обработчик «По автору» в отдельный private method с публичным `EnginePeer.Id`, оставляя в большом initializer короткий weak-self вызов. Порядок действий, проверки существования/автора/поколения, отмена и обработка архива сохранены. Это также уменьшает выражение, на котором SDK сообщил timeout; полное подтверждение даёт следующий SDK-запуск.

Before/After, 16 dependency guards и loader проверяются до записи. Все 2 092 прежних snapshots остаются неизменёнными. Полные деревья до/после содержат по 37 655 путей; изменён только указанный файл. Независимое применение loader к прежней свежей композиции даёт ноль отличий от проверенного кандидата.

Новая проверка компилирует настоящие 12 файлов NagramiXMediaSettings и настоящий NagramiXTabSettings отдельными модулями. Публичные Id alias читаются из защищённых native EngineMessage/EnginePeer. Клиент без Postbox import проходит; отсутствие NagramiXCore import и возврат к bare MessageId воспроизводят реальные ошибки SDK в debug/-O. Backing Postbox-типы этого узкого probe — явные адаптеры, а не полный Postbox runtime.

Полный новый private method и weak-self вызов исполняются на 34 сценариях прежней семантики в каждом режиме; stale archive и позднее удаление проверены отрицательными запусками. Loader имеет 12 fail-closed сценариев. Дополнительно повторены общий migration/Swift gate, native PostboxImportCheck, обратная проекция, custom member audit, локализация и статические проверки workflow.

Точные результаты и SHA: [RELEASE_090_SDK186_CHECKS](RELEASE_090_SDK186_CHECKS.json). Кандидат: `/workspace/.codex-release-090/fix186/source`. Apple SDK новой стадии и физическая приёмка остаются pending. Владелец уже разрешил исправления и повторы до успешного выпуска 0.9.0; повторная команда на этот retry не требуется.

# Авто-мьют новых каналов и точное время статуса

Подготовлено в исходниках NagramiX 0.5.1 на Telegram-iOS 13.0 (`f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`). В опубликованный IPA №83 эти изменения не входят. Состояние обеих функций: implemented / compile_pending / device_pending. Правка включена в текущую подготовку тестового выпуска; результат новой сборки записывается в RELEASE_STATUS.md.

## Настройки

«Авто-мьют новых каналов» находится в Функции → СООБЩЕНИЯ. Ключ `nagramix.messages.autoMuteNewChannels`, default **ON** только при отсутствии сохранённого значения. При новой подписке уведомления канала отключаются бессрочно штатным механизмом Telegram. Группы, собственные каналы и ранее подписанные каналы сохраняют настройки. После подписки пользователь может включить уведомления обычной кнопкой: повторное обновление канала не применяет авто-мьют заново. Выключение настройки влияет на следующие подписки и не размьючивает прежние.

«Показывать точное время» находится в Интерфейс → ПРОФИЛИ. Ключ `nagramix.profiles.showExactLastSeen`, default **OFF** только при отсутствии значения. К штатному статусу добавляется последнее посещение в местном часовом поясе, например «был(а) 2 часа назад (14:03:27)». Формат — 24 часа с секундами. В чате и профиле уже открытые статусы обновляются при изменении настройки. Статусы «в сети», «был(а) недавно», «на этой неделе», «в этом месяце» и «давно» не раскрываются; время не вычисляется из lastActivity. Настройка не меняет приватность Telegram и не добавляет точности, которой нет в полученном timestamp.

Оба значения сохраняются после перезапуска и обновления. Первоначальные значения не устанавливаются заново при каждом холодном запуске. Новые строки имеют IDs132–135, прежние идентификаторы сохранены; доступны поиск, русская/английская локализации, многострочные подписи и штатные переключатели.

## Нативная интеграция

Финальный `apply_channel_mute_and_exact_time` в `ios/apply_features.py` проверяет полные SHA256 шести файлов проверенного pin и 13 уникальных подстановок до любой записи. Зависимости модулей не меняются; TelegramCore и TelegramStringFormatting читают те же стабильные ключи Foundation/UserDefaults, без циклической зависимости от NagramiXCore.

В `UpdatePeers.swift` переход уже известного TelegramChannel из отсутствия членства в member запускает политику только для broadcast, кроме creator. Это охватывает обычные входы, папки, повторное вступление после выхода и одобрение заявки у известного канала. Первый импорт существующего member без прежнего peer исключён, чтобы синхронизация старых подписок не отключила уведомления.

Успешные явные join/import в `JoinChannel.swift` и `JoinLink.swift` дополнительно обрабатывают ранее неизвестный broadcast. Полученный peer и pending notification setting сохраняются одной Postbox-транзакцией перед штатным addUpdates, иначе native worker мог удалить настройку при отсутствии inputPeer. WebView, RPC-ошибки и request-sent не считают подпиской. Политика сохраняет звук, превью и story settings, предпочитая уже pending настройку, и использует `updatePendingPeerNotificationSettings` с `.muted(until: Int32.max)`; отправку на сервер выполняет штатный ManagedPendingPeerNotificationSettings.

Граница: одобрение приватной заявки, для которой Telegram ещё не предоставил peer и которая пришла позже без повторного успешного join/import, неотличимо в общем обработчике от первой синхронизации старого канала. Такой неизвестный канал автоматически не мьютится. Уже известные заявки обрабатываются при реальном переходе членства; фонового опроса invite hashes и массового изменения старых подписок нет.

В `PresenceStrings.swift` сохранён весь штатный форматтер; публичная функция дописывает `(HH:mm:ss)` только к реальному прошлому положительному `.present(timestamp)`, когда настройка ON. Используется localtime_r, без создания DateFormatter для каждой строки. При OFF результат побайтно прежний. Нативные ChatTitleView и PeerInfoData используют этот общий форматтер; добавлены observers изменения настройки с удалением при deinit/dispose. Observer профиля обновляет только текущий presence, сохраняя специальные статусы ботов/support.

## Проведённые проверки

Полное применение overlay к чистым проверенным входам: **427 выходных файлов**, **416 сохранены**, **11 изменились** относительно предыдущего proof, расширенного шестью stock inputs. Все **13 подстановок** обратимы в исходный pin. **12 вариантов изменения входов и повторное применение** отклонены до записи любого из шести файлов. **9 Swift syntax trees** проходят tree-sitter; предыдущие строки RU/EN и stable IDs не изменились, четыре новых локализованных ключа в каждом языке уникальны. Python overlay, метаданные выпуска, русские welcome-строки и git diff --check проходят.

Это проверки исходников. В Linux нет Xcode/Apple SDK: компиляция, сетевые эффекты и UI на физическом iPhone ещё не подтверждены.

## Приёмка на iPhone

- Чистая установка: авто-мьют ON, точное время OFF. Сохранить противоположные значения и проверить перезапуск/обновление.
- Войти в публичный и приватный broadcast через приглашение. Проверить локальный значок мьюта, отсутствие уведомлений и синхронизацию настройки в другом клиенте.
- Добавить каналы через новую/обновлённую общую папку: новые замьючены, прежние сохраняют свой выбор. Группы и собственные каналы не мьютятся.
- Подписка с выключенным авто-мьютом, ошибка RPC, WebView и ожидающая заявка: прежний результат. Одобрить заявку известного канала; отдельно проверить ограничение неизвестной приватной заявки.
- Размьютить новый канал вручную, получить сообщения/обновления, перезапустить: уведомления не выключаются повторно. Проверить выход и новое вступление при ON.
- Проверить настройки звука/превью и pending изменения: авто-мьют меняет только muteState. Обычный старт и синхронизация старых каналов не меняют уведомления.
- Точное время ON/OFF в открытом чате и профиле: только достоверный last-seen timestamp, секунды, местный часовой пояс, смена даты/года и летнее время. Проверить скрытые статусы, online, ботов/support и несколько аккаунтов.
- Проверить маленький экран, светлую/тёмную тему, большой шрифт, VoiceOver и быстрое открытие/закрытие экранов; отсутствие вылетов и задержек на этих путях.

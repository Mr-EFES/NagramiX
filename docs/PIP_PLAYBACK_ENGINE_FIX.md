# Общий запуск системного PiP

18 октября пользователь подтвердил физический отказ в установленной версии0.6.1: не работают ни отдельная кнопка, ни свайп. Это отменяет предположение, что достаточно исправления распознавания жеста. Предыдущая успешная компиляция не подтверждает работоспособность PiP на iPhone. Пользователь также сообщил, что сам удалил прежние релизы; не восстанавливать их автоматически.

## Изменения

Кнопка и свайп теперь вызывают один механизм запуска. Настройка свайпа ограничивает только жест; кнопка от неё независима. Сохраняются запреты секретных/рекламных/анимированных сообщений, текущая media identity и один действующий владелец PiP.

Источник предоставляет свой настоящий основной видеослой через UniversalVideoContentNode. NativeVideoContent и HLSVideoJSNativeContentNode возвращают AVSampleBufferDisplayLayer; PlatformVideoContent — AVPlayerLayer. Прежний поиск только sample-buffer слоя не покрывал второй путь. Запасной плеер, фиктивный слой и второй декодер не создаются.

Контроллер подготавливается при получении текущим видео собственного узла; автоматический запуск отключён. Явный запрос ожидает isPictureInPicturePossible через KVO в пределах общего срока8с. Готовность аудио проверяется через ManagedAudioSession. Если немому ролику не досталась активная playback-сессия, используется штатная mixing playback-заявка менеджера; при активной записи она не создаётся. Прямой смены AVAudioSession category/route нет.

NagramiXPiPPlaybackSession управляет ожиданием, единственным native start, подтверждением, передачей галереи и очисткой. willStart не закрывает галерею: передача происходит только после didStart либо подтверждённого active. Отказ/таймаут освобождает подготовку без оставшегося владельца; повторная попытка получает новый контроллер. Смена foreground после принятого native start не отменяет саму презентацию. Устаревшие события не повторяют передачу.

Sample-buffer delegate применяет запрошенное play/pause вместо инверсии. Его снимок статуса защищён; диапазон воспроизведения включает время controlTimebase. Expand подтверждает восстановление интерфейса только после реальной презентации галереи.

Пользовательское окно ошибки кнопки локализовано RU/EN. Пропорции ролика не ограничивают запуск. Существующее следование источника направлению swipe/drag сохранено; отдельное системное окно размещает iOS, публичного API задания его координат нет.

## Физическая приёмка

- Холодный запуск: кнопка, затем независимо свайп, на горизонтальном, вертикальном и квадратном видео. Должно появиться одно системное окно с текущим роликом и временем.
- Все8направлений, быстрый swipe и медленное удерживание; источник следует пальцу. Отдельно OFF: кнопка работает, штатные жесты возвращаются.
- Обычный локальный ролик, поток/HLS, немой ролик, пауза и буферизация; по10повторов на каждом формате.
- Закрытие PiP, Expand, следующее видео, повтор после отказа/таймаута, сворачивание и блокировка. Не должно быть пустой галереи, второго плеера или занятого состояния без окна.
- Наушники, внешняя музыка, звонок и запись: сохранить маршруты и поведение защищённых функций. Физический результат фиксировать отдельно от CI.

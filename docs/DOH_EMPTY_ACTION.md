# Пустое поле пользовательского DoH

Утверждённый эскиз реализован завершающим этапом75 `doh_empty_action`, после `wide_portal_api`. Меняется только `submodules/SettingsUI/Sources/NagramiXCustomDohController.swift`.

Подсказка получает перенос после стандартного обозначения `HTTPS URL`. Русский текст отображается так:

```text
Введите корректный HTTPS URL
с именем сервера без пробелов.
```

Текст берётся из прежней локализации. Размер шрифта, штатное измерение высоты и перенос длинных строк сохраняются; ни русский литерал, ни отдельная ветка языка в контроллер не добавляются. Все 71 каталога и их 668 ключей прежние. Переводы без этой последовательности слов продолжают переноситься штатно.

В окне остаются два действия:

- Пустая строка: нейтральное «Отменить» и недоступное «Сохранить».
- Любой введённый текст, включая неполный адрес: красное «Удалить». Сохранение доступно только после прежней проверки корректности HTTPS URL.
- Очистка поля крестиком, клавиатурой или заменой текста на пустой возвращает «Отменить». Очистка сама по себе не меняет сохранённые настройки.
- «Отменить» закрывает окно без удаления прежнего адреса и смены DNS-провайдера. Даже устаревший callback кнопки удаления проверяет текущее поле перед действием.
- «Удалить» при непустом поле сохраняет прежнее поведение: удаляет пользовательский адрес, восстанавливает прежнего провайдера и закрывает редактор.

Используется штатный `AlertScreen` с `actionsSignal`, `ExternalState.valueSignal` и постоянными ID двух кнопок. Меняются подпись и тема кнопки, поле ввода и окно не пересоздаются. Для точной русской подписи «Отменить» повторно используется существующий перевод `WebApp.Download.Cancel`; `Common.Cancel` в Telegram переводится как «Отмена». Новых строк, ресурсов и зависимостей нет.

HTTPS-валидация, проверка доступности сервера, сохранение, повтор после ошибки, защита от двойной отправки, отмена запроса при закрытии и отклонение запоздавших ответов сохранены. Резолвер, история DNS, список прокси, IPv6, автопереключение и остальные функции не меняются. Общие компоненты AlertScreen/AlertInputField не изменены.

Проверка исполняет полный production-контроллер, реальные getter локализации, native Action/Configuration/сигнатуру инициализатора, ExternalState и SwiftSignalKit. 35 проверок проходят в debug и `-O`; исходный74 и вариант ошибочного удаления при отмене должны отклоняться в обоих режимах. Проверяются неизменность ID и поля, пустой/сохранённый/неверный адрес, ввод/очистка, сохранение и Return, ошибка/повтор и поздний ответ после отмены. Загрузчик проверяет23 зависимости и все preimages до записи;12 повреждённых входов отклоняются. Новый сценарий включён в ранние Swift-проверки и обязательный post-apply gate.

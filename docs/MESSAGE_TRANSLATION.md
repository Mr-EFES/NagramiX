# Перевод сообщений и чатов

Текущее уточнение: [Telegram Premium и перевод в самом сообщении](TRANSLATION_INLINE_TELEGRAM.md), стадия `translation_inline_telegram` после упрощения. Семь явно выбираемых сервисов; контекстный перевод целого текста обновляет пузырь без отдельного результата, доступны исходник и возврат к нему.

**Актуальная стадия 28 октября — [упрощённый переводчик](TRANSLATION_SIMPLIFICATION.md):** Apple/Google/Яндекс без отдельных настроек, Gemini/ChatGPT/DeepSeek только с личным API-ключом, Pollinations исключён; main без трёх footer-подписей. Новый target/preferred, миграция и Save без промежуточной revision. Source/syntax проверены; новая SDK/iPhone ожидаются. Нижние сведения о семи сервисах относятся к предыдущим версиям.

Статус27октября: исходники включены в опубликованный0.7.6/build139 (`c7201b506bbc8ccd25e84e9cef9dd812b905bd77`). Нативная SDK и релизный IPA проверены; физическая приёмка ожидается. [Результат](RELEASE_STATUS.md).

Реализация согласованных эскизов и уточнений пользователя 26 октября 2026 года. Последнее имя первого переводчика — **Apple**. В списке семь пунктов: Apple, Google, Яндекс, Gemini, ChatGPT, DeepSeek и отдельно GPT-OSS · Бесплатно. Седьмой пункт явно одобрен пользователем. Включено в SDK/IPA139, физическая приёмка ожидается.

## Изменения в исходниках после build 139

В разделе «Прочее» группа переименована в «Переводчик». На странице отдельные переключатели контекстной кнопки и автоперевода чатов, выбранный провайдер показывает ссылку на свои настройки, GPT-OSS показан как Pollinations. Настройки нейросетей предлагают выбор модели колесом, температуру 0–100% и сохранение черновика по кнопке. Apple по умолчанию распознаёт источник сообщения; выбранный пользователем исходный язык сохраняется. Список языков и статусы пар запрашиваются у iOS, скачивание использует системную загрузку. Исключения проверяются до общего вызова провайдера, не только в списке чата. Распознавание короткого или неоднозначного текста может быть недостаточно уверенным.

Это изменения исходников, не включённые в build 139. Проверены точные шаблоны, fail-closed и метаданные; Swift/Apple SDK и физический iPhone ещё не проверены. Текущие нижеследующие разделы описывают прежнюю реализацию и её предыдущую проверку.

## Настройки и интерфейс

Прочее → отдельная группа «Перевод» → «Перевод сообщений» → «Настройки перевода». На странице находятся автоперевод, целевой язык, семь переводчиков, языковые модели Apple, API-ключи, исключённые языки и возврат скрытых панелей. Главный переключатель и автоперевод по умолчанию выключены, выбран Apple. Сохранённый OFF отличается от отсутствующего выбора; выключение не удаляет настройки или ключи. Родительская строка содержит провайдера в значении enum, чтобы его смена обновляла подпись через штатный diff списка.

Пункт контекстного меню «Перевести» появляется только при включённой функции и уверенно определённом языке, отличном от **языка приложения NagramiX**. Язык ОС не заменяет это сравнение. Русский интерфейс + английский текст дают пункт перевода; русский текст, только числа/эмодзи/ссылка и неопределённый язык — нет. Сохраняется штатный запрет этого действия в секретных чатах.

Для одного сообщения открывается нижнее окно с оригиналом, переводом, выбором языков, повтором и копированием. Копирование/выделение учитывают исходный `canCopy`. Закрытие отменяет подписку, смена языка или провайдера отсекает прежние callbacks. Тема, размеры текста и статусбар берутся из приложения; настройки не получают обои из нарисованного эскиза.

В обычной личной переписке, группе и канале используется штатная панель перевода. Для английского источника — `ENG · Перевести на Русский`, после включения — «Показать оригинал». Названия языков начинаются с заглавной буквы. В смешанной выборке без доминирующего языка выводится «АВТО», а не ложный ENG. Меню позволяет выбрать язык, исключить определённый язык, открыть переводчики и скрыть панель. Для «АВТО» исключение несуществующего общего языка не предлагается.

Включение, целевой язык и скрытие панели сохраняются отдельно по аккаунту, peer и thread; nil thread и 0 различаются. «Скрыть» не выключает уже активный перевод и не вызывает серверное скрытие. Возврат панелей не включает перевод в ранее отключённом чате. Настройки сервиса и собственные ключи общие для приложения.

## Провайдеры и бесплатный режим

Последнее уточнение пользователя реализуется следующей guarded стадией [translation_free_modes](TRANSLATION_FREE_MODES.md): **Google и Яндекс только бесплатно через интернет**, без полей ключей, чтения legacy Cloud credentials и платного fallback. Используются анонимные POST веб-служб; для Яндекса сначала получается сессия публичной страницы. Тексты не помещаются в URL. Ограничения или изменившийся сайт сохраняют оригинал и позволяют выбрать другой сервис. Это онлайн-перевод, офлайн Google ML Kit и словари приложения Яндекса не подключены.

Apple использует уже имеющийся `ExperimentalInternalTranslationService`/`TranslationSession` в iOS 18+. Страница подготовки языков вызывает настоящий `prepareTranslation()`. Нужны поддерживаемая пара языков и загруженные модели. При недоступности нет скрытого перехода на облачный сервис.

Gemini, ChatGPT и DeepSeek используют официальные HTTPS API с собственным ключом. Gemini может работать в бесплатной квоте подходящего проекта Google AI Studio, но и для неё нужен ключ. Другие сервисы применяют доступные аккаунту кредиты/тариф. Анонимный API этих трёх сервисов не подтверждён; бесплатный веб-чат не выдаётся за программный перевод. Пользователь одобрил отдельный [GPT-OSS · Бесплатно](TRANSLATION_GPT_OSS.md): модель GPT-OSS20B через Pollinations, без ключа, с собственной температурой и очередью по лимиту сервиса. Три прежние API-нейросети не подменяются.

У каждой нейросети редактируются модель и температура 0–2 с шагом 0,1. Температура означает вариативность, а не качество; отправляется только известным совместимым моделям, иначе UI сообщает об управлении моделью. Отдельные значения сохраняются без сброса прежней конфигурации и меняют revision. Для Google/Яндекса настроек ключа/температуры нет.

Ключи хранятся отдельно для каждого сервиса через Security/Keychain: `kSecAttrSynchronizable=false`, `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`. Не входят в UserDefaults, URL, prompt, отчёты или репозиторий. Ошибка записи/удаления не считается успехом. Сохранение ключа меняет revision настроек, старый ключ не используется как fallback.

## Перевод, форматирование и запись

Базовый путь включён guarded stage `message_translation` после `pip_native_entry`; стадия `translation_free_modes` обновляет четыре его helpers и добавляет Web helper; последняя `translation_gpt_oss` добавляет согласованный отдельный GPT-OSS. Он изменяет 11 существующих файлов через 52 операции, добавляет восемь Swift helpers в имеющийся TranslateUI и проверяет восемь неизменных входов. Единственная добавленная BUILD-зависимость — уже имеющийся Postbox, необходимый для локального атрибута перевода. Внешних библиотек нет. SHA/anchors/шаблоны/BUILD/пути/конфликты проверяются до записи.

Чатовый перевод использует штатные `ChatTranslationState`, history pipeline и `TranslationMessageAttribute`. При включённой функции премиальный серверный перевод не вызывается; применяется выбранный локальный/облачный сервис. При OFF прежняя штатная ветка сохраняется. Последние 32 сообщения служат ограниченной выборкой для определения языка; переводятся видимые сообщения и штатный небольшой запас вокруг них. Смена провайдера/ключа/целевого языка обновляет перевод видимой области, включая случай одинакового целевого языка.

На границах текстовых entities строится UTF-16 план фрагментов. Ссылки, упоминания, код, телефоны, пользовательские эмодзи и другие защищённые entities не переводятся; диапазоны форматирования пересчитываются по переведённым фрагментам. Оригинал сохраняется. Неполный/пустой ответ или недопустимый диапазон не записывается как успешный перевод. Фрагментный перевод на границах форматирования может влиять на качество формулировки; качество реальных моделей нужно оценить на устройстве.

Реализован автоматический перевод обычного входящего текста и подписей. Рекламные, исходящие, секретные, scheduled и специальные rich-документы не отправляются через новый автоматический путь. Автоперевод отдельных элементов опросов и аудиорасшифровок в этой реализации не добавлен; их нельзя объявлять проверенными. Ручной перевод текстового представления остаётся отдельным действием. Сообщения языка приложения, исключённого/неопределённого языка и нетекстовые фрагменты получают локальный исходный атрибут, чтобы штатный UI не ждал перевод бесконечно; внешнего запроса для них нет.

Перед записью повторно проверяются master/чат ON, revision сервиса/ключа, целевой язык и исходный текст с entities. Удалённое или отредактированное сообщение не заменяется старым результатом. Меняется только атрибут перевода; текст, автор, media, timestamps, группировка, thread и прочие метаданные сохраняются.

Облачный клиент использует ephemeral URLSession без дискового кеша/HTTP cookies и отклоняет перенаправления с API-ключом. Два активных HTTP запроса, ограниченная очередь, объединение одинаковых запросов и bounded memory cache с account/revision scope. Изменения настроек отсекают неразрешённые queued requests и отменяют ненужные активные; отмена не считается пользовательской ошибкой. Проверяются HTTP status, завершённость LLM-ответа, количество строк и лимиты размера. Ответы LLM принимаются только как JSON с массивом переводов, без исполняемых команд и инструментов.

## Проверки и следующий шаг

`scripts/validate_message_translation.py` проверяет точные выходы и восстанавливает предыдущие inputs в отдельной папке для прежних строгих round validators. Неизвестный drift не обходится. Есть положительное применение, повторное применение, missing/drift/anchor/hash/copy/path негативные входы без частичной записи.

Исполняются production settings, language policy, text plan, cloud codec/client, Keychain query bodies и весь runtime с явными границами Apple ML/Translation, Security, SwiftSignalKit delivery и Postbox DTO. Проверяются account/thread isolation, OFF, сохранение, endpoints/точный пользовательский ключ, HTTP ошибки, JSON/Unicode/entities, кеш/коалесцирование/отмена, stale revision/edit/target и сохранение оригинала. Негативные варианты без языкового/форматного/provenance guards должны падать.

Завершено: 160 проверок core/HTTP/политики, 26 actual runtime и 44 Keychain query в каждом debug/O — 230. Шесть отрицательных вариантов отклоняются в обоих режимах, 129 fail-closed случаев не оставляют частичной записи. Прежние round/refinement и scheduled/outgoing Swift-проверки повторно пройдены. Полная чистая композиция: все source validators и Swift parse PASS, 18 изменённых/новых native paths относительно предыдущего WIP, 313 модифицированных native всего, остальные 295 прежних модифицированных native побайтно сохранены. Исполняемые production-участки имеют те же SHA, что финальный исходник; последующая точечная правка выбора языка затрагивает только UI и проверена source/Swift parse.

Доказательства: `/workspace/.codex-validation-nagramix-translation/` (`verification.json`, `behavior.log`, `full-verification.json`, `full.log`). Проверки Linux не являются SDK-компиляцией, реальным Keychain, сетевыми вызовами оплачиваемых API или проверкой перевода Apple на iPhone. Не утверждать, что функция уже работает в опубликованном build 134. Опубликованная139предназначена для проверки провайдеров, загрузки языков, переключений, приватности, форматирования и анимации на физическом устройстве.

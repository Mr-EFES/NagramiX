# Пересылка своих одноразовых записей

**Исправление после113:** «Переслать» теперь выбирает одного адресата и открывает обычный чат с записью до Send; «Рассылка» сохраняет массовый выбор без сброса контактов при выборе вложенного канала/темы. [Актуальный контракт](TRANSFER_ROUTING_FIX.md). Новый dispatch — source_checked/native_compile_pending/device_pending; прежняя компиляция113 не подтверждает эту правку. Проверки владельца/local bytes/TTL/copier ниже сохранены.

Текущий статус на 21 октября: включено в Release 0.6.7 / build 113; Apple SDK compile и независимая проверка опубликованного пакета пройдены. Физическая приёмка новой версии ожидается. Предшествующие source-only proofs ниже описывают этап до этой сборки; актуальный итог — [RELEASE_STATUS](RELEASE_STATUS.md).

21 октября пользователь попросил добавить существующие «Переслать» и «Рассылка» для **собственных отправленных одноразовых голосовых и кружков**. Подтвердил, что новые сообщения тоже должны оставаться одноразовыми. Текст, чужие записи и прочие функции сохраняют прежнее поведение. Работа в main, без новой сборки.

## Поведение

- Пункты работают через существующие настройки контекстного меню: «Переслать» — один получатель, «Рассылка» — несколько. Дополнительного checkbox нет.
- Проверяются одновременно автор текущего аккаунта, исходящее направление, завершённая облачная отправка, одноразовый timeout и единственное вложение типа voice/instant video. Неизвестный автор, другой аккаунт, входящая запись, forward, pending/failed/scheduled, секретный чат и иной тип вложения не получают исключения.
- Создаётся новое сообщение с независимой локальной загрузкой и новым `AutoremoveTimeoutMessageAttribute(viewOnceTimeout, nil)`. Старый countdown, источник пересылки, reply и thread оригинала не переносятся; атрибуты голосового/кружка сохраняются. Каждый получатель получает новый одноразовый экземпляр. Обычная и тихая отправка поддерживаются.
- Для одноразовых копий доступны облачные личные чаты с обычными пользователями. Избранное, боты, группы/каналы, секретные и платные чаты не поддерживаются нативным режимом. Помимо фильтра списка повторно проверяются получатели после выбора через контакты/поиск и актуальные fees перед подготовкой отправки. Отложенная/«когда онлайн» отправка и native diversion в scheduled отклоняются, без превращения записи в обычную.
- Требуются полные локальные байты собственной записи. Проверка перед picker и повторно перед Send: regular file, ненулевой и ожидаемый размер; затем прежний staging фиксирует независимый файл. Нет запроса удалённого одноразового оригинала, открытия/потребления или нового автоматического сохранения. При отсутствии файла — существующая локализованная ошибка, без отправки. Уже исчезнувшие файлы не восстанавливаются.
- Разрешение определяется фактической одноразовой записью, а не текущим положением общего default. Выключение «Одноразовая запись медиа» после отправки не меняет тип старого сообщения. Настройка/ключ/fresh OFF и ручная кнопка «1» прежние.

Полученные одноразовые записи, обычный текст, архивные snapshots и их хранение, Фото/Файлы, скриншоты, Repost и нативная серверная пересылка не расширяются. Общий `nagramiXAllowsContentCopy` для сохранения прежний; исключение относится только к двум действиям новой отправки собственной записи.

## Интеграция

В существующем Core helper `NagramiXContentCopy.swift` добавлены отдельные проверки владельца/локального файла, optional account identity в preflight; UI preparation передаёт настоящий `context.account.peerId`. Нет новых зависимостей или изменений хранилища.

Поздний `ios/own_once_copy.py`/`own_once_copy_patches.json` идёт после archive persistence. Три полных SHA256 и 15 точных операций проверяются до записи: capability/builder/dispatch в ForwardMessages, меню и account-aware closure панели выделения. Builder по умолчанию без account identity не получает права на одноразовые записи. Копии обязательно идут через local staging и существующую отменяемую preparation; нативная пересылка ID оригинала не используется. Механика оплаты/тем/Send прежних обычных копий сохраняется.

Нативный enqueue переводит requested Autoremove в облачный Autoclear media timer, независимо от общего auto-delete чата. При media timer нативный upload пропускает cache reuse и задаёт ttlSeconds для нового uploaded document. Эти механизмы не переписаны.

## Проверки и ограничения

Полный overlay закреплённого Telegram-iOS13.0: 418 файлов, только пять целевых изменений и 413 побайтно прежних. Предыдущее исправление ожидания контактов сохранено. В `scripts/validate_own_once_copy.py` реальны production policy, builder, file staging, preparation, извлечённые menu/dispatch/mode/recipient выражения и native преобразование media timer. Postbox/Signal/UIKit/EnginePeer/network — управляемые границы теста; filter outgoing attributes проверен статически, в тесте conversion передаёт атрибуты без фильтрации. Это не симуляция настоящей доставки сервера.

- **147** новых проверок и **75** прежних protected-copy/export проверок в каждом режиме debug/optimized, warnings-as-errors.
- Владелец/другой аккаунт/входящие/ошибочные состояния, оба типа записи, меню, один/несколько адресатов, одноразовый attr без countdown, native cloud timer, разделение auto-delete, local identity/неизменные bytes, отсутствие remote fetch, отказ при eviction/truncation/directory и существующая ошибка UI. Проверены старые обычные/архивные копии, сохранение, отмена и файловый lifetime.
- Точный replay и **8 отказов без частичной записи**: reapply, missing/drift каждого из трёх входов, последняя несовпавшая точка. Swift grammar всех пяти файлов, Python AST, JSON и diff.

Proof `/workspace/.codex-validation-nagramix-own-once-copy/verification.json`, полный native tree `/workspace/.codex-validation-nagramix-prefer-ipv6/native-own-once-copy`. Статус **source_checked / native_compile_passed / device_pending**. Apple SDK compile и IPA проверены в Release 0.6.7 / build 113; физическая приёмка ожидается.

После отдельной команды на сборку проверить на физических iPhone: свой одноразовый voice и круг → один/несколько обычных пользователей → однократное потребление каждой копии; тихая отправка, отмена picker, исходный файл после очистки кеша, смена аккаунта. Входящие и обычный текст прежние; Repost отсутствует для одноразового оригинала. Проверить обход picker через контакты/поиск и отказ неподдерживаемых назначений, scheduled/when-online без деградации режима.

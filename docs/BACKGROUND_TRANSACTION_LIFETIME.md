# Завершения RUNNINGBOARD0xDEAD10CC при блокировке экрана

17октября пользователь предоставил два новых отчёта0.5.8/build94: закрытие через~71и41секунду после запуска, экран заблокирован11–14секунд. SIGKILL/RUNNINGBOARD3735883980 =0xDEAD10CC — завершение при удержании файловой блокировки во время приостановки процесса. Main находится в обычном RunLoop; это другой механизм, чем прежний camera watchdog0x8BADF00D. Активные frames Postbox/log не доказывают, какая именно база/файл удерживала блокировку. VM virtual size не является доказательством нехватки памяти. Полных dSYM94 нет; точный transaction callsite не символицирован.

В точном Telegram13.0 pin найден небезопасный lifecycle: inactive updateAccounts оставляет Postbox/StorageBox transactions enabled по внутреннему grace timer, а active branch считает ещё не запущенный BGContinuedProcessingTask ID разрешением выполнения. Expiration UI background task сначала освобождает assertion, затем закрывает/дренирует базу. Отдельно AppDelegate возвращает UIKit.invalid как будто созданную задачу. Эти пути позволяют транзакции пересечь suspension; отчёты не доказывают исполнение конкретной ветки на устройстве.

Последний apply_background_transaction_lifetime:2fullSHA/10точных замен. В inactive ветке transactions всегда false; active BGContinuedProcessingTask требует ID+Launched, explicit extension требует timer+действительныйtask. После фактического launch вызывается checkTasks для возобновления. UIKit.invalid возвращает nil. Wakeup/explicit expiration сначала очищает state и запускает штатный checkTasks, затем использует существующий updateAccounts barrier для Postbox и MediaBox.StorageBox всехаккаунтов перед endBackgroundTask. Late expiration старой UI задачи не сбрасывает новую. Новая background-wakeup задача создаётся только при remaining time >5секунд: нет повторного нулевого таймера, последние5секунд оставлены для drain. Foreground/audio/location/real tasks, все данные/SQLite recovery/schema/шифрование и сохранённые настройки прежние.

Не добавлены бесконечные background assertions, фоновые аудиозаглушки, main.sync/wait или удаление базы. Завершение уже выполняющейся транзакции остаётся штатным; при крайне долгом I/O истечение системного срока всё равно требует реального теста.

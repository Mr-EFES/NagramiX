# Приватность вместо общего режима невидимки

Актуально19октября: общий режим и отдельный экран удалены. Шесть независимых checkbox после «Сообщения»; server mode удалён. Fresh defaults: только скрытие активности ON, остальные OFF; сохранённый выбор не сбрасывать. Самостоятельное «Чтение по действию» скрывает прочтения до ответа/реакции. [Текущий контракт](PRIVACY_SETTINGS.md). Текст ниже описывает историческую интеграцию, текущие отличия перечислены в контракте. Новая native сборка и физический тест pending.

## Историческая реализация до объединения


Пользователь18октября попросил шесть функций по референсу Ghostgram и явно разрешил тестовый IPA после реализации. Отдельно подтвердил: автоматический офлайн нужен сразу при включении режима и при открытии приложения. Это разрешение относится к следующему тестовому IPA с новой функцией и подготовленной правкой PiP; GitHub Release отдельно не запрошен.

## Пользовательский сценарий

Настройки NagramiX → Функции → Приватность → Режим невидимки. Экран использует обычные ItemList-компоненты, тему/шрифт Telegram, многострочные подписи RU/EN и глобальный поиск. Общий переключатель по умолчанию OFF; все шесть опций выбраны. Выключение режима сохраняет отдельные ON/OFF, холодный запуск не сбрасывает выбор. Настройки действуют во всех аккаунтах этого приложения.

Правка19октября: в родительском разделе «Приватность» добавлены независимые [режимы прочтения](MESSAGE_READ_MODES.md), оба OFF по умолчанию. Явный local скрывает прочтения независимо от master и исключения ответа/реакции; явный server разрешает обычные прочтения открытого чата. Оба OFF сохраняют описанное ниже поведение невидимки. Остальные опции и сохранённый выбор не меняются. Изменения ещё не проходили native сборку и тест на iPhone; прежний IPA104 их не содержит.

1. Не отправлять прочтения сообщений: локальные счётчики/прочитанное обновляются штатно, серверные read-history/content receipts подавляются. Голосовые/одноразовые вложения сохраняют native playback, локальное потребление и сроки исчезновения.
2. Не отправлять просмотры историй: добавляется эффективное инкогнито поверх прежней отдельной настройки. Сохранённый выбор отдельной настройки не перезаписывается; старые просмотры не отзываются. Подтверждение просмотра, предупреждение об ответах/реакциях и native session snapshot сохранены.
3. Не отправлять онлайн: подавляются online keepalive. Если автоматический офлайн OFF, уже видимый статус истекает обычным способом; UI объясняет различие.
4. Не показывать набор/запись: фильтруются только исходящие typing/upload/record/emoji indicators. Входящие индикаторы и speakingInGroupCall сохраняются. Переключение пересчитывает текущую активность; до сетевого запроса политика проверяется повторно.
5. Автоматический офлайн: немедленный offline при активации/foreground через существующий account-presence manager, его очередь, timer и MetaDisposable. Для постоянного скрытия используется отдельная опция онлайн. Если пользователь отключил её, после разового offline штатный keepalive может возобновиться.
6. Прочитывать при ответе/реакции: отдельный scoped read для выбранного cloud peer и конкретного maxId. Немедленная успешная постановка сообщения в очередь разрешает чтение чата; scheduled/nil enqueue не разрешают его. Реакция читает только до выбранного сообщения, пустое снятие реакции не разрешает чтение. Stars reaction также учитывается. Глобальная приватность никогда временно не отключается. Автоматические прочтения секретных чатов через ответ не добавляются, сохраняя защиту native notification/Siri paths.

## Интеграция и сохранность

Foundation-only NagramiXGhostSettings расположен в существующем NagramiXMediaSettings, без UI/core циклов. Сохраняется один словарь с versioned key `nagramix.privacy.ghost.v1`, запись защищена lock. Собственное notification обновляет экран, presence и typing без перезагрузки чужих настроек.

Поздний `ios/ghost_mode.py` вызывается после прежних исправлений и PiP. План `ghost_mode_patches.json`:17полных SHA256 входов,63точных замен,2новых helper-файла. Все hashes/globs/замены/коллизии проверяются до первой записи. Секретное шифрование, transport, auth, схема Postbox, story approval/read-only gate, архив, запись, defaults, PiP и чужие callbacks не переписаны.

Read-state manager подтверждает подавленную операцию локально и не запускает серверную валидацию, которая при расхождении с намеренно непрочитанным сервером вызвала бы retry-loop. Consume/story workers также завершают пропущенную работу со штатной очисткой очереди. Форумы/топики/сохранённые диалоги имеют отдельные guards после локальных изменений. Приватная граница прочтения хранится в собственной preferences-записи того же Postbox, атомарно с локальным read и отдельно для каждого аккаунта/peer. После выключения режима validator сохраняет эту границу без retry-loop и без отправки старого receipt; новые обычные read за её пределом остаются штатными. При подтверждении сервером запись удаляется, исходящие прочтения продолжают обновляться. При выключении режима подавленные receipts не лежат в очереди для поздней отправки; последующие обычные прочтения снова работают штатно. Уже начатый сетевой запрос не может быть отозван как непрочитанный.

## Физический тест двумя аккаунтами

- Аккаунт A наблюдает статус/прочтения/набор, B использует новый IPA. Проверить все master/suboption ON/OFF и сохранение после закрытия приложения, повторной установки поверх и смены аккаунта.
- B читает обычный чат: у B счётчик исчез, у A нет прочтения. Проверить новые сообщения после прочтения, группы/топики, голосовые/кружки/одноразовые вложения, упоминания. Таймеры/плеер не зависают.
- Ответ B при readOnAction ON читает чат; реакция на более раннем сообщении — только до него. OFF сохраняет скрытые прочтения. Scheduled send, отмена, неуспешный enqueue и снятие последней реакции не разрешают новый read. Проверить другой открытый чат параллельно, сеть OFF→ON, отсутствие позднего replay после выключения невидимки.
- История: включить общий режим поверх отдельного инкогнито OFF/ON; закрыть и открыть просмотрщик. У A нет новой отметки B, ответы/реакции видны с прежним предупреждением. Выключение общего режима не меняет отдельный сохранённый выбор.
- Онлайн: включить режим, свернуть/открыть, дождаться нескольких30с интервалов. У A offline; отдельно autoOFF/hideOnlineON и autoON/hideOnlineOFF согласно описаниям. Другие клиенты B закрыть при измерении.
- Набор/запись/загрузка скрыты; отправка, звонок и speaking indicator голосового чата работают. Проверить включение/выключение во время набора и записи.
- Отдельно PiP по кнопке и свайпу на всех трёх форматах; новый IPA включает ранее подготовленный движок. Остальные защищённые сценарии — по прежней матрице iPhone.

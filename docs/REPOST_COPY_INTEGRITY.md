# Все части поста при отправке из редактора

**Состояние выпуска:** перенесено на Telegram13.2 и включено в успешный0.8.9/build185: `compile_passed / package_verified / owner_published / device_pending`. [SDK, IPA, hashes и релиз](RELEASE_STATUS.md); [приёмка на iPhone](DEVICE_CHECK_089.md) ещё ожидается. Далее — исходный контракт и история локальных проверок до публикации.

Владелец разрешил исправить только первую ошибку проверки от 6 ноября: потерю вложений при репосте со скрытием отправителя. Вторая ошибка с флагами отдельной подписи кружка и третья ошибка команды воспроизведения PiP остаются для следующих согласованных задач. Новая сборка, Actions, commit/push и публикация этой командой не разрешены и не запускались.

## Причина и исправление

Один исходный ID может создавать несколько `EnqueueMessage`: развёрнутые оплаченные вложения либо отдельный текст и сам кружок. Редактор сопоставлял исходные ID с плоским результатом через `zip`. Хвост отбрасывался; при нескольких исходниках последующий ID мог получить часть предыдущего поста.

В TelegramCore сохранён прежний плоский API `nagramiXCopyMessagesAsNew`. Общее внутреннее преобразование теперь также фиксирует полный диапазон результата каждого исходника. Новый `nagramiXCopyMessagesAsNewBySource` возвращает ID → массив всех его частей. Повторяющиеся ID этот API отклоняет до подготовки файлов; прежний плоский API продолжает принимать повторяющиеся входы, как раньше.

`ChatControllerNode` собирает одну упорядоченную выборку копируемых сообщений. Прежний приоритет источников сохраняется: защищённая разрешённая копия, собственная одноразовая запись, затем архив. Пересечение архивного и обычного поиска не готовит одно сообщение дважды. Все выбранные источники проходят одно преобразование, поэтому ключи альбомов не разрываются на границе этих категорий. В редактор добавляется весь массив каждого ID, затем следующий источник. Тема назначения переносится на каждую часть.

Сохраняются порядок исходных ID и вложений, подпись и её сущности, независимые альбомы и комментарий перед постом. Обычный репост с автором остаётся нативным `.forward`. Существующие ограничения назначения, режимы без звука и отложенной отправки, обработка тем и вызов нативного отправителя сохранены. В отправитель передаётся фактический полный массив; права и платный доступ к недоступным вложениям не подменяются.

Для платного адресата штатное подтверждение теперь получает реальное число исходящих сообщений после разворачивания поста, вместе с комментарием. Предварительная оценка по числу исходных ID в кнопке отправки для пересылаемого черновика пропускается. Сохраняются штатный экран, тариф, настройка предупреждения и возвращаемый им `postpone`; повторный callback покупки не отправляет пост второй раз. До согласия временные файлы принадлежат обратимой подготовке, отмена освобождает их, а commit выполняется перед передачей нативному отправителю. Перед продолжением после подтверждения проверяются прежние чат, черновик и тариф. Изменения отправителя, служебных атрибутов подписи кружка и PiP в эту задачу не включены.

## Стадия и проверки

Поздняя `repost_copy_integrity` применяется после `native_pip_baseline`: два replacements, 27 guards, четыре неизменяемых Before/After шаблона. Дополнительный guard фиксирует штатный `ChatControllerPaidMessage`. Все SHA, зависимости и пути проверяются до первой записи. Исторические canonical snapshots не переписываются. Совместимость старых валидаторов снимает новую стадию по точным SHA перед прежней цепочкой; новый validator запускается первым в workflow.

`validate_repost_copy_integrity.py` исполняет текущий production-копировщик, реальную файловую подготовку и полный изменённый блок сборки редактора. Проверяются составной пост из трёх вложений с реальными байтами; два поста с разным числом частей и текстом между ними; архив и обычное сообщение одного альбома; пересечение источников; отдельная подпись кружка и следующий исходник; тема; скрытие подписей; комментарий; нативный fallback; защитный guard; дубли; отсутствие частичного результата при позднем отказе.

В каждом режиме debug и `-O` проходят 48 новых проверок, 66 прежних payload-проверок на текущем общем преобразовании и 84 проверки временных сообщений. Дополнительно проверяются фактическая стоимость полного набора, отсутствие отправки до подтверждения, `postpone`, повторный callback, сохранение файлов до отправки, откат при отмене и отказ для некорректного платного количества. Одиннадцать отрицательных вариантов воспроизводят прежний `zip`, отдельное преобразование каждого исходника с разрывом альбома, преждевременную фиксацию диапазона, обратный порядок частей, перенос темы только на первую часть, потерю защитного guard, обрезанный диапазон, принятие повторяющегося ID, оплату по числу исходников, ранний commit и повторную отправку из callback. 68 loader сценариев отказа до записи и полный Swift parse включены в тот же обязательный validator.

Новых UI-строк нет. Strict localization без исключений проверяет 71 язык × 613 ключей, 112 файлов настроек/debug и 594 обращения; прежний runtime локализации выполняет по 43 621 проверке в debug и `-O`. Для локальных исторических snapshot-проверок при малом свободном месте использованы read-only hard links с копированием шаблонов между файловыми системами; ожидаемые SHA и сами проверки не ослаблялись.

Совместимость native PiP проверена прежними 37 checks/режим и его отрицательными вариантами. Актуальное обратное снятие новой стадии сохранило 13 точных native-блоков. Итоговая композиция прошла завершающий post-port семи файлов и штатный PostboxImportCheck. Полное SHA-сравнение 33 964 файлов выявило ровно два ожидаемых изменения; все прочие файлы и весь предыдущий полный source сохранены. Метаданные, Python AST и `git diff --check` пройдены.

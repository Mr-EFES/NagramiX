# Сохранение голосовых и кружков из удалённых сообщений

Текущее состояние: включено в проверенный IPA0.5.4/build88, **compile_passed / device_pending**. [Сборка, source SHA и пакет](RELEASE_STATUS.md). Записи о локальных проверках ниже описывают подготовку до этой нативной сборки; физическая проверка остаётся отдельной.

Новая правка после опубликованного build86: implemented / compile_passed / device_pending. Правка включена в build88; физическая проверка ожидается.

## Причина и поведение

Архивная ветка `ChatInterfaceStateContextMenus` очищала весь обычный список действий через `actions.removeAll()`, после чего восстанавливала только редактирование локальной копии, пересылки, выделение и удаление. Поэтому штатные действия сохранения исчезали.

В архивном меню перед остальными действиями теперь есть:

- «Сохранить звук» для аудио, удовлетворяющего той же базовой проверке, что и обычное меню: размер меньше1MB, длительность меньше60секунд, MIME MP3/OGG, отсутствие этого fileId в списке звуков. При нажатии применяются актуальные ограничения `NotificationSoundSettings` по длительности и размеру. Это именно штатная библиотека звуков уведомлений, как на референсе пользователя; экспорт аудио в «Файлы» здесь не вводился.
- «Сохранить видео» для кружка и обычного видео — запись в системную галерею с нативным запросом доступа Photos.

Оба действия учитывают текущую copy protection и `containsSecretMedia`. Для уже потреблённой архивной копии прежние expiry-атрибуты отсутствуют по существующему контракту хранения; новый код архивные flags/TTL/peers не изменяет. Отсутствие полных локальных bytes даёт понятную RU/EN ошибку; обращение к удалённому server message ID не используется. Меню обычных сообщений не изменено. Сохранение из просмотра через аватарку не вызывает активацию исходного чата или read receipt.

## Реализация

`apply_archived_media_save` последний helper: два full-SHA входа и три уникальные замены в памяти до записи. В архивный список добавляется `nagramiXArchivedSaveMediaActions`. Общая подготовка `NagramiXArchivedMediaCopy` используется также для явного сохранения: полные bytes получают независимый временный hard link, при недоступности link — copy fallback. Отправка, storage, playback и предыдущие архивные правки сохраняют прежние пути.

Голосовое: новый Core helper читает ограниченный файл на рабочей очереди, проверяет реальный размер до `Data`, загружает bytes через существующий `_internal_uploadNotificationSound`. У внутреннего uploader добавлен необязательный MIME-параметр с прежним default `audio/mpeg`: обычный импорт остаётся прежним, архивный OGG передаётся как `audio/ogg`, MP3-алиасы нормализованы к `audio/mpeg`. Native uploader сохраняет возвращённый cloud sound в существующем cache/list. Успех показывается по успешному результату, ошибка загрузки — отдельно. Нет `MessageReference` к удалённому оригиналу, нет перекодирования и новых сообщений в переписке.

Видео: на рабочей очереди полный файл закрепляется вторым link/copy в EngineTempBox URL с MP4/MOV-расширением. Затем на main queue штатный DeviceAccess запрашивает `.mediaLibrary(.save)`. Photos `PHAssetCreationRequest` добавляет video resource. «Видео сохранено» показывается только при success настоящего `performChanges`; отказ разрешения остаётся в штатном permission flow, ошибка записи сообщается отдельно. Временный URL освобождается после записи/отказа/ошибки; уже начатая запись Photos завершает cleanup даже после отмены подписки. Большое видео не читается целиком в RAM. Очистка архива после подготовки не удаляет закреплённые байты.

Core/UI helpers входят в уже существующие source globs; новые зависимости BUILD не нужны: TelegramUI уже зависит от DeviceAccess/Photos/SettingsUI и остальных используемых модулей.

## Проверки

Чистый proof `/tmp/nagramix-053-archived-save-proof`:449outputs против447 onboarding proof,442 побайтно прежних,5 целевых изменений и2 новых helpers. Три exact reversals восстанавливают оба native источника, включая обычный importer. Два source drift, rerun и конфликт helper отклонены до записи. Файловые проверки: двухступенчатые hard links и copy fallback переживают unlink архивного источника и освобождение builder; экспорт остаётся доступным, итоговая копия сохраняет bytes. Memory-mapped audio остаётся доступным после unlink. Это проверки файлового владения, а не вызовы iOS Photos/Telegram API.

RU/EN error keys уникальны; grammar5 изменённых Swift sources PASS. Предыдущий onboarding validator также PASS; source audit выполнен по pinned NotificationSoundList, SaveToCameraRoll, NotificationSoundSelection и SwiftSignalKit Queue. Python/metadata/diff checks PASS. Apple SDK/typecheck, реальное сохранение Photos и server round trip не выполнялись.

## Приёмка следующей сборки

1. Удалённое голосовое3–4секунды: «Сохранить звук» виден, добавляет правильное аудио в звуки уведомлений этого аккаунта, сообщение не отправляется собеседнику. Обычное голосовое работает прежним образом.
2. Удалённый кружок: «Сохранить видео» виден, галерея получает полноценное исходное видео. Проверить также обычное/удалённое видео, ориентацию и звук.
3. Сохранённые одноразовые voice/round после потребления: действия работают для локального архива; исходный server ID не запрашивается. Недоступный/неполный файл и нехватка места дают ошибку.
4. Превью через аватарку: сохранение не переводит источник в обычный активный чат, не отправляет read/отложенные реакции. Проверить действия из обычного чата тоже.
5. Разрешение Photos при первом запросе, отказе, повторном открытии и разрешении через Settings: нет ложного успеха. Ошибка Photos/неподдерживаемый контейнер тоже не показывает «Сохранено».
6. Очистить архив после запуска сохранения/во время permission prompt: закреплённый export остаётся рабочим. Уход с экрана/фон/блокировка/несколько быстрых действий не оставляют временные файлы после завершения.
7. Короткий/слишком длинный/большой звук, MP3/OGG, ограничение библиотеки, offline/возврат сети, ошибки сервера, повторное добавление, несколько аккаунтов: штатные ограничения, корректный список и честные ошибки. Ограничения stock eligibility сохраняются.
8. RU/EN, тёмная/светлая тема, VoiceOver, protected media: штатные подписи/иконки, ограничения не обходятся. Перед публикацией нужна нативная компиляция и физическая приёмка.

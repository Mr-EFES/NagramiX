# Засчитать просмотр одной истории

**Уточнение 28 октября:** успешный RPC с Bool false принимается как ACK по поведению TDLib, чтобы не показывать ложную ошибку уже засчитанного просмотра. Ошибки RPC/сети сохраняют повтор. [Последняя стадия и проверки](MEDIA_PRIVACY_FIXES.md). Прежнее требование положительного Bool ниже описывает отменённую проверку.

В просмотрщике NagramiX с включённым инкогнито меню показывает «Засчитать просмотр» вместо штатного «Скрыть просмотр». Явное нажатие разрешает отправку отметки только выбранной истории. Переключатель инкогнито и политика автоматических просмотров остаются прежними.

Во время запроса пункт меняется на «Засчитываем просмотр…» и недоступен для повторного нажатия. После положительного ответа Telegram отображается «Просмотр засчитан», а индикатор инкогнито для этой истории убирается. При ошибке или отрицательном ответе отметка локально не подтверждается, индикатор сохраняется, повторная отправка доступна. Переход к соседней истории сохраняет инкогнито. Состояние действия хранится в текущем экземпляре просмотрщика по account/peer/story, без новых настроек и постоянного списка исключений.

Обычный просмотр сохраняет штатное меню Telegram. Собственные истории и прямые эфиры не получают новое действие. При известном активном серверном Premium Stealth Mode вместо отправки показывается пояснение: нужно дождаться его завершения. Серверный режим нельзя выключить только для одной истории; приложение не отключает его для аккаунта.

## Реализация

Guarded stage `story_explicit_view` применяется после `round_video_page`: семь изменённых файлов, один Foundation helper, пять guards и три шаблона. Встроенная модель выбора получает точный ID из snapshot истории, а shared-состояние принадлежит конкретному StoryContainerScreen. Проверки текущего account instance, story ID, модели просмотрщика, центрального положения и закрытия экрана не позволяют устаревшему меню отправить другую историю. UUID запроса защищает от повторов и поздних ответов. UI-изменения после RPC доставляются на main. Последующий `story_download_quality` меняет только snapshot для скачивания; его точный итоговый SHA учитывается валидатором этой функции.

Новый явно названный engine-метод вызывает только `stories.incrementStoryViews(peer, [id])`. Штатный `stories.readStories(max_id)` отмечает все истории до указанного ID и поэтому здесь не используется. Не изменяются maxReadId, очередь синхронизации прочтений, глобальные privacy-настройки, approval/cancel/read gates и сохранение историй. Guards защищают неизменённые StoryChatContent и ManagedSynchronizeViewStoriesOperations, а проверка сравнивает тела прежних методов до/после.

Источники: [incrementStoryViews](https://core.telegram.org/method/stories.incrementStoryViews), [readStories](https://core.telegram.org/method/stories.readStories), [API историй](https://core.telegram.org/api/stories). Выбран точечный запрос, который штатный клиент уже использует для просмотров закреплённых историй. Положительный Bool подтверждает RPC; видимость записи в списке зрителей требует проверки на реальном сервере. Инкогнито не удаляет уже отправленные просмотры и не управляет другим клиентом.

## Проверки и приёмка

`scripts/validate_story_explicit_view.py --source <native>` проверяет итоговые SHA, обе ветки меню, локализацию RU/EN, ограничение запроса одним ID и сохранение автоматических read/approval/save guards. Он также проверяет отсутствие частичных записей при input/template/anchor/output/path/collision drift и повторном применении stage.

Дополнительные `--swiftc <compiler> --upstream <pinned-source>` запускают production Foundation-модель, извлечённые методы меню, engine wrapper и core-функцию с настоящим SwiftSignalKit в debug и `-O`. Сеть, Postbox и UIKit представлены тестовыми границами. Проверены pending/ACK/failure/retry, поздние ответы, account/peer/story/session isolation, устаревшее меню, закрытый/нецентральный экран, серверный stealth, свои/некорректные ID и отсутствие peer. Полная чистая overlay-цепочка и Swift parse проходят; доказательства в `/workspace/.codex-validation-nagramix-story-explicit/`.

Статус: source_checked / native_compile_pending / device_pending. Actions, SDK, IPA и публикация этой задачей не запускались.

На двух аккаунтах проверить обычные, закреплённые и открытые по ссылке истории: без нажатия отметки нет; после нажатия появляется только выбранная история; соседние остаются скрытыми. Повторить с потерей сети, быстрым перелистыванием, закрытием просмотрщика и Premium Stealth Mode. Проверить обычный OFF-режим, сохранение, ответы/реакции и доступность длинных подписей.

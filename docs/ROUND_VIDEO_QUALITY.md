Реализация в исходниках после0.7.1/build127: source_checked / native_compile_pending / device_pending. Опубликованный IPA не менялся.

В «Функции» → раздел кружков добавлен выключенный по умолчанию переключатель «Качественные кружки». После включения появляется «Настройка кружков» с подписью выбранного уровня под названием: Стандарт, Высокая или Максимум. Аннотаций в основном списке нет.

Внутри три раздела: качество480×480/Стандарт/1,2Мбит/с,512×512/Высокая/1,4Мбит/с,640×640/Максимум/1,5Мбит/с; частота30/60кадров/с; кодекH.264/Стандарт илиHEVC/Эффективное сжатие. Строки качества показывают FPS, фиксированный битрейт и кодек. Слайдера битрейта нет. Выбор сохраняется при перезапуске и выключении функции; исходные значения480/30/H.264. OFF сохраняет штатную запись.

При ON используется отдельный путь CameraNeo/hdBilinear с одной камерой и штатным переключением передней/задней камеры. Видеокадры, pool, размеры writer и возвращаемого результата получают единый snapshot Camera.Configuration. Реальные capture formats выбираются по разрешению/NV12/FPS, а не по одному encoder hint. Для беспрерывного переключения камер проверяется поддержка выбранного режима обеими позициями. Если60FPS недоступны, сохраняется30FPS с теми же качеством/битрейтом/кодеком и однократно показывается уведомление о причине. Предупреждающих подписей в настройках нет. Проверка относится к форматам камеры, не к отдельным пропущенным кадрам и не является гарантией60кадров при любой температуре/нагрузке.

OFF не меняет выбор штатного legacy/Neo pipeline, его FPS, битрейты и размеры. ON явно выбирает собственный Neo-путь независимо от экспериментального выбора штатной камеры; dual-camera при этом выключена. Ошибка аппаратного HEVC encoder проходит через native writer failure, без скрытой замены кодека. Физическая совместимость HEVC ожидает проверки.

Snapshot [разрешение,FPS,кодек] сохраняется в новом optional поле MediaEditorValues и JSON resource adjustments. Все native copy/update конструкторы его переносят. При обрезке/отложенной конвертации export читает этот snapshot, а не текущие UserDefaults. Неизвестный/отсутствующий snapshot оставляет штатный export. Новые необязательные данные не меняют формат прежних записей.

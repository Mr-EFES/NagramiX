# Единая подготовка копий и получатели из поиска

Актуальное согласованное поведение после физической проверки0.8.8 описано в [COPY_DELIVERY](COPY_DELIVERY.md). Ниже сохранён исторический контракт стадии `transfer_consistency`; её прежние OFF-gates, promotion выбранных строк и подтверждение только enqueue заменены поздней `copy_delivery`.

Исходная правка для выпуска 0.8.8 по видео6884843030437820600.mp4. В опубликованной IPA0.8.7/build173 её нет. Новая личная команда разрешила SDK/Actions/IPA/commit/push и публикацию0.8.8; текущий статус в RELEASE_STATUS.

На видео одна из отправок остаётся с ошибкой и действием «Повторить». По изображению нельзя установить ответ сервера или подтвердить единственную причину ошибки. В исходниках установлены отдельные воспроизводимые проблемы: single-copy уходил в другой draft/send путь, чем рассылка; поисковые получатели намеренно исключались из `foundPeers` при copy selection; multi-send не обеспечивал сохранение всех выбранных peer-records до Engine lookup/enqueue. При отсутствии записи адресата native enqueue не может штатно создать сообщение и включить новую переписку в список чатов.

Поздняя стадия `transfer_consistency` после `editor_attachment_delivery` меняет четыре TelegramUI-файла, с21 SHA-guard на неизменяемые API и зависимости. Старые canonical snapshots не изменяются.

- «Переслать» и «Рассылка» используют один существующий `NagramiXRecipientCopyBatch`, полную подготовку файлов и общий commit. Отличие — максимум один адресат для «Переслать». Выбранный контакт остаётся в окне со штатной кнопкой отправки; source IDs больше не переносятся в отдельный single-copy черновик. Политики Free Content ON/OFF, временных сообщений, неизвестного ответа викторины, оплаты, расписания, доступности файлов и допустимых типов сохраняются. Серверный репост остаётся штатным forward с прежними правами.
- Заголовок задаётся по действию: «Репост», «Переслать», «Рассылка», через существующие три локализованных свойства. Название сохраняется при переходе к локальной копии и загрузке полной rich-страницы. Временный репост с ранее утверждённой подписью автора передаёт подготовленный объект, не перезагружает исчезнувший оригинал и сохраняет заголовок «Репост».
- Найденные контакты входят в `foundPeers` и `selectedPeerMap`, остаются видимыми при переключении «Чаты»/«Контакты». Одинаковые адресаты не дублируются. Ограничение одного получателя проверяется и в поиске, и в callback вложенного picker. Выбранная тема сохраняется также при работе из вкладки контактов.
- Перед запросом fees/rendered peers и enqueue выполняется барьер `context.engine.peers.ensurePeerIsLocallyAvailable` для выбранных адресатов и связанных записей `peerMap`. Это существующий TelegramEngine API, без нового прямого Postbox-доступа в UI и без изменения allowlist. Последующая штатная транзакция enqueue включает новый cloud-user чат в root при первом сообщении. Перезапуск приложения и искусственная перезагрузка списка не требуются. Существующая архивная переписка не перемещается в root.

Дополнительная проверка перед повторной сборкой0.8.8 по сообщению о «мёртвой» кнопке в0.8.7: actual sendMessage callback и native requestSend bridge включены в Swift fixture. Кнопка для непустого выбора передаёт всех адресатов, текст/entities, forward options и режим ровно один раз; пустой выбор не отправляет. Проверены обе вкладки и single/broadcast. Полный copy builder отдельно проверяет самостоятельное видео с подписью/entities и полными локальными байтами, включая обычный открытый источник. Эта версия уже содержит соответствующие source fixes transfer_consistency/editor_attachment_delivery; дополнительных предположительных изменений в production-путь не добавлено. Тесты не обещают доступ к отсутствующим на устройстве/сервере байтам и не подменяют неподдерживаемые объекты текстом.

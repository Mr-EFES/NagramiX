# PiP Ghostgram в NagramiX

Этот документ описывает предыдущую стадию. Актуальная реализация после 0.8.4 и новая команда пользователя — [SYSTEM_VIDEO_PIP](SYSTEM_VIDEO_PIP.md): предварительная подготовка текущего владельца, KVO готовности и завершение AVKit. Ниже сохранён контракт прежнего опубликованного кода.

Источник: [ichmagmaus111/ghostgram](https://github.com/ichmagmaus111/ghostgram/blob/df95ba566c5f25a8f36de2b703bf070ca97c54ba/submodules/GalleryUI/Sources/Items/UniversalVideoGalleryItem.swift), коммит `df95ba566c5f25a8f36de2b703bf070ca97c54ba`, лицензия GPL-2.0 согласно LICENSE исходного репозитория.

Контроллер `NativePictureInPictureContentImpl`, его делегат, методы настройки, кнопки и возврата, обработчики центральности и видимости, заглушка и её раскладка перенесены из исходника Ghostgram. Валидаторы проверяют совпадение сохранённых блоков. Кнопка панели вызывает тот же метод через `controllerInteraction`, как в Ghostgram. Свайп вверх запускает PiP, вниз закрывает видео. Единственная привязка к настройкам клиента: вызов `GGGalleryHooks.allowsSwipeToPictureInPicture` заменён чтением сохранённой настройки NagramiX. Остальные возможности Ghostgram в приложение не переносятся.

Стадия `ghostgram_pip_cleanup` удаляет файлы прежних `NagramiXNativePlayerPiP` и `NagramiXNativePlayerPiPSwipe`, адаптеры жестов в pager/item, вспомогательные методы получения слоя и отдельные состояния старого PiP в MediaManager и GalleryController. Восстановлены исходная иерархия галереи, альтернативное закрытие, переходы, возврат из overlay и клавиатурная команда Ghostgram. Из активного пути удалены собственная подготовка PiP, ожидания/таймауты, передача позиции, кастомные фильтры и обработчики возврата. Исторические `.inc` и манифесты прежних стадий остаются входами воспроизводимой цепочки overlay и не являются активными реализациями приложения.

Перенос намеренно сохраняет поведение указанного `main`: `setupNativePictureInPicture()` вызывается кнопкой при отсутствии контроллера, а свайп использует уже существующий контроллер. Отдельной подготовки контроллера перед первым свайпом в этом исходнике нет; гарантировать запуск первым свайпом по данному коду нельзя. Пользователь потребовал точный перенос без собственных дополнений. Отдельный загрузчик не используется: PiP получает sample-buffer слой текущего UniversalVideoNode.

Пройдены три валидатора переноса/удаления, восстановление предыдущей цепочки и проверка layout поворота, синтаксический разбор 12 Swift-файлов и Python, `git diff --check`. Отдельно проверен отказ до любых записей/удалений при изменении BUILD или файла старого контроллера. Текущий main Ghostgram повторно сопоставлен с зафиксированным исходником.

SDK-сборка 160 обнаружила два остатка прежней интеграции: дубликат `moreButtonImage` и `@available(iOS 15.0, *)` на всём классе галереи. Стадия `ghostgram_pip_compile_fix` удаляет их, сохраняя исходные проверки доступности Ghostgram и аннотацию его отдельного AVKit-контроллера. Проверка уникальности глобальных констант и отсутствия лишней аннотации выполняется до нативной компиляции. Чистая Apple SDK-сборка 0.8.4/build162 пройдена; физический iPhone остаётся device_pending.

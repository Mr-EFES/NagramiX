# Выбор автора без восстановления истории

Задача владельца: действие «По автору» выделяет сообщения реального автора в текущей переписке. Оно не возвращает уже удалённые посты. При включённом показе удалённых сообщений выбираются также сохранённые локальные копии, доступные в обычной истории. При выключенном показе архив не участвует.

## Причина восстановления

В опубликованном исходнике `NagramiXAuthorSelection.swift` сначала обходил существующий Postbox, затем запрашивал всю доступную серверную историю или поиск автора. Найденные сообщения сохранялись через `transaction.addMessages(... location: .Random)`. В результате само выделение могло вернуть в локальную историю сообщения, ранее удалённые только в этом клиенте. Это подтверждается исходником, а не сетевым журналом конкретного аккаунта.

## Исправление

Поздняя guarded стадия `author_selection_no_restore` заменяет ровно два файла после итогового переноса Telegram 13.2. Исторические snapshots не переписываются.

- Helper обходит только существующие локальные сообщения Postbox последовательными страницами по 200, без общего лимита. Поддерживаются обычные cloud, local, secret incoming и ephemeral local namespaces; scheduled и quick reply не смешиваются с обычной историей.
- Страница без сообщений нужного автора не останавливает обход. Сохраняются реальный `message.author.id`, текущий peer/thread и существующая локальная история прежней группы при миграции супергруппы. Отсутствующий peer и отсутствие прогресса индекса завершаются ошибкой.
- Серверных запросов, загрузки результатов поиска, создания StoreMessage, изменения peers или `addMessages` в helper нет. Последняя read-only транзакция исключает ID, удалённые во время пагинации.
- UI добавляет локальные архивные ID только при включённом показе удалённых и в обычной истории. После подтверждения удаления голосового черновика повторно проверяются существующие live ID и текущая видимость первоначально выбранных архивных копий. Удалённые за время подтверждения копии не возвращаются; новые копии не добавляются в уже подтверждаемый набор.
- Сохранены generation, weak-self, peer/thread, отмена и native selection state. Права удаления, подтверждение, undo, альбомы и двухэтапное удаление архива не меняются. Выбор не вызывает удаления или восстановления.

Обход теперь выбирает все существующие в клиенте сообщения автора; сообщения, доступные только на сервере и ещё отсутствующие в Postbox, этим действием не загружаются. Это необходимая граница read-only выбора: выделение не должно материализовать очищенную историю.

## Проверки

`scripts/validate_author_selection_no_restore.py` получает точный source checkpoint непосредственно после этой стадии. Дальнейшие задачи меняют часть его зависимостей, поэтому на последнем полном дереве нужна точная обратная проекция поздних стадий либо исходный checkpoint, а не ослабление SHA.

Исполняются целиком реальные тела Core-helper и UI-обработчика «По автору». Адаптеры ограничивают Postbox/signal queue и UIKit; сеть намеренно отсутствует в API тестовой границы. Проверяются 650 сообщений, страницы чужого автора, namespaces, текущая тема и миграция, удаление во время обхода, повторный выбор, read-only история, archive ON/OFF, изменение настройки и удаление во время подтверждения, устаревшие callback, уход контроллера и пустой результат. Пройдены 34 production checks в каждом debug/-O, 22 исполнения семантических отрицательных вариантов и 40 fail-closed проверок. Отрицательные варианты завершаются ожидаемой проверкой поведения; drift/missing/replay/manifest corruption отклоняются до первой записи. Полные два Swift-файла прошли parse; Python compile и diff check также пройдены. Отчёт восстановления: `/workspace/scratch/recover-author/validation.json`.

Новых UI-строк и пользовательских ключей нет; переводы не меняются. Apple SDK и физическая проверка на iPhone остаются отдельными этапами. Восстановление этой задачи по согласованным требованиям не является подтверждением побайтного возврата исчезнувших файлов прежней среды.

Команда проверки:

```bash
python3 scripts/validate_author_selection_no_restore.py \
  --source /path/to/author-stage-checkpoint \
  --swiftc /path/to/swiftc \
  --report /path/to/validation.json
```

# Оригинальное видео как медиа, OFF по умолчанию

**Дополнение100:** [галерея: исходные байты, HFR/optional preview и обычный плеер](ORIGINAL_VIDEO_GALLERY.md). Предпочитается исходный Photos video resource; старые исключения HFR/thumbnail ниже — история предыдущих стадий.

Статус: `source_checked / native_compile_pending / device_pending`. Это правка после опубликованного 0.9.7/build213; его IPA не заменяется. Новая сборка запускается по отдельной команде.

Действующий контракт владельца:

- При первом запуске без сохранённого значения «Видео без сжатия» выключено. Отправка из «Галереи» использует обычную обработку и выбранное качество Telegram.
- При включении подходящее неизменённое видео передаётся исходными байтами как видеомедиа с превью и штатным плеером. Автоматической отправки документом из-за MIME больше нет.
- Явный выбор ON/OFF сохраняется при перезапуске. Ключ `nagramix.videos.original`, stable ID138 и название настройки прежние.

Были подтверждены две причины расхождения: инициализатор настроек по-прежнему имел `originalVideos: Bool = true`; полный Photos-экспортер добавлял `.Video` только для `video/mp4` и `video/quicktime`. Собственная таблица Telegram содержит `m4v → video/m4v`: такой исходник терял атрибут видео, `file.isVideo` становился false, а нативный загрузчик устанавливал `force_file`. Предыдущая проверка этапа70 подтверждала переключение маршрута со stub-экспортером и не выполняла этот MIME-участок полного производителя. Поэтому она не подтверждала соблюдение всего нынешнего контракта.

Этап78 `original_video_media` после `story_avatar_visibility` меняет только `NagramiXMediaSettings.swift` и `LegacyMediaPickers.swift`. Значение инициализатора по умолчанию стало false. Экспортер проверяет `PHAsset.mediaType == .video` и для ресурса `.video`/`.fullSizeVideo` всегда создаёт обычную `.Video` с размерами и длительностью исходника. Реальные имя, MIME, данные, превью, обложка и существующее владение временным файлом сохраняются. Нативный `force_file` остаётся снятым, нативная строка чата выбирает видеомедиа. Прямая отправка «Файлом» сохраняет свой отдельный маршрут.

Перекодирование, remux и изменение исходного MIME на выдуманный MP4 не добавлены. `.supportsStreaming` определяется прежним ограниченным BMFF-парсером: для `moov` после `mdat` потоковый старт не обещается. Видеомедиа и потоковое воспроизведение — разные свойства; большой исходник может требовать загрузки. Совместимость кодека и реальное поведение сервера/устройства проверяются отдельно.

Путь OFF, битрейт/пресеты Telegram, маршрутизация, подписи/entities, спойлер, обложка, группировка и ошибки остались прежними. Содержательные правки и специальные типы (mute/GIF/Live Photo/HFR/таймер/платные медиа/кружки/камера) сохраняют необходимые штатные пути обработки, описанные в [предыдущем контракте](ORIGINAL_VIDEO_MODE.md). Другие функции, в том числе плеер, запись звука/кружков и восстановление аватары, не менялись.

Проверка:

```sh
python3 scripts/validate_original_video_media.py \
  --source <native> --swiftc <swiftc> --report <json>
```

Первая регрессия выполняет целиком production-экспортер, `FileHandle`-запись чанков, BMFF-парсер, pin и отложенную передачу в MediaBox на настоящих синтетических H.264/AAC MP4/MOV. Проверяются байты до/после отложенного перемещения и disposal, метаданные, M4V/UTI-fallback, `.fullSizeVideo`, безопасное имя, превью/обложка, отмена и неверный/пустой ресурс. `isVideo`, `isInstantVideo`, флаги и условие нативного `force_file` извлекаются из реальных исходников. Photos, UIKit и MediaBox/API-модели представлены явными границами. Тестовые фильмы сгенерированы локально из FFmpeg lavfi; пользовательских видео в Git нет.

Вторая регрессия выполняет фактические current/update настроек, context wrapper, original preparation и native `.compress`-ветку, проверяя OFF/ON/OFF, отсутствие original Photos export при OFF, snapshot режима, редактированные/специальные случаи и отмену. Photos/конвертер — явные границы; она не выдаётся за измерение размера сжатого видео. Настройки тестового процесса восстанавливаются после проверки. Прежний default и реальный прежний MIME-whitelist должны проваливать проверки.

Ранний preflight дополнен проверкой полного экспортера с настоящими UIKit/Photos/UTType на iPhoneOS arm64/iOS15; эта проверка требует macOS. На Linux выполняется реальная компиляция модуля настроек, runtime с явно указанными границами и Swift parse, а Apple SDK успех не объявляется. Регрессии обязательны до длинного overlay и после применения этапа. Итоги — [ORIGINAL_VIDEO_MEDIA_CHECKS.json](ORIGINAL_VIDEO_MEDIA_CHECKS.json).

На iPhone: свежий запуск → OFF; отправить один и тот же обычный ролик OFF/ON/OFF. При OFF сравнить со штатным Telegram при том же качестве. При ON проверить карточку видеомедиа, плеер, MP4/MOV/M4V, обложку/подпись/альбом и SHA256 основного скачанного ресурса относительно выбранного Photos-оригинала. Повторить после перезапуска, с iCloud, отменой и явной отправкой файлом. Серверный byte roundtrip и физическая приёмка остаются pending.

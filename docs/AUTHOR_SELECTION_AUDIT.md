# Анализ выбора и удаления сообщений автора

Актуальная интеграция перенесена на Telegram 13.0; [аудит миграции](TELEGRAM_13_MIGRATION.md). Ранее указанные результаты №79 и локальных отдельных проверок относятся к прежней базе; новый нативный результат фиксируется отдельно.

2026-10-07. Анализ предыдущего опубликованного IPA №72 и закреплённой базы Telegram-iOS 13.0 (`f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`). Пользователь в целом положительно оценил физическую проверку предыдущей версии; сообщает два сбоя этой функции. Остальной функционал сохранять. Анализ проведён перед реализацией. После согласования пользователь разрешил исправление этой функции, а затем отдельно разрешил сборку и публикацию предыдущего выпуска.

## Сообщение пользователя

- В группе собственные и чужие сообщения автора выбираются и считаются. Пересылка и жалоба доступны. Корзина для чужих сообщений предлагает очистку кэша вместо удаления.
- В личном чате собственные сообщения автора выбираются, сообщения собеседника через «Выделить от автора» не выбираются. Одиночное входящее сообщение вручную выбирается и даёт штатное удаление у себя / у обоих.

## Проверено в исходниках предыдущего опубликованного IPA

1. `ios/apply_features.py`, обработчик `selectMessagesByAuthor` (строки 3752–3805): для всех типов чатов используется один `searchMessages(.peer(... fromId: authorId ...), query: "", limit: 100)` с пагинацией. В итоговый выбор передаются только ID; загрузки найденных сообщений в Postbox нет. Результат также объединяется с локальным архивом, если в нём есть сообщения этого автора.
2. Штатный `TelegramCore/.../SearchMessages.swift`: `mergedState` создаёт `locallyRenderedMessage` для выдачи, но не вызывает `transaction.addMessages`. RPC-ошибка поиска преобразуется в `.single(nil)`; отсутствующий результат далее превращается в `completed: true` с пустыми сообщениями. NagramiX завершает такой выбор без сообщения об ошибке. Официальный messages.search допускает SEARCH_QUERY_EMPTY/FROM_PEER_INVALID и другие ошибки. Точный ответ сервера в личном чате пользователя без журнала запроса не установлен; нельзя утверждать, что from_id запрещён во всех личных чатах.
3. Штатный `TelegramUI/Sources/ChatInterfaceStateContextMenus.swift`, `chatAvailableMessageActionsImpl` (2487–2811): права считываются по объектам сообщений из EngineData/Postbox или явно переданному словарю. Для отсутствующего сообщения остаётся пустой набор прав на удаление. Итог — пересечение прав всех выбранных сообщений. Даже один найденный поиском, но не загруженный ID может убрать удаление для всего набора.
4. Штатный `Chat/ChatControllerLoadDisplayNode.swift` (1847–1863): корзина вызывает `presentClearCacheSuggestion`, когда нет ни `.deleteLocally`, ни `.deleteGlobally`. Это действующий штатный fallback, не новый диалог NagramiX.
5. `ChatMessageSelectionInputPanelNode.swift` (465–480): в обычном чате корзина остаётся видимой и может быть активной без прав на удаление (`!actions.disableDelete`). Потому значок корзины сам по себе не доказывает доступность удаления.
6. Права различаются по типу чата. В обычной группе `TelegramGroup` есть локальное удаление; глобальное чужих — creator/admin. В супергруппе `TelegramChannel` входящие чужие сообщения требуют `.deleteAllMessages`; локальное удаление отдельных чужих сообщений этот native путь не предлагает. В личном чате `TelegramUser` предусмотрены `.deleteLocally` и разрешённое конфигурацией глобальное удаление входящих, с исключениями для ботов и специальных сообщений. Отсутствие прав в супергруппе нельзя исправлять принудительным добавлением флагов.
7. Проверен существующий `engine.messages.getMessagesLoadIfNecessary` / `LoadMessagesIfNecessary.swift`: загружает отсутствующие сообщения и сохраняет их через `transaction.addMessages(... location: .Random)`. Для будущей интеграции нужны ограниченные партии, проверка фактически полученных ID и обработка удаления/ошибки, без вызова с пустым массивом.

## Выводы и предлагаемый объём исправления

- Личный диалог: обеспечить выбор обеих сторон, с проверкой настоящего `author.id`. Для надёжного полного выбора использовать страницы доступной истории личного чата (`messages.getHistory` уже есть в закреплённой базе), без зависимости от пустого текстового поиска по отправителю. Не ограничиваться видимыми/кэшированными сообщениями, одной страницей или 300 сообщениями. Пустой результат, отказ сети и отмену различать; при сбое не показывать частичный результат как полный.
- До передачи ID штатной панели загружать необходимые cloud-сообщения штатным механизмом, небольшими партиями. Повторно проверить чат, ветку, автора и набор после загрузки; сохранить generation/cancellation/lifecycle guards. Архивные сообщения не выдавать за существующие серверные, их локальные действия сохранить.
- Удаление оставить штатным, с подтверждением и проверкой прав. В личном чате — доступные «у меня» / «у обоих»; в группах — только разрешённые Telegram действия. Не заменять удаление очисткой всей истории/автора и не обходить права администратора. Когда прав действительно нет, не маскировать очистку кэша под удаление; предложить понятное объяснение и отдельное явно названное действие кэша, если оно нужно.
- Не менять темы, русский запуск, прокси, кружки, Stories, контакты, ширину постов и пересылку. Дальнейшие изменения этой функции требуют отдельной задачи.

Это анализ кода, не runtime-тест личного аккаунта.

Пересылку и жалобу проверить как регресс. На этапе анализа код не менялся. Текущее исправление описано ниже; эта функция сохранена без изменений в текущей задаче тем.


## Внесённое исправление

Добавлен `ios/Sources/TelegramCore/NagramiXAuthorSelection.swift`: страницы доступной истории личного cloud-чата, author search в группах/каналах, native thread/saved-dialog параметры и предыдущая группа мигрированного чата. Общее количество не ограничено. Сообщения фильтруются по реальному автору, peer и ветке; selected ID берутся после штатного сохранения StoreMessage/peers в Postbox. Используется уже полученная страница, дополнительная повторная загрузка тех же ID не нужна. Медиаконтент не скачивается. Последняя проверка отбрасывает ID, исчезнувшие из базы во время операции.

Сетевой отказ/FloodWait/таймаут30s и отсутствие прогресса offset завершают операцию ошибкой, без применения частичного выбора. Пустой успешный результат получает отдельное уведомление. UI callback сохраняет generation/peer/thread/cancellation/voice-discard guards и прежнее объединение с архивом. Локальный архив не записывается в Postbox и его действия не меняются. Helper не предназначен для серверного обхода истории секретных чатов.

Корзина продолжает использовать native права/подтверждения/undo/bans; никаких принудительных delete-флагов или clear-all-history вызовов не добавлено. Только для неизменённого набора, полученного «Выделить от автора», отсутствие прав показывает понятный отказ. Кэш предлагается отдельной явно подписанной кнопкой. При обычном ручном выборе прежний Telegram fallback сохранён.

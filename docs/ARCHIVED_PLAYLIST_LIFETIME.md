# Воспроизведение сохранённого кружка без ложного закрытия

Видео пользователя длительностью 28,733 секунды разобрано обзорными кадрами и подробным интервалом 1–4 секунды. При открытии удалённого кружка появляются повторные изменения состояния панели плеера и смещается соседний текст. Запись сама по себе не раскрывает причины каждого касания; первопричина ниже подтверждена исполнением production-кода. Личные кадры и переписка в Git не входят.

## Причина

Удалённое сообщение открывается штатным `SharedMediaPlayer` через `PeerMessagesMediaPlaylist.recentActions(message)`, поскольку сохранённая копия не находится в Postbox. Маркер `NagramiXArchivedMessageAttribute` прямо обозначает такое синтетическое сообщение.

Но `PeerMessagesMediaPlaylist.updateState()` затем подписывался на исходный ID через `engine.data.subscribe(Messages.Message(id:))`. Для уже удалённого оригинала движок возвращает `nil`. Если ответ приходит после установки обработчика, запускается цепочка:

```text
Postbox: оригинал отсутствует
→ playlist.currentItemDisappeared
→ SharedMediaPlayer.cancelled
→ MediaManager: stop(), voiceMediaPlayer = nil
→ строка перестаёт считаться воспроизводимой и сворачивается
```

Следующее открытие снова создаёт штатный плеер. Это даёт повторные раскрытия/сворачивания кружка и перемещения подписи и соседних сообщений. Прежние проверки кнопок, идентификаторов и геометрии не исполняли эту отдельную подписку плейлиста.

## Исправление

Новый этап76 `archived_playlist_lifetime` после75 меняет только `PeerMessagesMediaPlaylist.swift`. Для `.recentActions(message)` с `NagramiXArchivedMessageAttribute` подписка на отсутствующий оригинал не создаётся, а возможное старое наблюдение освобождается. Данные берутся из переданного локального снимка.

Обычные сообщения, обычные recentActions без маркера и одноразовые сообщения сохраняют прежнее наблюдение за исходником. Наличие архивного атрибута в обычной message-location само по себе ничего не отключает. Политика custom-source также прежняя. Публикация state, порядок, looping, управление, завершение, декодер, звук, playlist/item/resource ID и хранилище не меняются.

Используются тот же штатный проигрыватель и те же действия pause/resume/replay. Геометрия, анимации, маски, 50% прозрачность и подпись «Это сообщение было удалено» сохранены побайтно. Исправление не добавляет отдельного плеера, задержек, повторных попыток открытия или обхода всех исчезновений сообщений.

## Проверка

Исполняются настоящее тело `updateState`, реальные closures отмены `SharedMediaPlayer` и `MediaManager`, native-декларация `SharedMediaPlaylistState` и SwiftSignalKit. Движок, граф сообщений и аппаратная остановка — явные тестовые границы. `nil` намеренно приходит после установки владельца плеера, как при асинхронном ответе движка.

117 проверок проходят в debug и `-O`: сохранённые кружок/голосовое/аудио, несколько looping-режимов, повторные state-refresh, тот же владелец, освобождение старого наблюдения, native end, обычные и одноразовые сообщения, normal recentActions, custom-source, смена соседей и освобождение наблюдения. Исходный75 воспроизводит ложную остановку и обязан отклоняться. Также отклоняются слишком широкий обход normal recentActions и оставленное старое наблюдение. Загрузчик с 20 guards проверяет все входы до записи; 12 повреждённых вариантов отклоняются.

Новый сценарий подключён к раннему набору Swift и обязательному post-apply gate. [Машинный отчёт](ARCHIVED_PLAYLIST_LIFETIME_CHECKS.json) отдельно фиксирует границы проверки.

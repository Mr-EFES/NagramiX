# Ручное переключение видимости репозитория

По последнему распоряжению пользователя видимость `Mr-EFES/NagramiX` переключает сам пользователь, а ассистент каждый раз даёт ссылку и проверяет результат. Прежний план автоматического переключения заменён этим порядком. Разработка ведётся в приватном репозитории; рабочая ветка — `main`.

## Перед каждой сборкой

1. По отдельной команде на сборку подготовить и проверить изменения, сохраняя README без правок.
2. Дать ссылку [Открыть репозиторий для сборки](https://github.com/Mr-EFES/NagramiX/settings#danger-zone) и инструкцию: **Danger Zone → Change repository visibility → Make public**.
3. Дождаться сообщения пользователя об открытии и проверить фактическую видимость через GitHub. Только после подтверждённого public запускать Actions. Ссылка сама ничего не переключает; отдельной ссылки, автоматически делающей репозиторий публичным, нет.

## После каждой сборки

1. Дождаться завершения всех заданий, публикации и проверки исходника/версии/checksum IPA.
2. Вместе с результатом дать ссылку [Закрыть репозиторий после сборки](https://github.com/Mr-EFES/NagramiX/settings#danger-zone) и инструкцию: **Danger Zone → Change repository visibility → Make private**.
3. После сообщения пользователя проверить private. Не утверждать, что репозиторий закрыт, только потому, что ссылка отправлена. IPA из закрытого релиза скачивается после авторизации пользователя.
4. При неуспехе, отмене или завершении попытки без выпуска также дать ссылку для закрытия. Повторная разрешённая сборка проходит тот же цикл.

## Ограничения

Текущее GitHub-подключение не имеет Administration: write; попытки смены видимости возвращали HTTP403. Пользователь выбрал ручной режим вместо настройки отдельного административного токена. Не запрашивать пароли, коды и токены в чат, не пытаться менять права или видимость автоматически без новой задачи.

Публичные сборки на стандартных GitHub-hosted runners используют бесплатные условия публичных проектов. Это не обнуляет приватную квоту и не гарантирует бесплатность larger runners и хранения. Временная публичность делает код и историю общедоступными; полученные копии и публичные форки последующим закрытием не удаляются. Пользователь выбрал такой порядок после обсуждения этих ограничений.

После публикации 0.8.5/build165 4 ноября 2026 года GitHub API подтвердил private. Видимость перед следующей работой проверять заново. Само сохранение распоряжения не запускает сборку и не изменяет видимость.

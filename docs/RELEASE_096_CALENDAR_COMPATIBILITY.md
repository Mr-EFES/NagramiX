# Совместимость праздничного календаря с iOS15

Ранняя проверка настоящим iPhoneOS SDK в попытке204 обнаружила обращение к `Calendar.Component.isLeapMonth`, доступному только с iOS17. Приложение сохраняет минимальную версию iOS15. Ошибка обнаружена до overlay и основной SDK-компиляции приложения.

Stage61 `release_096_calendar_compatibility` после60 меняет ровно один запрос: `dateComponents(in: referenceZone, from: noon)` вместо набора компонентов с новым enum case. Этот старый API возвращает также `DateComponents.isLeapMonth`; сама проверка признака високосного месяца сохранена. Публичные методы, все даты праздников, местные интервалы, density75, ручные настройки, показывать в чатах, таймеры и частицы остаются прежними.

Новая стадия содержит один replacement, четыре guards и шесть новых `.inc`. Все4338 прежних snapshots и планы сохранены. Изменён только `NagramiXSnowHolidays.swift`;18полных исторических манифестов43–60 восстанавливаются через checkpoint. Ресурсы,71×668переводов и метаданные0.9.6 не изменяются.

Проверка исполняет полный код праздников, настроек, расписания, native SignalKit и отображения с явными границами системных часов/UIKit/CA. Сохраняются6933проверки праздничной логики и7смысловых мутаций; дополнительно5857случаев сравнивают новый и старый Calendar API на2020–2035годах, включая известный китайский високосный месяц. Debug и `-O`, warnings-as-errors обязательны.

Проверка настоящим iOS15 SDK перенесена в начало early gate перед большим runtime-набором. Она компилирует все окончательные Core helpers и внешний consumer. Исходный код204 также компилируется как отрицательный сценарий и обязан отвергаться именно по доступности `isLeapMonth` с iOS17. После него в начале проверяется UIKit clipboard, который204 ещё не успела проверить; прежние native gates сохраняются.

Историческая57 остаётся точным source/runtime checkpoint с прежним SHA. Её Native SDK-проверка выбирает окончательный policy61 только при точном совпадении известного input/output SHA, без изменения исторического дерева. Это явно отражается в отчёте. Старый несовместимый код не объявляется iOS15-совместимым; настоящий SDK всегда проверяет окончательную реализацию. Обратное снятие стадий и все прежние runtime-контракты остаются обязательными.

Linux не может подтвердить доступность Apple API. Подтверждение iOS15 и воспроизведение ошибки204 требуют новой Apple-проверки; полная IPA и физическая приёмка остаются отдельными этапами. Повторы текущей0.9.6 разрешены владельцем до успешной публикации; все прежние релизы/IPA сохраняются.

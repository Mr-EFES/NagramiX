## Что настроить в боте

По официальному [Telegram Bots FAQ](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get), бот получает все сообщения пользователей в личных чатах, включая документы. Групповой privacy mode для этого выключать не требуется. ZIP отправляет авторизованный пользователь обычным MTProto-сообщением; Bot API токен не нужен на iPhone. Клиент не отправляет сообщения другим получателям и не вызывает /start автоматически.

Одного создания через BotFather недостаточно для автоматического разбора/пересылки. Нужен постоянно работающий серверный обработчик:

1. Принимать updates через существующий webhook или long polling `getUpdates` (одно из двух). В `allowed_updates` должны быть обычные `message`, а обработчик должен обрабатывать `message.document`, не только команды/текст.
2. При получении ZIP сохранить `chat.id`, `message_id`, `document.file_id` и метаданные. Сам токен держать в секретах сервера, не в коде приложения и не в переписке.
3. Для передачи владельцу вызвать `forwardMessage`/`copyMessage` в выбранный служебный чат. Нужен ID этого чата, отличный от ID бота; бот должен иметь возможность туда писать. Владелец не видит чужие входящие боту просто потому, что создал его в BotFather.
4. Если нужно именно скачивание на сервер, использовать `getFile` с учётом текущих ограничений Bot API. Для обычной пересылки владельцу скачивать/распаковывать архив не требуется. Подтверждать update после надёжного сохранения/обработки; не запускать второй poller поверх действующего webhook.
5. При желании отвечать пользователю подтверждением получения. Клиентское enqueue не является таким подтверждением.

Без доступа к backend/его конфигурации или пробной отправки нельзя утверждать, что бот реально обработал/переслал файл. В этой задаче сообщения в живого бота не отправлялись, его настройки не менялись. Данные username/ID взяты из скриншота пользователя; идентичность проверяется на устройстве при каждом разрешении получателя. Секреты для клиентской интеграции не запрашиваются.

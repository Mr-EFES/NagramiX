# Удаление чата с ботом без блокировки

В списке чатов штатный диалог удаления обычного бота предлагал удаление с остановкой и очистку истории. Теперь между этими действиями есть отдельное «Удалить».

Поздняя стадия `bot_delete_without_block` добавляет один пункт только в существующую ветку `canStop` в `ChatListController.deletePeerChat`. Пункт использует штатную строку `Common_Delete` и `maybeAskForPeerChatRemoval` с пустым callback `removed`. Он не вызывает `requestUpdatePeerIsBlocked`. Существующий пункт удаления с блокировкой сохраняет свой callback и вызывает блокировку только после подтверждённого удаления. Очистка истории, системное подтверждение, отложенная фиксация удаления и Undo остаются прежними. Для support-ботов, обычных пользователей, групп и каналов дополнительных пунктов не добавляется.

Изменяется один Swift-файл; восемь guards защищают BUILD, нативные API удаления и очистки, существующий путь блокировки и штатные строки. Новых ключей локализации нет. Исходный полный snapshot 13.2 из опубликованной 0.8.9 и прежние canonical snapshots не переписываются.

Проверка `scripts/validate_bot_delete_without_block.py` исполняет реальные тела двух пунктов меню: 17 проверок в каждом debug/-O, шесть скомпилированных отрицательных вариантов, 14 fail-closed проверок и parse полного Swift-файла. Отдельно проверяется побайтовая неизменность `maybeAskForPeerChatRemoval`, `schedulePeerChatRemoval`, очистки истории и всего исходника вне добавленных четырёх строк. Scheduling, privacy и AlertScreen в локальном исполнении представлены адаптерами; работа системного диалога и Undo на iPhone этим исполнением не подтверждается.

Восьми guards достаточно для этой изолированной стадии; наличие остальных семи задач и итоговой композиции доказывается общими проверками всего набора. Стадия применяется после `extended_poll_integrity`, перед `wide_tab_bar_setting`. При объединении с другими правками того же файла вход rebases на их точный snapshot без потери предыдущих изменений.

Вход и все восемь зависимостей дополнительно сверены с настоящим полным опубликованным деревом `/workspace/scratch/recovery-090/published-final`. Применение и валидатор на его точной проекции прошли повторно; отчёт `/workspace/scratch/recover-bot/actual-validation.json`.

SDK/IPA/Actions и физическая приёмка этой задачей не запускались. Первоначальный изолированный отчёт: `/workspace/scratch/recover-bot/validation.json`.

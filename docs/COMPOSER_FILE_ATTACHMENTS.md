# Текст и файлы при первом создании сообщения

**Актуальное дополнение59:** [полная первая вставка, файлы сверху в обоих редакторах и отсутствие лишней карточки](COMPOSER_COPY_INTEGRITY.md). Копия поста получает native fragment вместе с Telegram entities/RTF, а file+caption route принимает оба краевых положения файла. Исторический контракт38 ниже описывает первоначальную реализацию.

Запрос: видео4306602437152444786, создание длинного поста в обычном поле ввода с IPA из «Файлов». Прежний `presentICloudFileGallery` создавал сообщение с пустым `text` и сразу передавал его в очередь; набранный текст оставался отдельным черновиком. Подмена медиа при последующем редактировании проходила другим путём. Список недавних файлов и вкладка аудио также не получали подпись обычного нового черновика.

Владелец выбрал: после выбора файла оставлять текст и вложение вместе до нажатия «Отправить». Это исходная правка после опубликованной0.9.4/build195. Новая IPA и SDK этой командой не разрешены; следующий пакет0.9.5 — по отдельной команде.

## Реализация

Stage38 `composer_file_attachments` после `bubble_selection_edge`:4 точные замены,23 зависимых guard,31 новый snapshot. Все прежние3218 `.inc` сохраняются. Изменены только `ChatControllerOpenAttachmentMenu.swift`, `ChatControllerNode.swift`, `ChatControllerOpenDocumentScanner.swift` и одна строка регистрации файла в `RichTextAttachmentScreen.swift`. Нативный scanner впервые становится input стадии; Git blob исходной13.2 независимо сверен с официальным pin.

«Файлы», недавние документы, аудио и сканер вставляют `TelegramMediaFile` в структурный `ChatInputContent` текущего черновика. Выбор сам по себе ничего не отправляет. Текст не восстанавливается из плоской строки: форматирование, прежние блоки, emoji, вложения и выделение остаются. Явно изменённая подпись picker может заменить только тот черновик, который picker отображал. Если за время выбора началось редактирование отправленного сообщения либо такой черновик изменился, операция не затирает новое состояние.

Все типы `TelegramMediaFile` принимаются: неизвестное расширение также становится документом, музыкальные и голосовые файлы — аудио, видео — видео. MIME и имя, байты ресурса, атрибуты файла и ID сохраняются. Обе формы редактора сохраняют `partialReference` недавнего/облачного файла для штатного обновления просроченной ссылки. В расширенном редакторе прежний общий обработчик и uploader уже поддерживают `.document`, `.audio` и `.video`; ограничивающего списка расширений нет.

Нажатие «Отправить» использует штатный composer pipeline с его ответом, темой, slow mode, оплатой, расписанием и очередью. Обычный текст с файлами, помещающийся в допустимую подпись, получает native sendMedia с текстом на вложении, без отдельного текстового enqueue и без требования Premium за сам файл. Несколько подходящих файлов используют штатные группы максимум по10; голосовые не объединяются в недопустимый альбом. Кружок с текстом и набор с несколькими кружками не попадают в native caption/album, который их не представляет: такой пост сохраняет rich-путь. Предпросмотр ссылки не превращается в дополнительное сообщение. Текст-emoji с файлом не заменяется одиночным интерактивным dice.

Длинные/структурные посты сохраняют rich-message путь расширенного редактора, без обрезки до длины подписи. «Без форматирования» также сохраняет файлы; длинный текст остаётся частью rich-поста, а проверка Premium для структурного медиа не обходится. Серверные ограничения Telegram и Premium сохраняются. Явная отправка без звука/по расписанию из контекстных действий picker остаётся явной отправкой через native Send, после переноса всего поста в черновик.

Подмена медиа существующего сообщения, native gallery Send с подписью, камеру, редактор кружков и полный маршрут отправки расширенного редактора эта стадия не перестраивает. Отмена выбора не меняет черновик. Лимиты размера файла проверяются до вставки; при неразрешённом элементе iCloud не вставляется неполный набор. Постоянный draft/preupload/upload/retry продолжают использовать прежние реализации.

## Проверка и границы

Новый validator компилирует реальные структурные модели/позиции/replace-range/ChatTextInputState, функции сборки черновика, выбора транспорта, нативный text send-plan и builder сообщений. Выполняется также настоящий метод вставки контроллера с адаптерами только для отображения ошибки и interface/display services. Проверяются короткие/длинные подписи, форматирование и выделение, повторное вложение, все классы файлов, отмена/ошибка/устаревший picker, отсутствие автоматической отправки, метаданные источника, ответ/тема, несколько групп и сохранение вложений при снятии форматирования. Семантические отрицательные варианты должны падать в debug и `-O`; изменённые входы loader отвергаются до первой записи.

Общие проверки: полный финальный source и историческая обратная проекция, native Postbox import, canonical/full custom members и строгие71 каталога×635 ключей. Результаты и точные SHA — [COMPOSER_FILE_ATTACHMENTS_CHECKS](COMPOSER_FILE_ATTACHMENTS_CHECKS.json).

Это source checks. Адаптеры не доказывают UIKit/Markdown-пиксели, двоичную Postbox-персистентность, срок жизни iCloud bookmarks или серверную доставку. Для приёмки новой IPA: вставить текст из видео, выбрать IPA/PDF/ZIP/аудио/видео/неизвестное расширение; до Send в чате ничего не появляется; после Send проверить общий пост, несколько вложений, ответ, платный/отложенный чат, возврат из расширенного редактора и восстановление черновика после перезапуска.

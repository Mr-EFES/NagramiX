# Переслать и разослать без автора: быстрый маршрут GhostGram

**Проверено сборкой0.9.4/build195:** Apple Swift и чистая нативная компиляция пройдены с первой попытки; IPA проверен и опубликован. [Результат](RELEASE_094_PUBLICATION_CHECKS.json). Compile_passed/device_pending. Ниже сохранена история source-проверок до SDK; физический iPhone ещё ожидает приёмки.

Стадия34 `ghostgram_authorless_transport` применяется после `private_temporary_transcription`. Пользователь явно выбрал: «Быстрый путь GhostGram; копия, когда пересылка недоступна». Для этих двух действий это заменяет прежнее правило исключительно самостоятельных копий. Штатный «Репост» остаётся отдельным действием.

## Изученный образец

GhostGram проверен на фиксированном commit [`2a6b08272b7da893f88986846022bafd0727df89`](https://github.com/ichmagmaus111/ghostgram/commit/2a6b08272b7da893f88986846022bafd0727df89):

- [GGForwardSend.swift](https://github.com/ichmagmaus111/ghostgram/blob/2a6b08272b7da893f88986846022bafd0727df89/Ghostgram/Features/Shared/Sources/Messages/GGForwardSend.swift): `.forward` со `ForwardOptionsMessageAttribute(hideNames: true, ...)`, затем native `enqueueMessages` для адресатов.
- [GGForwardCopy.swift](https://github.com/ichmagmaus111/ghostgram/blob/2a6b08272b7da893f88986846022bafd0727df89/Ghostgram/Features/Shared/Sources/Messages/GGForwardCopy.swift): для защищённых/сохраняемых временных источников — подготовка полных байтов, новое медиа и `.message`.
- [GGMessageMenuCustomization.swift](https://github.com/ichmagmaus111/ghostgram/blob/2a6b08272b7da893f88986846022bafd0727df89/Ghostgram/Features/Messages/Sources/MessageMenu/GGMessageMenuCustomization.swift): ограничения native forward и выбор адресатов/режима отправки.

Лицензия образца — GPLv2. Перенесён принцип выбора транспорта; существующие NagramiX builder, media stager, выбор получателей и native Telegram используются своими реализациями. Копировщик образца сам исключает опросы/игры и не доказывает поддержку самостоятельной копии абсолютно всех объектов. Обычный опрос у GhostGram проходит через пересылку, сохраняя исходное голосование.

## Поведение NagramiX

Общий `nagramiXMessagesWithoutAuthor` используется одним и несколькими получателями. Доступные живые облачные сообщения отправляются по оригинальным ID со скрытым автором; полное видео перед отправкой не скачивается. Telegram сохраняет структуру объекта, включая опрос с видео, неизвестный правильный ответ викторины, форматирование, подпись и вложения. Это native forward с `drop_author`, а не новое независимое голосование.

Защищённые, временные, секретные, архивные и уже преобразованные источники получают прежнюю самостоятельную копию. Живой статус, namespace, ID, реальные ограничения исходника и отсутствие native принудительного заголовка проверяются отдельно от интерфейсного имени действия. Виджеты исключены из быстрого пути, поскольку штатный Telegram сохраняет их автора даже при hideNames. Неотправленные/ошибочные источники, истёкшие placeholder и служебные сообщения не получают пересылку по ID.

Если хотя бы один выбранный элемент альбома требует копии, весь выбранный альбом остаётся на одном транспорте. Исходный group key учитывается вместе с peer, чтобы совпавшие числа разных чатов не объединяли сообщения. Порядок смешанного выбора сохраняется. Перед первым enqueue готовятся все необходимые локальные наборы, у адресатов отдельные группы и временные файлы.

Предварительное скачивание и разрешение специальных объектов применяются только к источникам, которым нужна копия. Быстрый опрос/игра/история не превращается заранее в карточку. Созданные карточка, изображение результата или извлечённое медиа явно помечаются как копия: их старый облачный ID относится к другому объекту и повторно использовать его для forward нельзя. Существующее согласованное поведение полной копии либо карточки сохраняется там, где native пересылка недоступна.

«Переслать» оставляет одиночный выбор; «Рассылка» — галочки, порядок найденных/выбранных адресатов и пакетную отправку. Комментарий, тихая отправка, расписание, темы, подтверждение оплаты и отдельные correlation IDs сохраняются. Стоимость рассчитывается по фактическому смешанному payload: обычный кружок с текстом через forward остаётся одним сообщением, а полная копия может состоять из нескольких.

Повтор после подтверждённого отказа доступен обоим транспортам и использует существующий pending ID/random_id. Права, FLOOD_WAIT и реальные RPC-ошибки не превращаются в спекулятивную повторную отправку другим способом. Выбор копии при известной недоступности forward соответствует образцу GhostGram; автоматическая повторная отправка после неоднозначного сетевого результата не добавлена.

Строгие `nagramiXCopyMessagesAsNew`/`BySource`, копии при ответе на удалённое сообщение, новая идентичность самостоятельного опроса, архивная схема, receipts/TTL, транскрибация и плеер не изменены. Для сохранённых одноразовых сообщений не вызывается native forward по ID оригинала.

## Проверки

```sh
python3 scripts/validate_ghostgram_authorless_transport.py --source <source34> --swiftc <swiftc> --report <report.json>
```

Исполняются фактические policy, смешанный builder, recipient batch, строгий копировщик, файловый stager, native enum EnqueueMessage с преобразованиями и native ветка установки флагов drop_author/drop_media_captions. Проверяются разные типы медиа/специальных объектов, опрос с видео, отсутствие скачивания, скрытие автора, локальный резерв, альбомы/порядок/разные peer, расписание/тихий режим/темы, изоляция и отмена файлов, виджеты, временные и удалённые источники и повтор. Foundation файловый I/O настоящий; media/Postbox/сеть/UI — явные адаптеры или закреплённые неизменённые исходники.

Пройдены1056 проверок на режим,9 смысловых поломок в debug/-O,16 отказов loader и3 Swift parse. Каждая смысловая поломка должна воспроизводиться и отклоняться в debug и `-O`. Дополнительно проверяются fail-closed loader, обратимость всей цепочки, source/Postbox, custom members, полная локализация и независимое применение к полному дереву. Результаты — [GHOSTGRAM_AUTHORLESS_TRANSPORT_CHECKS.json](GHOSTGRAM_AUTHORLESS_TRANSPORT_CHECKS.json).

Новый Apple SDK/IPA и физический iPhone в этой задаче не запускались. Опубликованная0.9.3/build194 остаётся прежней; следующая сборка0.9.4 только по отдельной команде. На устройстве проверить исходный видеоопрос в «Избранном» и обычном чате, одного/нескольких получателей, сразу/без звука/по расписанию, обычный/защищённый/временный источник и отсутствие автора. Настоящие серверные ограничения определяются Telegram.

# Подмена профиля — удалена

Текущий статус14октября: **compile_passed / device_pending**, правка включена в опубликованный0.5.5/build89. [Пакет и независимые проверки](RELEASE_STATUS.md). XCTest и физическое поведение не проверены. Прежние отметки о подготовке ниже относятся к состоянию до этой сборки.

По прямой команде пользователя функция «Подмена профиля» (ранее «Ссылка на профиль») полностью удалена из текущих исходников. Возможность перенаправлять переход по имени/аватарке отправителя во всех официальных и сторонних клиентах Telegram клиентской настройке недоступна; предложенный механизм ссылок пользователь отменил.

Удалены пункт настроек и поиска, отдельный экран и редактор ID, состояние/чтение/запись параметров, RU/EN строки, Core обработчик и его XCTest. Генератор больше не добавляет эти файлы и не вызывает функцию при enqueue. «Анти-капс» и анонимные стикеры передаются непосредственно в штатный send; их остальные правила и ограничения сохраняются. Прежние локальные ключи могут оставаться в UserDefaults, но в новой версии не читаются и не исполняются. Уже отправленные сообщения и обычные ссылки/упоминания Telegram не переписываются. Stable ID136 зарезервирован; другие настройки не перенумерованы.

Полный overlay на чистом fixture прошёл, повторное применение с чистой базы совпало460/460 выходных файлов. Относительно прежних463 удалены три feature-файла, семь изменены,453 побайтно сохранены. `scripts/validate_profile_link_removal.py` проверяет точное изменение enqueue, отсутствие кода/меню/локализаций, сохранение других ID и default timerON/rearON. Validators анти-капса и приватных функций подтверждают обновлённые full-SHA guards, drift/collision/reapply без частичной записи. Пять изменённых Swift файлов прошли grammar parsing; Python compile, метаданные и diff check проходят. Native XCTest и Apple SDK compile не выполнялись.

Опубликованный IPA0.5.4/build88 содержит прежний код; удаление относится к следующей сборке. Новая сборка/commit/push не запускались. Status source_checked / native_build_pending / device_pending. Подробности проверки и следующий шаг записаны в [AI_HANDOFF](AI_HANDOFF.md).

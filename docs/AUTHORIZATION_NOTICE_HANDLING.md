# Предупреждение сервера об авторизации

Нативная попытка №85 обнаружила несовместимость типов: textAlertController(context:...) возвращает ViewController, а weak property была AlertController?. Исправлено на ViewController? без приведения; все действия и владение сохраняются. Следующая новая версия0.5.3, нативная компиляция ещё требуется. Source proof436outputs/435unchanged и exact reverse подтверждают, что изменился только тип.


## Что установлено

На физическом iPhone в NagramiX 0.5.3 №84 периодически показано английское «Authorization error…» с «Отмена»/«Выйти» и предупреждением о потере секретных чатов. Пользователь использует одну установку NagramiX и параллельно официальный Telegram; это штатная конфигурация и не доказывает дублирование MTProto-ключа.

Путь источника подтверждён: updateServiceNotification с popup и type AUTH_KEY_DROP_* → updatedState.addDisplayAlert → stateManager.displayAlerts → ApplicationContext. Текст приходит от сервера, не из пользовательских настроек или встроенной локализации. На этапе addDisplayAlert штатный код оставляет только text/isDropAuth; конкретный server type в UI недоступен. По одному скриншоту нельзя установить, почему сервер просит повторную авторизацию, или обещать, что ключ исправлен. Уточнение, продолжают ли сообщения работать после «Отмена», пока ожидает ответа пользователя.

## Подготовленные изменения

- При AUTH_KEY_DROP_* логировать ограниченный ASCII-код причины (до80 символов), без текста уведомления, номера, account ID, auth key или API credentials. Неподходящее значение заменяется AUTH_KEY_DROP_UNSPECIFIED.
- Для одного account-owned ApplicationContext держать слабую ссылку на открытое предупреждение. Повторные auth-окна не наслаиваются; после закрытия одинаковое уведомление не повторяется60 секунд по монотонному uptime. Другой текст после закрытия доступен сразу, первый показ нового context не подавляется. Отсутствие presenter не записывает успешный показ. Это защита от дублей, не восстановление ключа и не постоянное сокрытие серверного требования.
- Канонический английский текст ошибки авторизации локализовать RU/EN, сохраняя смысл необходимости повторного входа и явное предупреждение о потере секретных чатов. Нестандартные server instructions и обычные service alerts остаются без подмены.
- «Отмена» не меняет аккаунт/ключи/данные. «Выйти» сохраняет штатный явный путь; автоматического выхода, удаления сессии, копирования ключей между приложениями или очистки секретных чатов не добавлено.

Статус: implemented / compile_pending / device_pending. Опубликованный IPA №84 прежний; новая сборка только по команде пользователя. Эти изменения устраняют выявленные проблемы обработки и дают код для диагностики серверной причины. Сама причина AUTH_KEY_DROP_* пока не установлена, прекращение реальных серверных предупреждений не подтверждено.

## Следующий шаг

Уточнить работу отправки/получения после «Отмена». При повторном событии в следующем IPA собрать строку authorization service notification с точным AUTH_KEY_DROP_* и соседние коды RPC; credentials не запрашивать. Если сервер действительно требует новой авторизации, клиент не может гарантированно восстановить её без повторного входа пользователя. Не выполнять выход автоматически: он удаляет секретные чаты устройства.

После новой сборки проверить RU/EN, пачку одинаковых уведомлений, повтор после «Отмена» до/после60 секунд, другой текст, смену аккаунтов, возврат foreground, отмену и явный выход на отдельном тестовом аккаунте без ценных секретных чатов; обычные server notices и native logout/revocation обработку сохранить.

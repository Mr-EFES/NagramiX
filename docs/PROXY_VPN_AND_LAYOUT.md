# Прокси при VPN, сохранение выбора и DNS

Текущее состояние: включено в проверенный IPA0.5.4/build88, **compile_passed / device_pending**. [Сборка, source SHA и пакет](RELEASE_STATUS.md). Записи о локальных проверках ниже описывают подготовку до этой нативной сборки; физическая проверка остаётся отдельной.

Новая правка после опубликованного build86: implemented / compile_passed / device_pending. Версия и IPA0.5.3 прежние; нативная компиляция и тест на iPhone этой правки ожидаются.

## Поведение

«Не использовать прокси с VPN» автоматически включается при первом фактическом использовании прокси, если ключ ещё отсутствует. До начала использования значение OFF. Сохранённый OFF/ON сохраняется при перезапуске, выборе другого сервера и включении прокси. При включённой опции и обнаруженном VPN обходится эффективный прокси, но сохранённые enabled/activeServer/list/useForCalls не меняются. После снятия обхода применяется актуальный выбор пользователя. Во время обхода failover/периодические проверки остановлены; ручная проверка доступна.

Автопереключение автоматически включается при использовании прокси и двух и более разных сохранённых серверах, только при отсутствующем выборе пользователя. С одним сервером ключ остаётся отсутствующим; добавление второго может включить автоматику. Сохранённый OFF/ON не меняется, в том числе прежний OFF из старой версии. Таймер по умолчанию15секунд; варианты15/30/60. Автоматика с одним сервером не переключает соединение.

Причина отскакивания VPN-чекбокса: callback сохранял глобальную настройку, но не обновлял локальный ValuePromise контроллера. Теперь оба переключателя обновляют модель экрана; контроллер наблюдает внешние изменения и удаляет observer при завершении подписки. Явный OFF сохраняется даже при совпадении с отсутствующим default. Изменения других настроек не записывают отсутствующие прокси-defaults.

Порядок основного блока: использование, DNS-сервер, автопереключение, задержка при ON, VPN-чекбокс. Затем отдельно «Проверить список прокси», отдельно «Поделиться списком прокси», сохранённые серверы и добавление. Справочные footer отсутствуют; реальные статусы соединения сохраняются. Custom DoH и звонки используют прежние поля.

## DNS

Системный DNS → DNS Telegram → Google → Quad9 → AdGuard → Mullvad → Cloudflare → Пользовательский.

Системный DNS остаётся прежним пунктом0 и default. Новый отдельный пункт Telegram имеет значение7; значения1–6 существующих провайдеров не меняются, сохранённый выбор остаётся действующим. Оба первых пункта используют штатный resolver клиента через iOS; это отдельно сохраняемые варианты с одинаковым разрешением имён. Публичный отдельный DNS-сервер Telegram не добавляется. DoH-endpoints и проверка пользовательского URL прежние.

## Приёмка на iPhone после следующей сборки

1. Без сохранённых настроек: неиспользуемый прокси ничего не активирует. Начало использования одного сервера включает VPN-опцию; второй разный сервер включает автопереключение и таймер15. Дубликаты не считаются вторым сервером.
2. При активном VPN включить/выключить опцию один раз: экран должен показывать сохранённое значение. Быстро повторить; открыть экран заново и перезапустить приложение. Проверить внешние изменения и несколько аккаунтов.
3. Вручную выключить оба переключателя; сменить сервер, выключить/включить использование, добавить сервер, импортировать ссылку, перезапустить. Сохранённый OFF остаётся OFF. Прежние сохранённые значения также сохраняются.
4. Проверить DNS-порядок, сохранение всех восьми вариантов и соответствие выбора после перезапуска. Системный и Telegram идут через native resolver; все внешние DoH и Custom по прежним endpoints.
5. Проверить обход для SOCKS5/MTProto/WEB при VPN до запуска и после запуска; снятие VPN уважает актуальные enabled/activeServer. Детектор VPN эвристический: проверить WireGuard/OpenVPN/IKEv2, split/per-app VPN, Private Relay, фон, Wi-Fi/мобильную сеть. Уже начатый VoIP не обещает миграцию.
6. Проверить15/30/60, ручную проверку, обе отдельные кнопки, QR/список, удаление активного/резервного, большой шрифт, RU/EN, VoiceOver. Убедиться в сохранении обычной отправки и авторизации.

# Временные вложения: сохранение расшифровки и действия

**Уточнение после 0.8.8:** в поздней [copy_delivery](COPY_DELIVERY.md) восстановлен временный «Репост» с подписью автора. Обычный native Репост для других сообщений не подменяется. При ON собственные записи, как и полученные, идут полной локальной копией без нового одноразового таймера; ограниченная own-view-once льгота применяется только при OFF. Отдельные проверки охватывают все четыре типа, автора/entities, Ответ на удалённую запись, пересылку/рассылку и оба направления. Новая Apple SDK/IPA-сборка не запускалась; проверка iPhone остаётся pending.

**Текущий статус: нативная чистая0.8.7/build173 и пакет проверены, релиз опубликован.** Source27217997bd5a691cfc2013b733e7be5646ed7479, run42081412326; полный pre-SDK151/cold gate/native/package/owner publication passed. Физическая работа на iPhone остаётся device_pending; [проверка0.8.7](DEVICE_CHECK_087.md). Сведения о pending/IPA171 ниже — история предыдущих исходных этапов.

Актуальное уточнение владельца для 0.8.6 заменяет прежнее превращение временной копии в обычное удалённое сообщение. При «Временные сообщения» ON сохранённая запись остаётся временной после просмотра или удаления оригинала другим клиентом. Прежние воспроизведение, огонь и повтор не меняются; локальная копия не получает настоящего таймера и не посылает consume/read ради расшифровки.

## Поведение

- `→A` у поддерживаемой временной голосовой и кружка остаётся независимо от Premium, выбранного провайдера и наличия готового текста. Готовая расшифровка открывается без RPC. Новая использует только выбранный доступный способ; недоступность сервера или локальных данных остаётся понятной ошибкой. Нельзя отправлять удалённый ID в Premium API или создавать скрытую серверную копию.
- Завершённые native Premium результаты и асинхронные updates зеркалируются в существующий архив, даже если его медиа ещё докачивается. Локальный распознаватель по-прежнему требует полные байты. Отключение функции или очистка записи блокируют позднюю запись результата; запись не создаётся заново.
- Серверные удаления по message IDs, global IDs и собственное первое удаление не сбрасывают temporary/replay признаки. Схема обратно совместима. Для старых ошибочно разжалованных записей доказательством служит optional `transcriptionAttributes`, который сохранялся только у временных записей, в том числе пустым массивом. По обычному типу голосового происхождение не угадывается; отсутствующие исходные данные восстановить нельзя.
- У временных голосовых, кружков, фото и видео сохраняется обычное контекстное меню. Ответ/сохранение/копирование/«Переслать»/«Рассылка» и выделение используют отображаемое вложение; повторное удаление архивной копии сохраняет прежнюю механику локального стирания. Права настоящих редактирования, закрепления и серверных действий не выдумываются. Для удалённого оригинала ответ вставляет локальную цитату с автором и описанием медиа, не использует недействительный reply ID.
- На отдельный вопрос владелец выбрал: «Отправлять копию с подписью автора». Такой «Репост» — новая локальная копия с обычной текстовой подписью, без поддельного Telegram forward header. UTF-16 offsets исходного форматирования смещаются корректно. У кружка подпись отправляется соседним текстом перед видео: его bubble не показывает caption. Для обычной пересылки/рассылки подпись автора не добавляется.
- Допуск временного вложения определяется собственным переключателем, независимо от «Свободного контента». Выключение перепроверяется перед отправкой; последняя политика обычных копирующих действий описана в COPY_DELIVERY. Секретные чаты, коды, paid/expired/action, отправляющиеся и неудачные сообщения не получают эту временную льготу. При OFF сохранено прежнее исключение для отправления своей one-shot записи допустимым адресатам; при ON оно уступает полной сохранённой копии.
- Каждый адресат получает полный независимый набор файлов и групп, подготовленный до enqueue. Обычная копия входящего сохранённого вложения не наследует уже истёкший countdown. Байты должны существовать; новый экземпляр не восстанавливает недоступный серверный оригинал.

## Реализация и проверка

Поздняя guarded стадия `temporary_media_actions` после `message_copy_availability`: 15 replacements, 25 guards. Canonical прежние стадии не изменяются. Все входы, шаблоны, выходы и пути проверяются до записи. Прежние validators снимают новую стадию по точным SHA.

`python3 scripts/validate_temporary_media_actions.py --source <pre-post-port-tree> --swiftc <swiftc>` проверяет фактические Runtime, archive deletion/ASR методы, Engine mutations, условия кнопок голосовой/кружка, copier/fetch/stager/recipient helpers и сериализацию. Пройдены 163 ASR/архив/UI и 38 copy проверок в debug и -O; 63 recipient и 18 rich-post проверок также пройдены на новом copier. Четыре негативных варианта возвращают прежние ошибки и отвергаются в обоих режимах; 90 некорректных наборов/путей отвергаются до записи. Postbox, Speech, HTTP и UIKit — явные тестовые границы. Строгие 71 языковой каталог по 613 ключей сохраняются; новые строки интерфейса не добавлены.

Свежая композиция и incremental совпали по 598 путям; строгая локализация 71×613, 87384 lookup проверки, metadata и diff checks пройдены. Точный post-port,739 Core imports и PostboxImportCheck также пройдены.

Статус: source checks; новая Apple SDK/IPA и физическая проверка ожидаются. В IPA171 этой стадии нет. Ничего не собирать и не запускать Actions/rerun без отдельной личной команды владельца. PiP и прежние ASR модели не изменены.

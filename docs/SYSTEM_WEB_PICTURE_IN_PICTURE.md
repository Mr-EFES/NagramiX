# Системный PiP и фон для YouTube и встроенного видео

Текущая доработка YouTube — [стадия54](YOUTUBE_PLAYBACK_POLICY.md): устойчивое снятие повторных клиентских запретов и ранняя обработка фоновых событий на том же HTML-video. Ниже сохранён контракт базовой системной реализации48; его плееры, галерея и аудиосессия продолжают использоваться.

По уточнению владельца используются стандартные окна PiP iOS. Прежний внутренний overlay Telegram из42 для этой категории больше не запускается. Стадия48 `system_web_picture_in_picture` следует за47; восемь замен,22guards,38новых snapshots. Все3581прежних canonical `.inc` сохранены.

## Плеер и владение

Для `SystemVideoContent`/`PlatformVideoContent` AVPictureInPictureController получает тот же AVPlayerLayer, который уже показывал видео. Другой AVPlayer не создаётся. Делегат сообщает фактический старт/стоп, отклоняет запоздавший старт после отмены и передаёт восстановление исходному владельцу.

Для `WebEmbedVideoContent` разрешён native WebKit PiP. Скрипт установлен во все фреймы существующей WKWebView. Сначала выбирается один живой HTML-video, с предпочтением играющего; затем команда выполняется через публичный evaluateJavaScript именно в выбранном WKFrameInfo. Видео вызывает webkitSetPresentationMode. URL потока не извлекается, blob/MSE не переносится, второй WebView/декодер/аккаунт/сервис не создаётся. Имеющиеся разрешения и авторизация видео сохраняются.

Запросы привязаны к token, поколению и выбранному фрейму; поздний enter после stop или нового probe не запускается. JavaScript-наблюдатель презентации один на элемент. Временное снятие disablepictureinpicture отменяется при выходе или отказе. Возврат играющего HTML-элемента из PiP восстанавливает галерею; закрытие при остановке освобождает исходник. Навигация/завершение WebContent process снимает активность.

Галерея сохраняет явную ссылку на своего владельца на время запроса/PiP, поскольку currentPictureInPictureNode — weak. Видимость и центральность не отсоединяют активный источник. До подтверждения PiP галерея остаётся видимой; повторное нажатие блокируется. Через5с неподтверждённый запрос отменяется и оформление восстанавливается. Присоединение при возврате подтверждает прежний реальный attachment gate с одноразовым acknowledgement и timeout2с. Старая генерация не меняет новый запрос. Закрытие не ставит на паузу контент, уже переданный другому владельцу. При остановке/отказе ссылка освобождается; самопроизвольного сброса позиции или повторного запуска нет.

## Фон и блокировка

Оба существующих переключателя/default ON сохранены. Обычный фон учитывает backgroundVideoPlayback; системный PiP сохраняет аудио и управление независимо от него. Статус воспроизведения встроенного видео теперь участвует в штатных фоновых owners и едином Now Playing writer. PiP-запрос получает ограниченную по времени аудиосессию до ответа системы. Глобальный MediaManager не выполняет dropAll для живого системного PiP.

AVPlayer использует audiovisualBackgroundPlaybackPolicy.continuesIfPossible, пока действует фоновой owner или PiP; при OFF/последнем освобождении возвращается automatic. Platform не отсоединяет слой активного PiP при уходе в фон. WebEmbed использует имеющийся ManagedAudioSession типа play, без silent audio или бесконечных resume-таймеров. Играющий разрешённый web-поток сохраняет видимость документа для обработчиков сайта; OFF возвращает native visibility. Вход/выход из фона отслеживается через публичные notifications, без UIApplication.shared в библиотеке. Пауза, звонок/потеря аудиосессии и закрытие не превращаются в принудительное возобновление.

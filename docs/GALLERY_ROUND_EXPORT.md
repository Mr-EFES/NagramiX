## Параметры текущего вложения

«Круглые видео» и «Качественные кружки» теперь независимы. Пятая кнопка открывает редактирование:

| Поле | Варианты |
| --- | --- |
| Размер | Стандарт480×480, Высокое512×512, Максимум640×640 |
| Битрейт | Стандарт, Средний, Высокий, Максимум |
| Кодек | H.264/AVC, H.265/HEVC |
| Частота кадров | 30,60кадров/с |

Уровни битрейта соответствуют1000/1100/1200/1300кбит/с; в меню показаны названия уровней. Новый профиль галереи по умолчанию480×480/30FPS/H.264/1000кбит/с. Он не читает и не меняет переключатель, пресет или другие настройки записи камеры.

Нажатие строки открывает варианты; выбор возвращает к сводке. «Применить» один раз сохраняет четыре значения только в текущий attachment snapshot. Крестик/закрытие отменяют изменения. Защита по identity вложения не применяет старое окно к другому ролику, отправляемому или закрытому редактору. Звук, подпись, кадрирование, поворот, тримминг и остальные поля сохраняются. SD/HQ/MAX показывают выбранный размер текущего вложения. Качество круглого ролика можно менять и при выключенном звуке.

Существующие43поля модели, JSON-adjustments и deferred snapshot не расширяются. Сохранённые профили из3/4значений мигрируют без сброса размера/FPS/кодека: трёхэлементный получает прежний эффективный битрейт, старый битрейт выше1300ограничивается1300. Неизвестные/невалидные значения получают независимый стандартный профиль. Переключение режима, обновление toolbar и подготовка отправки больше не подменяют локальный выбор настройками камеры.

## Изменение экспорта

В стадии102 к custom round был добавлен `AVAssetReaderVideoCompositionOutput` для изменения FPS. Стадия107 убирает этот дополнительный compositor: кадры снова читает штатный `AVAssetReaderTrackOutput` Telegram. Размер исходных декодированных кадров не меняется на этапе чтения; существующий composer один раз выполняет поворот, кадрирование и вывод выбранного квадратного размера.

Отдельный ограниченный двумя удерживаемыми samples планировщик задаёт временные метки30/60FPS. При понижении FPS он пропускает кадры, при повышении повторяет исходные кадры; новых деталей движения это не создаёт. Сохраняются тримминг и длительность. После EOF native reader отдаётся оставшийся хвост; затем выполняется штатное завершение, включая существующий bounce path. Невалидные/неупорядоченные timestamps, отсутствие изображения и ошибка CoreMedia copy завершаются ошибкой чтения, а не успешным пустым файлом.

Публичный `NagramiXRoundVideoExport`, ограничение размера, проверка реального кодека/разрешения/FPS, ограниченные повторы, отмена и запрет отдачи непроверенного файла в upload сохранены побайтно. Round attribute сохраняется; fallback в квадратный документ не добавлен. Камера, её настройки и страница «Качественные кружки» не менялись. Обычные видео читаются прежним способом без планировщика.

Альтернатива — предварительно нормализовать весь исходник отдельным проходом, затем кодировать кружок. Выбран один проход со штатным reader: он не требует промежуточного полного видео и повторного сжатия. Реальную совместимость VideoToolbox конкретного исходника всё равно нужно подтвердить на устройстве.

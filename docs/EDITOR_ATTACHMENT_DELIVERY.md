# Вложения редактора и предпросмотр ссылок

Интеграция с synchronizing drafts дополнительно исправлена после native failure174: [rich draft fix](RELEASE_088_DRAFT_UPLOAD_FIX.md). Общий uploader по-прежнему возвращает ошибку; draft consumer получает cancellable retry вместо bare fallback.

Исходная правка для NagramiX 0.8.8, ещё не включена в опубликованную IPA0.8.7/build173. Проверка Apple SDK и физического iPhone ожидается. Новая личная команда разрешила сборку0.8.8; текущий статус в RELEASE_STATUS.

На видео7710089604145914782.mp4 обычный редактор отправляет аудиофайл с текстом. В расширенном редакторе тот же файл виден перед отправкой, но в истории остаётся текст без файла. У скопированного текста также появляется дополнительная карточка ссылки, которой не было в исходном посте.

В коде обнаружена конкретная причина: `messageContentToUpload` выбирал загруженную `TelegramMediaWebpage` раньше `RichTextMessageAttribute` с embedded media. Отправка шла по ветке веб-страницы, минуя загрузку вложений. Последующая сериализация rich-атрибута без подготовленных photos/documents оставляла текст без доступных файлов. Это воспроизводится регрессионным тестом на реальной функции маршрутизации; сервер и устройство в этой проверке заменены явными границами.

Поздняя стадия `editor_attachment_delivery` после `local_model_size` исправляет подготовку и отправку:

- Rich-пост с карточкой ссылки сначала проходит существующую загрузку всех embedded media. Прогресс и ошибки сохраняются. Подготовленный rich payload передаётся вместе с исходной карточкой, включая её размер и положение, в pending, standalone и ephemeral отправители. Существующие обычные вложения, native forward и rich-путь без карточки сохраняют прежнюю маршрутизацию.
- При копировании поста без карточки добавляется штатный `disableLinkPreviews`. Текст URL и entities остаются исходными; новая карточка не генерируется. Имеющийся в источнике preview сохраняется, без добавления ссылок или подписи. Его нельзя принимать за вложение и стирать весь текст через `hideCaptions`.
- Редактирование с неуспешной загрузкой rich-вложений завершается ошибкой существующего pending-edit механизма. Удалён запасной media-less serializer, который мог успешно отправить частичную замену без файла. Поддерживается один результат после завершения загрузки, без повторного запроса на каждом progress.

Шесть полных replacements TelegramCore и16 SHA-guards фиксируют upload producer, native attachment/editor handoff, API serializer, pending edit, оба предыдущих исправления архива и размеров моделей. Старые canonical snapshots не меняются. Нет новых строк, зависимостей, настроек, изменений языка, прав, оплаты, отложенной отправки или анимаций клавиатуры. Предыдущие проверки снимают только точный новый stage по SHA, затем проверяют прежние исходники.

Проверено локально:

-109 утверждений в каждом режиме Swift/debug и `-O`: реальная маршрутизация, preview merge, edit resolver, три sender handoff и полный актуальный copy builder. Восемь отрицательных вариантов в обоих режимах воспроизводят пропуск upload, потерю prepared payload, возврат bare serializer и изменение исходного preview.
-54 fail-closed случая; полные Swift-файлы проходят frontend parse. IO/Signals/Postbox/Telegram API — тестовые границы; реальные сеть, серверная доставка и UIKit этим не подтверждаются.
-Полная композиция pinned13.1.2+legacy13.0 и финальный семифайловый post-port совпадают с incremental по613 принадлежащим pipeline путям. Изменены только шесть outputs этой стадии; предыдущие archive effect и model sizes сохранены. `PostboxImportCheck` и контракт локализации71×613/111files594calls проходят.

Текущий final source: `/tmp/nagramix-editor-attachments/fresh`. Отчёты `validation.json`, `composition.log` и `final-composition-hashes.json` находятся рядом; это рабочие артефакты, не исходники релиза. В workflow добавлена154-я обязательная source-команда перед SDK. Новые SDK/Actions/IPA/commit/push не выполнялись.

На iPhone проверить исходный сценарий: копирование поста с обычной текстовой ссылкой и без карточки; репост/рассылка нескольким получателям; пост с собственной карточкой; добавление MP3, PDF/ZIP, фото/видео и альбома в обоих редакторах; отправка во время загрузки; редактирование с обрывом связи и повторной попыткой. Проверить полные файлы у получателя, текст/entities, порядок, группировку и отсутствие лишней карточки.

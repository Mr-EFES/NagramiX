# Удалённые сообщения

## Состояние и отображение

Источником deleted state остаётся `NagramiXArchivedMessageAttribute`, который ставится только синтетическим display-only сообщениям существующего локального архива. Текст сообщения не используется для определения удаления, backend перехвата delete updates и формат архива не меняются.

Обычные сообщения сохраняют штатный Telegram layout и `alpha = 1.0`. Для архивного сообщения bubble, media/content container, headers, action buttons и reactions получают `alpha = 0.5`; интерактивность и hitboxes не отключаются. При каждом bind alpha назначается явно, поэтому reused cell обычного сообщения возвращается к `1.0`.

Для статуса резервируется отдельная компактная строка внизу bubble. В ней справа отображаются существующая theme-tinted Telegram delete icon и метка вторичным цветом текущей incoming/outgoing message theme. Строка добавляется после основного content layout, поэтому не пересекается с time, views, edited и другими штатными metadata. Сам статус не входит в dimmed content container и остаётся читаемым.

## Пользовательская метка

В разделе «Функции → Сообщения» строка «Текст метки удаления» открывает штатный Telegram alert editor. Значение хранится в `nagramix.messages.deletedMessageLabel`, нормализуется в одну строку, обрезается до 64 символов и сохраняется между запусками. Пустое значение использует локализованный fallback `Это сообщение было удалено` / `This message was deleted`.

Изменение публикует отдельное notification и перепривязывает сообщения открытого чата без restart. Основной checkbox `nagramix.messages.showDeletedMessages` не меняется: когда функция выключена, архивные сообщения не инжектируются и новый visual state не появляется.

## Проверка на устройстве

- normal/deleted/normal при прокрутке: только deleted имеет alpha 0.5, icon и label;
- live delete в открытом чате обновляет сообщение без повторного открытия;
- custom label, 64-character limit, newline rejection и empty fallback;
- text, photo, video, GIF, file, voice, sticker, forward, reply и grouped media;
- incoming/outgoing в private chat, group, channel и Saved Messages, если snapshot доступен backend;
- Light, Dark, AMOLED и custom themes;
- long press, selection, copy, media viewer, reactions, date/views/edited/footer не ломаются.

## Геометрия status footer

Ширина архивного bubble учитывает не только исходный message content, но и измеренную однострочную ширину `delete icon + spacing + deleted label + horizontal insets`. Короткое сообщение поэтому расширяется под пользовательскую метку, но не выходит за штатный `maximumContentWidth` Telegram. Если даже максимальной ширины недостаточно, `ImmediateTextNode` допускает несколько строк, а высота отдельного status footer вычисляется по полному тексту. Используется существующий ресурс Telegram `Chat/Context Menu/Delete`, отрисованный отдельным `ASImageNode`: текстовый `NSTextAttachment` заменён, чтобы пиктограмма не зависела от поддержки вложений в `ImmediateTextNode`. Размер иконки 13 pt, ширина вместе с промежутком 17 pt; цвет — вторичный цвет текущей темы. При reuse обычного сообщения оба узла метки удаляются.

## Взаимодействие с архивной копией

Причина мгновенного закрытия контекстного меню: `ChatMessageContextExtractedContentSource.shouldBeDismissed` проверял наличие оригинала в Postbox. Теперь для `NagramiXArchivedMessageAttribute` он наблюдает updates локального архива и закрывает меню только при удалении копии или отключении показа. Обычные сообщения продолжают использовать штатную проверку базы.

Архивное меню содержит: копирование текста с entities, ответ цитатой при разрешённой отправке и непустом тексте, редактирование локальной копии, пересылку без автора для поддерживаемого содержимого, историю правок при наличии, выбор, выделение от автора и локальное удаление. Оба дополнительных действия учитывают существующие настройки видимости. Ответ цитатой добавляет текст цитаты перед существующим черновиком, сохраняя черновик; это не серверный reply на удалённый ID. Локальный редактор хранит изменённый текст и медиа, сохраняет предыдущий текст в revisions, сбрасывает прежние offsets entities после изменения и обновляет stableVersion для немедленной перерисовки. Пустой текст без медиа не сохраняется. Сохранённая пользовательская метка не заменяется новым fallback.

Обработчик «Переслать без» принимает архивный snapshot напрямую. Пересылка выбранных ID загружает доступные обычные сообщения из базы и недостающие удалённые — из архива; если в наборе есть архивная копия, весь набор отправляется без автора как новые сообщения. Для её медиа используется standalone reference; доставка требует доступного ресурса, возможность повторной загрузки с сервера после удаления не гарантируется. Выделение от автора объединяет полную серверную пагинацию с архивными сообщениями этого автора в том же чате/теме. Для полностью архивного выбора панель разрешает пересылку копий и локальное удаление.

Закрепление удалённого оригинала, серверное редактирование, серверная пересылка с атрибуцией оригинала, реакции и серверная жалоба не добавляются в меню архивной копии: Telegram больше не хранит этот ID. Локальное закрепление пока не реализовано. Внешний share архивного выбора и отдельный полностью локальный сценарий удаления смешанного выбора не расширялись этой правкой. Абсолютно одинаковый набор серверных операций с живым сообщением не обещается.

После изменения прошли применение overlay к pin, синтаксический разбор изменённых Swift, Python и проверки локализаций/метаданных. Нативная компиляция новых исходников ожидается; физические сценарии текущей версии ожидаются. Проверять long press/выбор/возврат без исчезновения, отмену меню, редактирование/сохранение/перезапуск, кириллицу и многострочную метку, очистку архива при открытом меню, copy-as-new текста/медиа, смешанный выбор, выбор автора и выключенные пункты меню.

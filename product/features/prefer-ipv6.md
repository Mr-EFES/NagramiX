# Предпочитать IPv6

Настройки прокси → «Предпочитать IPv6», непосредственно после строки «DNS-сервер» и перед полем пользовательского DoH, если оно показано. Штатный переключатель, RU/EN заголовок с переносом, без справочного footer. Stable ID17; старые ID сохранены.

Один Bool `nagramix.network.preferIPv6` в существующем `NagramiXProxyPreferences`. При отсутствии ключа OFF, чтение не записывает значение. Выбор пользователя сохраняется при холодном запуске, обновлении и добавлении прокси. Это общая настройка соединения аккаунтов приложения, доступная и при выключенном прокси.

## Соединение

- OFF сохраняет прежний выбор адресов Telegram. Это не запрет IPv6: сеть только с IPv6 продолжает использовать штатные возможности клиента.
- ON допускает IPv6-адреса дата-центра к первой попытке и предпочитает работоспособный IPv6 перед IPv4. Недавняя ошибка схемы уступает исправному адресу; через 60 секунд IPv6 можно проверить снова. Если обе схемы недавно отказали, сохраняется выбор по более ранней ошибке.
- Для SOCKS/MTProto-прокси с hostname системный resolver выбирает AAAA перед A. DoH последовательно пробует AAAA/A для существующих GET/POST запросов. При отсутствии AAAA используется A; выбор DNS-провайдера и endpoints не меняется.
- После ошибки установления TCP к IPv6-адресу прокси следующие попытки к тому же hostname:port на 60 секунд предпочитают IPv4. Это процессный кеш максимум на 256 адресов, с монотонным временем; он не меняет сохранённые настройки. Успешное IPv6 TCP-соединение снимает ограничение. Отмена, переключение настройки и ошибка протокола после установления TCP не считаются недоступностью семейства адресов.
- Для SOCKS меняется адрес самого прокси. Штатное кодирование адреса назначения в SOCKS CONNECT не меняется; IPv6-схемы дата-центра не получают новый приоритет при активном прокси. Явно заданный IP не подменяется другим семейством.
- WEB-прокси сохраняет прежний carrier и отсутствие прямого DNS-запроса; выбор семейства его HTTP/WebSocket соединения остаётся системным. Опция не добавляет обход выбранного прокси или произвольный прямой endpoint.

Существующие таймауты, порядок повторных соединений и автопереключение прокси сохранены. Это приоритет адресов с восстановлением после ошибки, без нового параллельного Happy Eyeballs соединения или обещания мгновенного перехода при недоступной сети.

Изменение настройки публикует прежнее уведомление обновления UI и `NagramiXDnsSettingsChanged`. Существующий observer аккаунта переподключает main session с учётом keep-connection/paused state. Фоновые аккаунты не пробуждаются; уже работающий worker может завершить текущую сессию до следующего соединения. Штатный iOS backend закреплённого Telegram13.0 — MtProtoKit; экспериментальный Rust backend отдельной реализации не получает.

## Интеграция и проверки

Поздний `ios/prefer_ipv6.py`/JSON stage применяется после прежней финальной правки переноса Proxy UseForCalls в `apply_features.py`. Девять полных SHA256, 31 точная операция, три private helper файла MtProtoKit; уже скопированный preferences helper проверяется на совпадение canonical bytes. Все входы проверяются до записи, новые внешние зависимости не добавлены. Старые stages и SHA не ослаблялись.

Полный offline overlay закреплённого Telegram-iOS `f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838`: 416 выходных файлов против 413 baseline, 11 изменений, три helper добавлены, 402 файла побайтно прежние. `scripts/validate_prefer_ipv6.py` проверяет точное воспроизведение patch table, порядок UI и stable ID, unchanged SOCKS CONNECT/обе WEB ветки, source/public resolver headers, reuse observer и 29 fail-closed сценариев без частичных записей.

Реальные C функции политики: 47 проверок в debug и optimized с UBSan. Реальный Foundation preferences helper: 24 проверки в каждом режиме, ещё по шесть отдельных холодных процессов для сохранения ON/OFF. Включены порядок DNS A/AAAA, отсутствие одного семейства, новая IPv6-схема, ошибки и граница 60 секунд, отмена/успех, OFF без записи, сохранённые DNS/System, VPN, auto-switch и старый интервал 15. Swift syntax и Python/JSON проверки пройдены.

Proof: `/workspace/.codex-validation-nagramix-prefer-ipv6/verification.json`, итоговый generated tree `native-final`. Apple SDK typecheck и реальная сеть не проверены: `source_checked / native_compile_pending / device_pending`. Сборка IPA/Actions/commit/push не запускались; новая сборка только по отдельной команде пользователя.

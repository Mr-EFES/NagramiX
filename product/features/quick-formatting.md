## Поведение

В поле сообщения рядом с эмодзи появляется штатная по размеру кнопка **Aa**. Она открывает панель вместо системной клавиатуры, затем показывает значок клавиатуры для возврата. Панель открывается и без выделения, но стили в этом случае выключены; «Выделить всё» доступно при непустом вводе — это уточнённый пользователем вариант. Текст целиком автоматически не выделяется, оформление будущего ввода не меняется.

Десять пунктов: цитата, спойлер, жирный, курсив, моноширинный, ссылка, дата, зачёркнутый, подчёркнутый, код. Подписи берутся из штатных TextFormat-строк Telegram. Команда проверяет актуальное выделение при каждом нажатии, а не диапазон, сохранённый при открытии панели. Уже применённые ко всему выделению стили подсвечены; смешанное оформление не показывается как полностью активное. Допустимые сочетания, включая цитату с жирным и курсивом, сохраняются.

В обычном редакторе вызываются прежние formatAttributes-обработчики, в новом структурном редакторе — performFormatAction. Ссылки и даты используют штатные диалоги, которым возвращается управление фокусом. Содержимое структурного документа не переписывается через плоский attributedText. Запрет сочетания спойлера с моноширинным и ограничения секретного чата сохранены.

**Ограничение закреплённой базы:** новый структурный редактор Telegram ещё не умеет сущность даты; его штатная команда date ничего не делает. В нашей панели «Дата» для этого редактора выключена. В обычном редакторе она доступна и открывает прежний диалог. Не выдавать отсутствующую возможность редактора за работающую команду.

Кнопка не занимает место при выключенной настройке, недоступном вводе, расширенном поиске, активной записи или предпросмотре записанного медиа. Нативные кнопки эмодзи/стикеров и bot keyboard сохраняют свои переходы. Центральный ChatControllerNode учитывает текущую панель при назначении inputView; обычная перерисовка не должна возвращать клавиатуру сама. При закрытии сбрасывается только наш inputView, другой владелец клавиатуры не затрагивается. При переходе из старого редактора в новый панель передаётся новому узлу.

По выбранному пользователем эскизу №1 панель переработана: клавиши4×3 с двумя дополнительными действиями по утверждённому23октября макету, короткие однострочные подписи, полные названия для VoiceOver. На узких экранах и при увеличенном шрифте число столбцов адаптируется, содержимое при необходимости прокручивается внутри прежней высоты. Aa и обратный значок клавиатуры используют тот же `inputControlColor`, что и соседняя кнопка эмодзи. Панель использует системный фон клавиатуры, фактическую высоту из штатной разметки и безопасные отступы внутри неё. Дополнительный немедленный layout при переключении убран. Штатные меню форматирования и сами преобразования текста не изменены. [Реализация и проверка нового интерфейса](../../docs/QUICK_FORMATTING_VISUAL_FIX.md).

## Видеореференс пользователя

21 октября просмотрена запись FullSizeRender.mov длительностью 14,1 секунды. Она подтверждает последовательность уже реализованного взаимодействия:

1. Ввод текста обычной клавиатурой; кнопка оформления находится рядом с эмодзи.
2. Открытие панели без выделения: десять действий видны, но выключены. Вместо кнопки оформления появляется клавиатура.
3. Выделение первого слова, применение жирного и подсветка соответствующей кнопки. Затем выделение другого слова: старая подсветка снимается, курсив применяется к новому диапазону. Панель остаётся открытой.
4. Отправка сообщения с разным оформлением отдельных слов. Поле очищается, панель остаётся открытой, действия и подсветка сбрасываются.
5. Возврат к обычной клавиатуре через кнопку в поле сообщения.

По этой последовательности добавлены 28 проверок в существующий тест: по 14 для каждого редактора. Проверяется маршрутизация команд, смена диапазона, чтение активных атрибутов, пустое состояние после отправки и возврат клавиатуры. Результат штатного форматирования и очистки при Send подаётся на границе редактора; эти тесты не выполняют реальную отправку, не воспроизводят UIKit и не доказывают плавность анимации на iPhone. Визуальные детали записи также включены в приёмку после сборки. Рабочий код и defaultOFF по этому референсу не менялись.

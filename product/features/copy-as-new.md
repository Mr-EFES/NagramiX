# Копирование сообщений без источника

24 октября после IPA123 исправлено открытие отключённой строки форума/сообщества в множественной «Рассылке»: контейнер открывает штатный выбор темы, прежние адресаты сохраняются. **source_checked/native_compile_pending/device_pending**, без новой SDK/IPA. [Причина и проверки](../../docs/BROADCAST_CONTAINER_SELECTION_FIX.md). Нижние записи относятся к прежним этапам.

22октября подтверждён оставшийся сбой рассылки в IPA114. Новая [правка папок/адреса темы](../../docs/BROADCAST_TOPICS_FIX.md) подготовлена в исходниках: **source_checked/native_compile_pending/device_pending**. Новая IPA не запускалась; ниже описана история предыдущей интеграции.

Текущий результат: включено в Release0.6.8/build114; Apple SDK compile и опубликованный IPA проверены. Физическая приёмка **device_pending**. Source-only описания ниже — история подготовки; [актуальный статус](../../docs/RELEASE_STATUS.md).


После113 исправлены разделение одиночной пересылки своих одноразовых записей и сохранение адресатов/тем рассылки: **source_checked/native_compile_pending/device_pending**. [Контракт](../../docs/TRANSFER_ROUTING_FIX.md). Опубликованный IPA113 этих исправлений не содержит.

Прежний режим copyAsNew теперь называется в меню **«Рассылка»**: отправка новых копий без автора одному или нескольким адресатам через прежнюю панель выбора/отправки Telegram. Содержимое, порядок, альбомная группировка, media references и native quiet/schedule/payment/topic handlers сохранены. Исходные reply/thread/send-as/paid/suggested-post defaults не переносятся в копии.

**«Переслать без»** — отдельное действие для одного адресата. Для существующего серверного сообщения оно готовит штатную пересылку со скрытым автором в чате назначения. Для сохранённой удалённой копии используется тот же snapshot copier с лимитом одного адресата и native send panel. Удалённые server ID повторно не пересылаются.

Copier поддерживает прежние text/entities/inline stickers/spoiler, изображения, файлы/видео/голосовые/кружки, контакты и геолокации; copy-protected, secret, paid, expired и неподдерживаемые типы сохраняют прежние ограничения. Это клиентская новая отправка копии, серверная плашка автора удалённого оригинала не создаётся.

Подробности режимов, настроек, статических проверок и план приёмки — [пересылка и рассылка](message-distribution.md). Автоматическую отправку при выборе адресата, отдельную очередь или собственный таймер не добавлять. Нативную компиляцию и физическую доставку подтвердить после команды пользователя на новый IPA.

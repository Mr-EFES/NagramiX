# Редактирование двойным тапом и скрытие реакций

Актуальная интеграция перенесена на Telegram 13.0; [аудит миграции](../../docs/TELEGRAM_13_MIGRATION.md). Ранее указанные результаты №79 и локальных отдельных проверок относятся к прежней базе; новый нативный результат фиксируется отдельно.

Включено в успешную сборку №83 и проверенный IPA 0.5.1. Обе функции: implemented / compile_passed / device_pending. В IPA №79 этих настроек нет. Пользователь отдельно подтвердил, что редактирование двойным тапом должно быть выключено при первом запуске.

| Настройка | Категория | Ключ iOS | При отсутствии ключа |
| --- | --- | --- | --- |
| Редактирование двойным тапом | Функции / Сообщения | nagramix.features.doubleTapEdit | OFF |
| Скрыть реакции | Интерфейс / Чаты | nagramix.interface.hideReactions | OFF |

Сохранённые значения не перезаписываются при запуске или изменении других настроек. Используются штатные ItemListSwitchItem/ItemListTextItem, Telegram presentationData, RU/EN подписи и глобальный поиск. Добавлены stable IDs 113–116; прежние идентификаторы, ключи и значения по умолчанию, включая новую нижнюю панель канала, сохранены.

## Редактирование

При ON двойной тап по обычной области доступного для редактирования сообщения или поста открывает штатное редактирование. Существующий hit-test ChatMessageBubbleItemNode выбирает конкретное сообщение под пальцем, включая альбомы; ChatMessageAnimatedStickerItemNode также передаёт двойной тап для крупных эмодзи. Редактирование имеет приоритет перед штатной реакцией двойного тапа. При OFF и для недоступных к редактированию сообщений прежние обработчики остаются в работе.

Новая необязательная callback-свойство ChatControllerInteraction связывает компонент с владельцем ChatController, не меняя сигнатуры существующих инициализаторов. Владелец использует настоящий canEditMessage с текущими Telegram limits и правами, затем ChatPanelInterfaceInteraction.setupEditMessage. Для TelegramMediaTodo вызывается штатное editTodoMessage, как в стандартном меню. Запись голосового и её отмена, ввод текста/подписи, rich text, сохранение/отмена редактирования остаются штатными.

Не обходятся ограничения Telegram на срок редактирования, чужие сообщения, пересланные сообщения, стикеры, кружки и остальные неподдерживаемые типы. Нельзя редактировать архивную удалённую копию этим жестом; её локальное редактирование остаётся в прежнем меню. Панель выбора сообщений, preview, закреплённые сообщения и старые сообщения мигрированной группы исключены по штатным ограничениям. Одиночные тапы, удерживание, вложенные кнопки/ссылки и свайпы не заменяются новым распознавателем.

## Реакции

При OFF реакции отображаются как в Telegram. При ON скрываются только визуальные реакции под сообщениями/постами и возле времени. Серверные и локальные attributes сообщения, счётчики, теги, выбранные реакции и API отправки не изменяются. Настройка не запрещает ставить реакцию в штатном меню.

Планировщик bubble content не добавляет реакционный footer, но сохраняет комментарии. Внешние reaction layouts пузырей, стикеров, анимированных стикеров/эмодзи и кружков получают штатные пустые reaction collections. Общий ChatMessageDateAndStatusNode очищает reactions/reactionPeers только в локальной копии layout arguments, закрывая inline-реакции у текста, фото, видео, файлов и других bubble contents. Время, доставка, просмотры, replies, стоимость сообщения, комментарии и вложения сохраняются. Прозрачная панель с прежней высотой не создаётся.

HideReactionsChangedNotification публикуется только при смене значения. ChatControllerNode на главной очереди перебирает все уже созданные item nodes, включая предварительно загруженные за пределами видимой области, собирает message IDs и вызывает штатный requestMessageUpdate. Новые строки используют актуальный getter. Observer слабо захватывает узел и удаляется в deinit. Перезапуск не требуется по реализации; runtime ещё ожидает проверки.

- Изучены реальные canEditMessage, setupEditMessage/editTodoMessage, gesture hit-test, layout reactions/date/status и requestMessageUpdate точной базы Telegram-iOS 13.0. Дополнительные raw пути сверены по Git blob SHA pin.
- Fresh full overlay: 17 generated-файлов изменены относительно подготовленной нижней панели канала, 308 совпадают. Native scope — 12 файлов: ChatControllerInteraction, ChatController, ChatControllerNode, bubble/animated/sticker/instant-video/date-status и четыре BUILD с зависимостью от существующего NagramiXCore. Backend, темы и правки панели канала не менялись.
- 24 exact native-вставки обратимо восстанавливают прежние файлы побайтно; 72 missing/duplicate/already-applied случая и повторное применение отклоняются.
- Разбор синтаксиса всех 11 изменённых Swift-файлов, Python, прежние keys/defaults/IDs, оба default OFF, уникальность локализаций, metadata и diff пройдены. Это не Swift type checking и не проверка жестов/UIKit/UserDefaults.

## Проверка на iPhone после следующей сборки

1. Чистая установка: оба переключателя OFF; реакции и двойной тап работают штатно. Включить каждый по отдельности, проверить сохранение после закрытия приложения.
2. ON редактирования: собственный текст, подпись фото/видео, крупный эмодзи, разрешённый пост канала, конкретный элемент альбома, todo. Форма должна совпадать со штатным «Изменить»; проверить отмену и сохранение.
3. Чужое/слишком старое/пересланное сообщение, стикер, кружок, архивная копия, selection/preview/pinned/migrated: обхода прав и ложной формы редактирования нет. OFF возвращает исходную реакцию двойного тапа.
4. ON скрытия: текст, фото/альбом, голосовое, файл, видео, опрос, todo, стикер/анимированный эмодзи, кружок; приватный чат, группа, канал, Saved Messages. Нет реакций под сообщениями или возле времени и лишнего пространства. Комментарии и остальные статусы доступны.
5. OFF → ON → OFF в открытом чате: реакции возвращаются без перезапуска, в том числе после прокрутки к заранее загруженным строкам и новым сообщениям. Проверить Light/Dark/Night/custom и крупный системный текст.
6. Совместно проверить нижнюю панель канала, широкие посты/альбомы, архивное воспроизведение и обычные тапы/удерживания/свайпы.

Нативную компиляцию и физическую проверку не запускали. Новая сборка — только по отдельной команде пользователя.

# История правок

18 октября после физического теста0.5.10 подготовлены исправления начального зазора и пересылки, которая открывала рассылку. Следующая версия0.6.0: source_checked/native_compile_pending/device_pending. Опубликованный IPA99 этих исправлений не содержит.

## Поведение

«История правок» в контекстном меню обычного или локально удалённого сообщения открывает отдельный экран на всю высоту, со штатной навигацией и закрытием. Каждая сохранённая версия текста или подписи — самостоятельная карточка с номером, датой и временем; последняя отмечена как текущая. Первую известную версию нельзя выдавать за исходную, если приложение не получало более ранний текст.

Список начинается с первой карточки сразу под навигацией. Пояснение об ограничениях архива находится после карточек, а при пустой истории там показано уведомление об отсутствии версий. Для него используется один постоянный footer: UILabel не переносится в новый header при каждом layout. Штатный sectionHeaderTopPadding обнулён; offset устанавливается в начало только при первом ненулевом layout. Обновления сохраняют позицию чтения.

Список прокручивается, длинные карточки растут по содержимому. Шрифт следует настройкам приложения и размеру текста iOS; safe areas, поворот, светлая/тёмная тема и VoiceOver учитываются. Ячейки переиспользуются: единый гигантский attributed string для всей истории не создаётся. При новом событии архива перечитывается актуальный снимок, без подстановки устаревшего текста из открытого ранее контекстного меню.

Для непустой версии доступны:

- выделение и копирование фрагмента удержанием текста;
- «Копировать» — полный текст именно этой версии с entities;
- «Переслать» — штатный выбор одного получателя, затем обычный чат с текстом выбранной версии, который пользователь отправляет кнопкой в чате. «Избранное» тоже требует отправки в открытом чате; для форума выбирается конкретная тема.

Для пересылки создаётся transient snapshot с выбранным текстом/entities, без текущих вложений. Отдельный callback `forwardEditHistoryVersion` передаёт его новому `NagramiXEditHistoryForwarding`: он не использует broadcast callback, не задаёт исходный server ID в forward draft и не запрашивает текущую версию Postbox. Старая редакция отправляется локальной текстовой копией; серверный заголовок пересланного оригинала не имитируется. Native ChatTextInputState готовит выбранный текст/форматирование в composer получателя, без записи синтетического сообщения в историю или автоматического enqueue.

Проверки экспортируемости, замороженного аккаунта и текущей записи сохраняются. Native picker допускает только доступного для записи получателя, без кнопки множественного выбора/счётчика рассылки. Тема форума получается штатным factory и проверяется по peer/thread; поздний ответ после закрытия picker не открывает чат. Обычная навигация с `useExisting: false` не переиспользует readonly preview. Оплата, тихая/отложенная отправка и ограничения выбранного чата обрабатываются его штатным composer при Send. История остаётся под picker и новым чатом; отмена выбора ничего не отправляет. Открытие/копирование истории сами не помечают исходный чат прочитанным и не активируют readonly preview.

Права копирования и пересылки сохраняются. Secret-chat, защищённый контент и paid media не получают обход ограничений через историю. Пустая подпись показана явно; пересылать или копировать пустой текст нельзя.

## Локальное хранение

Прежний per-account JSON, ключ `nagramix.messages.editHistory` и сохранённый выбор пользователя сохраняются. По умолчанию история выключена. Сохраняются полученные приложением версии при включённой функции; неизвестные старые серверные редакции восстановить нельзя. История содержит текст/entities/время, не исторические байты всех изменений вложений.

Число редакций не ограничивается и при показе не обрезается. Удаляются только последовательные дубликаты текста/entities; A → B → A и изменения одного форматирования сохраняются. Текущий текст хранится отдельно и добавляется при чтении. JSON сохраняется прежней atomic-записью на очереди архива. Перезапуск читает тот же формат, миграция не нужна.

Обычная загрузка страницы/синхронизация проверяет существующее сообщение до native addMessages и сохраняет его предыдущий текст, включая первую замеченную таким способом правку. При выключенных обеих функциях чтение предыдущего сообщения не добавляется. Не требуется сохранять все ещё не редактированные сообщения ради истории. Обновление уже существующего архивного снимка также сохраняет прежний текст, вместо молчаливой замены. Повторная загрузка одинакового содержимого не сбрасывает время правки к дате отправки. Explicit edit дополнительно сохраняет фактическую предыдущую версию Postbox, если локальный снимок отстал во время паузы. Существующие файлы не очищаются; выключение скрывает историю и приостанавливает capture.

## Реализация и проверка

`apply_edit_history_screen` заменяет старый alert и точку синхронизации с двумя full-SHA входами и preflight двух файлов. Последующий `apply_edit_history_interaction_fix` проверяет ещё четыре SHA и пять точных замен до записи: callback меню, optional/default-nil поле ChatPanelInterfaceInteraction и его wiring в ChatControllerLoadDisplayNode. Он копирует `NagramiXEditHistoryForwarding.swift` в существующий TelegramUI glob. BUILD и зависимости приложения не меняются; прочие действия пересылки/рассылки остаются прежними. `NagramiXEditHistoryController` использует Display.ViewController, UITableView, selectable UITextView и существующий Pasteboard/UndoUI.

`scripts/validate_edit_history.py --before <предыдущий полный overlay> --after <новый полный overlay>` проверяет точную область изменений, обратимость замены меню, clean/rerun/drift/collision/missing-source сценарии без частичной записи. Native XCTest `NagramiXEditHistoryTests` покрывает 2000 длинных версий и JSON round-trip, A → B → A в одну секунду, форматирование и пустую подпись.

Для новой правки выполнены чистые полные feature overlay до/после на pin:338→339outputs,4изменённых+1helper/334идентичных. `scripts/validate_edit_history_interaction.py` проверяет точный scope/обратимость пяти замен, неизменность карточек/copy/snapshot, отдельный single-recipient путь без refetch/enqueue и10clean/rerun/partial/missing/collision/helper-missing/drift сценариев. Swift grammar5файлов, Python syntax, release metadata иdiff PASS. Proof `/workspace/.codex-validation-nagramix-edit-history`.

Текущий статус: source_checked/native_compile_pending/device_pending. Apple SDK, XCTest и UIKit здесь не запускались; parser не является typecheck. Предыдущая реализация скомпилирована в опубликованном0.5.10/build99, новые исправления туда не входят. Новую сборку запускать только по новой команде пользователя.

Приёмка на iPhone:

1. Длинный пост, 2/20/200+ правок: при первом открытии первая карточка сразу под заголовком, без пустого зазора/предварительного свайпа. Прокрутить до конца и увидеть пояснение; закрыть/открыть/перезапустить. Проверить пустую историю, поворот/изменение шрифта и сохранение позиции при обновлении списка.
2. Выделить фрагмент; скопировать целую раннюю версию со ссылками/жирным/эмодзи. Проверить, что текущий текст не подменяет выбранный.
3. Переслать раннюю версию себе, в другой чат и тему форума; отменить выбор. Нет чекбоксов/выбора нескольких чатов или отправки из picker. В чате получателя подготовлен именно выбранный текст; отправить обычным/тихим/отложенным способом. Текущий текст и вложение исходника не подставляются. Проверить существующий черновик получателя согласно штатной вставке текста, paid/restricted chat, быстрый повторный тап и Back во время загрузки темы.
4. Получить A → B → A и formatting-only edit; перезагрузить историю/приложение. Все различные последовательные версии сохраняются.
5. Архивное удалённое сообщение, режим просмотра через аватарку, история OFF/ON, фон/возврат, смена темы/языка, маленький iPhone/крупный текст/поворот. Защищённые сообщения сохраняют запрет экспорта.

# Пересылка и рассылка сообщений

22октября пользователь подтвердил сбой смешанной рассылки в IPA114. Новое [исправление](../../docs/BROADCAST_TOPICS_FIX.md) сохраняет полный выбор между папками и задаёт server reply target выбранной темы для новых копий. **source_checked/native_compile_pending/device_pending**; в IPA114 не включено. Одиночный режим/настройки прежние.

Текущий результат: включено в Release0.6.8/build114; Apple SDK compile и опубликованный IPA проверены. Физическая приёмка **device_pending**. Source-only описания ниже — история подготовки; [актуальный статус](../../docs/RELEASE_STATUS.md).


После Release0.6.7/build113 исправлены подтверждённые регрессии: одиночная пересылка своих одноразовых voice/round через обычный чат и сохранение адресатов рассылки при выборе рабочего вложенного канала/темы. **source_checked/native_compile_pending/device_pending**; текущий IPA113 этой правки не содержит. [Причины, контракты и проверки](../../docs/TRANSFER_ROUTING_FIX.md). Новых настроек/defaults нет. Прежние protected-copy/export механизмы прошли SDK113; их проверки ниже сохраняются. Новая сборка только по отдельной команде.

## Действия

| Действие | Адресаты | Путь отправки |
| --- | --- | --- |
| Репост | Штатный выбор Telegram | Прежняя пересылка с источником для существующего серверного оригинала, без обхода copy protection |
| Переслать | Один | Обычное сообщение — штатный черновик со скрытым автором; своя одноразовая запись — обычный чат и local reupload при Send с сохранением one-shot; обычное защищённое — черновик в чате получателя с локальным копированием при включённом «Свободном скриншоте» |
| Рассылка | Один или несколько | Прежнее копирование как новые сообщения без источника, с панелью отправки в выборе адресатов |

Новое «Переслать без» не показывает кнопку множественного выбора и не отправляет сообщение при выборе получателя, включая Избранное. В чате назначения — штатная кнопка отправки и её меню без звука/по расписанию. Назначение может быть контактом, группой, каналом или темой форума по действующим правам. Существующий редактор Telegram сохраняет обычные возможности пересылки и комментария.

«Рассылка» сохраняет прежний copyAsNew: выбранные сообщения/альбомы становятся новыми копиями без плашки автора; получателей можно выбрать несколько. Защищённые оригиналы загружаются полностью и получают независимые локальные ресурсы для новой загрузки вместо server forward/cloud reuse. Отправка, комментарий, без звука, расписание, платежи и отмена используют прежние native handlers. Выбор адресата сам не отправляет копию, включая защищённый одиночный режим. Автоматической новой рассылки без действия пользователя нет.

Удалённый серверный ID Telegram переслать не может. Для сохранённого snapshot «Переслать без» теперь выбирает одного адресата штатным одиночным picker и открывает подготовку в обычном чате назначения, включая Избранное и темы форумов. Ничего не отправляется до явного Send. Штатная панель и предпросмотр получают отсутствующие оригиналы из локального архива. При Send вместо удалённого ID создаётся новое сообщение без источника. Смена получателя сохраняет одиночный режим.

«Рассылка» сохраняет выбор нескольких адресатов и штатную панель отправки копий. Оба режима подготавливают полные локальные вложения с новыми LocalFile/LocalImage ID и без cloud references удалённого оригинала. Незагруженные дополнительные превью/обложки исключаются; отсутствие основных байтов вызывает понятную ошибку до enqueue. Полные байты закрепляются отдельными временными ссылками, поэтому очистка архива после постановки сообщения в очередь не удаляет источник отправки. Native upload, темы адресатов, платежи, тихая/отложенная отправка прежние.

Новая правка после build86: implemented / compile_passed / device_pending. В опубликованном IPA её нет; [интеграция и физическая приёмка](../../docs/ARCHIVED_MESSAGE_TRANSFER_FIX.md). Серверную плашку автора у удалённого оригинала не имитировать; прежний несогласованный пункт об авторе архива остаётся незавершённым.

## Настройки

Интерфейс → Контекстное меню: независимые «Переслать без автора» (действие «Переслать»), «Возможность рассылки» (действие «Рассылка»), «Выделить от автора». Существующий ключ showForwardWithoutAuthor/default true/IDs 81–82 сохраняется; showBroadcastMessages/default true/IDs 121–122 прежние. На обновлении без второго ключа видимость «Рассылки» наследует сохранённую видимость прежнего copy-действия; явный false не сбрасывается. После первого сохранения переключатели независимы. Оба действия читают настройки при новом открытии меню, включая архивные строки. Когда хотя бы один включён, в обычном защищённом чате доступны также штатные «Копировать»/Фото/Файлы. При обоих OFF дополнительные возможности скрыты. Новых keys/checkbox не добавляется. Название и поисковое описание RU/EN используют штатные темы/шрифты; footer не добавляется.

## Интеграция

Нижняя панель выделения с тремя видами пересылки рядом с удалением/экспортом включена в №84. «Рассылка» имеет штатную иконку с двумя людьми также в контекстном меню. Видимость подчиняется прежним переключателям, кнопки используют прежние single/multi callbacks, свежие сообщения и общий валидатор. После физического теста подготовлена отдельная правка: разрешить эту панель при выделении одного или нескольких сообщений в просмотре через аватарку, сохраняя read/composer gates. Обычный чат прежний. Новая правка compile_passed/device_pending, в№84 отсутствует; включено в№86. [Полный контракт и проверка](../../docs/MESSAGE_SELECTION_ACTIONS_FIX.md).

apply_copy_broadcast_split в ios/apply_features.py применяется после прежних copy_send_options и readonly helpers. Enum transfer mode различает forwardWithSource/copyAsNew/forwardWithoutSource/copyToSingleRecipient. Общий native picker имеет multipleSelection=false только для двух одиночных режимов; обычная «Переслать без» сохраняет реальные forwardedMessageIds, у рассылки — пустые ID, у архивного одиночного режима — IDs для штатного черновика с локальным fallback.

Анонимная пересылка устанавливает штатный ChatInterfaceForwardOptionsState(hideNames: true, hideCaptions: false, unhideNamesOnCaptionChange: false) для нового/текущего/переиспользованного адресата. В native enqueue используется ForwardOptionsMessageAttribute. У Избранного обходится только немедленная ветка одиночного анонимного режима; классическая пересылка сохраняет прежнее поведение. Экран просмотра без ввода не переиспользуется как editable destination. Для обоих одиночных режимов проверяется соответствие threadId перед повторным использованием контроллера.

Новый optional forwardMessagesWithoutSource callback в ChatPanelInterfaceInteraction не меняет существующие callers; старый copyMessagesWithoutSource callback сохранён побайтно для «Рассылки». Ограничение контактов opt-in, default nil, включается только мостом одиночной архивной копии. Штатный выбор остальных контактов не ограничивается.

Entities/inline emoji/spoiler, группировка, тихие/отложенные атрибуты копий и native destination payment/topic commit сохраняются. Поздний content_copy overlay добавляет только сценарий обычного защищённого содержимого в эти два custom действия и штатное сохранение. Таймер/очередь отправки NagramiX не создавались. Secret/одноразовые/paid/expired, служебные/verification и неподдерживаемые копии сохраняют ограничения. «Репост» не становится фиктивным server forwarding. Штатный screenshot checkbox независим. Полный код/проверки/принцип Files lifetime — в [новом контракте](../../docs/PROTECTED_CONTENT_COPY.md).

## Проверка

Полный overlay применён к точному pin Telegram-iOS 13.0, f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838. Против предыдущего pending batch изменены 11 generated файлов, остальные 318 совпали. Все шесть затронутых native raw файлов сверены по Git blob SHA. 28 вставок helper обратимо восстанавливают baseline bytes, отдельный helper совпадает с full overlay. 85 missing/duplicate/already-applied/repeat случаев отклоняются. Девять Swift-файлов разобраны tree-sitter без ошибок; проверены маршруты/режимы, прежний broadcast callback/copier/send transforms, старые keys/defaults/IDs, новый наследуемый выбор, RU/EN uniqueness, Python и метаданные/diff.

Это статические проверки, не Swift type checking и не подтверждение доставки/расписания. Linux не имеет Xcode или физического iPhone.

На опубликованном IPA 0.5.3 проверить:

1. Нормальное сообщение/альбом/медиа: все три пункта меню; «Переслать от» сохраняет исходную работу.
2. «Переслать без»: выбрать одного адресата через список, Контакты, поиск, группу/канал/форум. До явной отправки доставка отсутствует; получатель получает сообщение без автора, подпись и media сохранены.
3. Новый, уже открытый и текущий чат адресата, Избранное, тема форума: выбран правильный peer/thread, плашка автора скрыта, поле ввода доступно.
4. Без звука и расписание в обычном чате и Избранном: доставка/атрибуты подтверждены другим клиентом; отмена каждого шага ничего не отправляет.
5. «Рассылка»: два адресата, текст/комментарий/альбом/медиа/архивная копия; обычная, тихая и отложенная доставка; оплата и её отмена.
6. Архивное «Переслать без»: список, Контакты, поиск — второй адресат не выбирается; deselect первого и смена адресата; после явной отправки только одна доставка, no server deleted-ID request. Проверить quiet/schedule/topic/payment.
7. Все комбинации двух переключателей, перезапуск, обновление со старым OFF, новая чистая установка; настройки аватарки, компактные строки, темы и прочий pending batch остаются прежними.

В нижней панели выделения «Переслать» отображается штатным контурным значком одного человека, «Репост» — стрелкой, «Рассылка» — двумя людьми. Значок использует цвет темы; обработчики, выбор и доступность кнопок не меняются.

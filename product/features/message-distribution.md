# Пересылка и рассылка сообщений

Актуальная интеграция перенесена на Telegram 13.0; [аудит миграции](../../docs/TELEGRAM_13_MIGRATION.md). Ранее указанные результаты №79 и локальных отдельных проверок относятся к прежней базе; новый нативный результат фиксируется отдельно.

Статус текущего кода: implemented / compile_passed / device_pending. Предыдущий опубликованный IPA №79 этой доработки не содержит. Новую сборку запускать только по команде пользователя.

## Действия

| Действие | Адресаты | Путь отправки |
| --- | --- | --- |
| Переслать от | Штатный выбор Telegram | Прежняя пересылка с источником для существующего серверного оригинала |
| Переслать без | Один | Штатная пересылка со скрытым автором; выбор адресата открывает подготовку в его чате |
| Рассылка | Один или несколько | Прежнее копирование как новые сообщения без источника, с панелью отправки в выборе адресатов |

Новое «Переслать без» не показывает кнопку множественного выбора и не отправляет сообщение при выборе получателя, включая Избранное. В чате назначения — штатная кнопка отправки и её меню без звука/по расписанию. Назначение может быть контактом, группой, каналом или темой форума по действующим правам. Существующий редактор Telegram сохраняет обычные возможности пересылки и комментария.

«Рассылка» сохраняет прежний copyAsNew: выбранные сообщения/альбомы становятся новыми копиями без плашки автора; получателей можно выбрать несколько. Отправка, комментарий, без звука, расписание, платежи и отмена используют прежние native handlers. Автоматической новой рассылки без действия пользователя нет.

Удалённый серверный ID Telegram переслать не может. Поэтому «Переслать без» сохранённого удалённого сообщения использует локальный snapshot и прежнюю панель отправки копий, ограниченную одним получателем. Для этого fallback штатный список ограничен одним адресатом; дополнительно ограничены контакты, глобальный поиск и callback отправки до платежей/расписания/enqueue. У этого picker нет вкладок папок; темы форума выбираются штатно. «Рассылка» архивных копий остаётся множественной. Серверную плашку автора у удалённого оригинала не имитировать: прежний несогласованный пункт об авторе архива остаётся незавершённым.

## Настройки

Интерфейс → Контекстное меню: независимые «Переслать без», «Рассылка», «Выделить от автора». Существующий ключ showForwardWithoutAuthor/default true/IDs 81–82 сохраняется; новый showBroadcastMessages/default true/IDs 121–122 добавлен отдельно. На обновлении без нового ключа видимость «Рассылки» наследует сохранённую видимость прежнего copy-действия; явный false не сбрасывается. После первого сохранения переключатели независимы. Оба действия читают настройки при новом открытии меню, включая архивные строки. Название и пояснение доступны глобальному поиску, RU/EN используют штатные темы/шрифты.

## Интеграция

apply_copy_broadcast_split в ios/apply_features.py применяется после прежних copy_send_options и readonly helpers. Enum transfer mode различает forwardWithSource/copyAsNew/forwardWithoutSource/copyToSingleRecipient. Общий native picker имеет multipleSelection=false только для двух одиночных режимов; обычная «Переслать без» сохраняет реальные forwardedMessageIds, а копии — пустые ID.

Анонимная пересылка устанавливает штатный ChatInterfaceForwardOptionsState(hideNames: true, hideCaptions: false, unhideNamesOnCaptionChange: false) для нового/текущего/переиспользованного адресата. В native enqueue используется ForwardOptionsMessageAttribute. У Избранного обходится только немедленная ветка одиночного анонимного режима; классическая пересылка сохраняет прежнее поведение. Экран просмотра без ввода не переиспользуется как editable destination. Для одиночного режима проверяется соответствие threadId перед повторным использованием контроллера.

Новый optional forwardMessagesWithoutSource callback в ChatPanelInterfaceInteraction не меняет существующие callers; старый copyMessagesWithoutSource callback сохранён побайтно для «Рассылки». Ограничение контактов opt-in, default nil, включается только мостом одиночной архивной копии. Штатный выбор остальных контактов не ограничивается.

Не менялись copier содержимого, media/entities/inline emoji/spoiler, группировка, тихие/отложенные атрибуты копий, native destination payment/topic commit. Таймер/очередь отправки NagramiX не создавались. Copy-protected/secret/paid/expired и неподдерживаемые копии сохраняют прежние ограничения; ложных кнопок для недоступного server forwarding не добавляется.

## Проверка

Полный overlay применён к точному pin Telegram-iOS 13.0, f1dd7a2dbd02cbbf513e75d5695d8d36d1cf5838. Против предыдущего pending batch изменены 11 generated файлов, остальные 318 совпали. Все шесть затронутых native raw файлов сверены по Git blob SHA. 28 вставок helper обратимо восстанавливают baseline bytes, отдельный helper совпадает с full overlay. 85 missing/duplicate/already-applied/repeat случаев отклоняются. Девять Swift-файлов разобраны tree-sitter без ошибок; проверены маршруты/режимы, прежний broadcast callback/copier/send transforms, старые keys/defaults/IDs, новый наследуемый выбор, RU/EN uniqueness, Python и метаданные/diff.

Это статические проверки, не Swift type checking и не подтверждение доставки/расписания. Linux не имеет Xcode или физического iPhone.

На опубликованном IPA 0.4.9 проверить:

1. Нормальное сообщение/альбом/медиа: все три пункта меню; «Переслать от» сохраняет исходную работу.
2. «Переслать без»: выбрать одного адресата через список, Контакты, поиск, группу/канал/форум. До явной отправки доставка отсутствует; получатель получает сообщение без автора, подпись и media сохранены.
3. Новый, уже открытый и текущий чат адресата, Избранное, тема форума: выбран правильный peer/thread, плашка автора скрыта, поле ввода доступно.
4. Без звука и расписание в обычном чате и Избранном: доставка/атрибуты подтверждены другим клиентом; отмена каждого шага ничего не отправляет.
5. «Рассылка»: два адресата, текст/комментарий/альбом/медиа/архивная копия; обычная, тихая и отложенная доставка; оплата и её отмена.
6. Архивное «Переслать без»: список, Контакты, поиск — второй адресат не выбирается; deselect первого и смена адресата; после явной отправки только одна доставка, no server deleted-ID request. Проверить quiet/schedule/topic/payment.
7. Все комбинации двух переключателей, перезапуск, обновление со старым OFF, новая чистая установка; настройки аватарки, компактные строки, темы и прочий pending batch остаются прежними.

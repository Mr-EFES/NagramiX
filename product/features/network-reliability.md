# Proxy failover и DNS/DoH

## Proxy failover

Контроллер работает от штатного `Network.connectionStatus` и не опрашивает список постоянно. Состояние `.waitingForNetwork` отменяет текущую попытку и не перебирает proxy без физической сети. При proxy failure выбранному серверу даётся настроенное окно 15/30/60 секунд. Затем кандидаты проверяются по порядку штатным `MTProxyConnectivity`; недоступные и незавершённые проверки пропускаются. Успешный ping только допускает кандидата к применению: после переключения он обязан достичь настоящего `.online` в то же пользовательское окно 15/30/60 секунд.

Каждый timer, probe и callback проверяет generation token. Восстановление соединения, ручная смена proxy, изменение списка или выключение функции инвалидирует старое поколение, поэтому устаревший timeout не может переключить proxy позднее.

## DNS/DoH

Выбранный DoH остаётся первичным асинхронным resolver. HTTP request выполняется `NSURLSession` вне UI thread и ограничен request/resource timeout. Если endpoint недоступен, запрос отменён, ответ повреждён либо общий timeout истёк, `MTDNS` переходит к штатному асинхронному native resolver. Таким образом, недоступный Mullvad/custom DoH не образует бесконечный цикл закрытия MTProto connections и не блокирует запуск интерфейса; сеть может временно работать через системное разрешение имён.

Точный crash/ANR stack trace предыдущей сборки отсутствует, поэтому документируется подтверждённая кодом failure mode, а не вымышленная трассировка. Финальная проверка Mullvad DNS требует device log и физического запуска.
